# 대기실 역할과 제외 (#11)

방장 권한과 게임 역할은 독립이다. 방장도 피고가 될 수 있으며 강제 원고 역할은 없다. 신규 참가자의 대기 역할은 참가자다. 본인이 참가자/피고를 선택하고 활성 피고는 한 방에 한 명뿐이다. 실제 게임 참가자/투표 자격은 아직 생성하지 않는다.

## 서버 명령

- POST `/api/rooms/:code/role`: `{role: 'defendant' | 'participant'}`. 쿠키의 본인 역할만 바꾼다. memberId 등 추가 키는 거부한다.
- POST `/api/rooms/:code/exclude`: `{memberId}`. 현재 방장만 같은 방의 활성 멤버 중 서버가 단절로 표시한 다른 사람을 제외한다. 자기 자신, 연결된 사람, 다른 방 사람은 제외할 수 없다.

두 명령 모두 동일 origin·CSRF·서버 세션을 확인한다. 트랜잭션 안에서 열린 방, 현재 멤버십, 게임 시작 여부와 권한을 재검사한다. 게임이 진행 중이면 역할/제외 편집은 거부한다. 연결 상태가 화면과 달라졌다면 서버가 최종 판정한다. heartbeat가 먼저 처리되면 제외가 거부되고, 제외가 먼저 처리되면 이전 멤버십 heartbeat가 거부된다.

피고 동시 선택은 immediate transaction과 DB partial unique index가 함께 보호한다. 같은 역할의 반복 명령은 버전을 바꾸지 않는다. 제외는 left_at을 기록하는 것이며 영구 ban이 아니다. 링크로 다시 들어오면 새 멤버십·기본 참가자 역할을 받는다. 이전 게임 참여/투표 권한은 복원하지 않는다. 방 입장과 시작된 게임의 고정 명단은 별개다. 시작 후 새 방 참가자의 관전 처리 등은 후속 기능에서 구현한다.

## 수락 무효화 연결

migration 3은 기존 스키마에 대기 역할과 `rooms.role_revision`을 추가한다. 기존 참가자는 참가자로 보존된다. 역할 변경마다 roleRevision을 증가시키고 피고를 제외할 때도 증가시킨다. A가 피고였다가 참가자로 돌아갔다 다시 피고가 되어도 이전 revision과 일치하지 않는다. [벌칙 수락](penalty-consent.md)은 이 revision 및 현재 벌칙 revision/피고를 함께 확인한다.

## 검증과 남은 범위

실제 API로 두 피고 선택 경합, 방장=피고, 타인 역할 요청 거부, 비방장/연결된 대상/자기 자신/다른 방 제외 거부, 새 멤버십 재입장, 진행 게임 잠금을 확인한다. 실제 임시 DB 시험은 복귀·제외 양쪽 순서, unique index, revision 증가, v2→v3 기존 참가자 보존을 검사한다. UI 제외 확인은 대상 이름을 보여주고 서버 성공 후에만 명단을 반영한다. 게임 시작·10분 자동 퇴장·방장 이전·실기기/외부 배포는 아직 완료 범위가 아니다.

## 화면 확인

390px Chromium의 `artifacts/roles/host-defendant-mobile.png`를 직접 확인했다. 피고 선택 표시와 참가자 명단의 ‘방장 · 피고 · 나’가 함께 읽히며 두 권한 축이 구분된다. 입력·선택·버튼의 가로 잘림은 없었다. 실제 단절 대기 후 제외 확인/취소·재참가를 브라우저로 검사했고, 시작 후 입력 잠금 UI는 명시적 응답 fixture로 검사했다. 실제 게임 시작 E2E나 실기기 검증으로 간주하지 않는다.

제외된 화면은 마지막 명단임을 표시하고 역할/설정 조작을 숨긴다. 후속 네트워크 오류만으로 권한을 다시 표시하지 않는다. 같은 브라우저의 다른 탭에서 재입장했다면 새 멤버십이 담긴 유효 snapshot을 받은 뒤 조작을 복구한다. 이는 이전 피고/게임 권한 복원이 아니다.
