# 모바일 설정·투표 동선 개선 · #71

## 문제와 측정 방법

초대 링크·참가자·게임 상세가 현재 해야 할 행동보다 먼저 길게 나와 모바일에서 설정 저장과 투표 제출을 찾으려면 여러 화면을 내려야 했다. 기준 소스는 `6f369a1`이다.

로컬 실제 API에 독립 브라우저 신원 3개를 연결하고 Chromium의 320/390px 터치 viewport로 측정했다. 최초 설정은 방 생성 직후, 시작은 세 신원이 참여하고 수락한 뒤, 투표는 피고가 아닌 참가자 화면이다. 스크롤을 맨 위로 돌린 다음 버튼 boundingBox의 y 좌표를 기록했다. 실제 iPhone Safari·Android Chrome이나 소프트 키보드 검증은 아니다.

| 폭 | 이전 설정 저장 y | 이전 준비 완료 후 시작 y | 이전 투표 제출 y |
|---|---:|---:|---:|
| 320px | 1569.9 | 2235.4 | 2010.6 |
| 390px | 1504.0 | 2148.0 | 1943.0 |

원본 측정·화면은 무시된 `artifacts/compact/`와 `artifacts/screenshots/compact-before-*`에 저장한다. 캡처는 모두 합성 참가자·사건이다.

## 설계 경계

- 준비 단계는 사건·벌칙 설정, 자신의 역할, 저장된 벌칙 수락과 시작을 중심으로 배치한다.
- 투표 단계는 단계 제목·역할·짧은 사건 맥락, 타이머·선택·이유·제출을 앞에 둔다.
- 전체 사건·벌칙, 변론, 이전 라운드 공개 결과와 초대·참가자 정보를 필요할 때 펼쳐 본다. disclosure는 DOM을 제거하는 화면 전환이 아니다.
- 벌칙 수락 전에 전체 저장된 벌칙을 계속 보여준다. 미저장·오류·재시도·익명성 주의는 숨기지 않는다.
- 게임 규칙, 저장·수락 권한, 타이머·정산, 투표 자격·불변성, 응답 세대 방어와 공개 정책은 바꾸지 않는다.
- 작은 글씨나 작은 터치 버튼으로 길이를 줄이지 않는다. 기존 입력 상태와 키보드 접근을 유지한다.

## 검증 해석

새 위치·상호작용 회귀와 기존 기능 시험을 함께 확인한다. 기존 시험은 필요 정보를 실제 summary 클릭으로 펼친 다음 같은 역할·공개 범위 assertion을 실행한다. 전역으로 모든 패널을 열거나 개인정보 비공개 assertion을 삭제하지 않는다.

화면 가독성·자동 브라우저 성공은 기존 실기기/외부 운영 인수 차단을 해소하지 않는다. 최종 실행 결과와 정확한 소스는 PR 검증 보고서에서 확인한다.

## 첫 개선 측정과 회귀

| 폭 | 설정 저장 y (감소) | 준비 완료 후 시작 y (감소) | 투표 제출 y (감소) |
|---|---:|---:|---:|
| 320px | 745.13 (52.5%) | 1460.34 (34.7%) | 878.47 (56.3%) |
| 390px | 723.69 (51.9%) | 1438.91 (33.0%) | 857.03 (55.9%) |

이 수치는 짧은 합성 사건에서 접힌 상세의 기본 상태다. 긴 사건·벌칙 전체를 펼치거나 오류가 나타나면 화면은 길어질 수 있다. 시작은 미저장 입력과 저장 상태를 혼동하지 않도록 설정·수락 뒤의 논리적 순서를 유지했다. 모든 행동이 첫 화면에 들어온다는 뜻은 아니다.

위치 RED는 기존 320/390 화면에서 설정 저장 y<900 assertion이 각각 실패한 2건이다. 투표 제출의 이전 위치는 측정했으며 별도의 RED로 부풀리지 않는다. 새 회귀는 저장·제출 y<900, 시작 y<1500, 44px 이상 선택 영역, 키보드 disclosure, 미저장 입력·선택·이유 보존, 실제 heartbeat 뒤 focus, 판단 미선택 오류 및 실제 투표 접수를 확인한다. 긴 내용 시험은 저장된 벌칙 전문과 상세 사건이 사라지지 않는지 별도로 확인한다.

최종 소스의 실제 시험 수·실행 시간·실패 여부는 검증 보고서에 남긴다. 화면 캡처의 위치·레이아웃과 수치 assertion은 기능·개인정보 회귀를 대신하지 않는다.

작업 중 최종 targeted 결과: 신규 모바일 3/3(18.9초), 기존 대상 18개는 첫 실행 15통과/3실패 후 disclosure·중복 본문 locator를 수정하고 관련 8개를 재실행해 8/8 통과했다. 나머지 10개는 최초 실행에서 통과했으며 18개 전체를 다시 실행한 것으로 보고하지 않는다. 기존 assertion과 timeout은 삭제·완화하지 않았다. build·lint·unit 57·문서 7 검사를 별도로 통과했다. 전체 suite는 최종 clean 소스의 독립 검사 단계에서 수행한다.
