# 보안 결함 주입 검증 (#25)

## 실행

빌드 이후 `node tools/security/mutation-check.mjs` 또는 `node --test tests/unit/security-mutations.test.mjs`를 실행한다. aggregate 하네스의 unit 자동 탐색에도 포함된다.

실행마다 시스템 임시 폴더에 컴파일된 API를 복사하고 합성 SQLite DB를 새로 만든다. 결함은 이 복사본에만 주입한다. 원래 source/dist/운영 DB/배포 설정에는 쓰지 않는다. 의존성은 기존 node_modules를 읽기 위한 링크이며 별도 설치나 네트워크 접속이 없다. probe는 소유 임시 디렉터리 및 아직 없는 DB 파일을 요구하며, 실행 후 임시 트리를 제거한다.

## 네 대조군과 네 결함

| 결함 | 실제 검사 경계 | 정상 대조군 | 결함 복사본 |
|---|---|---|---|
| 피고의 투표 역할·자격 검사를 제거 | eligible=false 피고의 실제 SubmitVote 호출이 거절되는가 | FORBIDDEN | 표가 저장되어 보안 assertion 실패 |
| 표의 game/round/member 유일 키 제거 | 다른 requestId로 같은 멤버의 두 번째 표 저장이 거절되는가 | constraint | 두 행이 저장되어 보안 assertion 실패 |
| 현재 남의 표를 ownVote로 직렬화 | 미완료 라운드에서 다른 참가자의 합성 이유가 응답에 없는가 | ownVote=null, 이유 없음 | 남의 표/이유가 보여 보안 assertion 실패 |
| 개인 기록의 실제 게임 참여 권한 검사 제거 | 게임에 참여하지 않은 신원의 진행 게임 상세가 거절되는가 | FORBIDDEN | 사건이 반환되어 보안 assertion 실패 |

각 시나리오는 정상 복사본과 결함 복사본에서 동일한 probe를 실행한다. 정상 대조군은 exit 0이어야 한다. 결함 복사본은 해당 시나리오의 `MUTATION_INVARIANT`가 포함된 AssertionError로 실패해야 한다. import 실패·잘못된 SQL·시간 초과 같은 무관한 실패를 결함 검출로 인정하지 않는다. 결함 주입 지점이 정확히 한 곳이 아니어도 실패한다.

최초 실행에서 정상 대조군 4/4 통과, 의도한 결함 4/4 검출을 확인했다. 도구의 최종 `status:passed`는 제품에 결함이 있다는 뜻도, 의도적으로 실패한 검사를 일반 제품 통과로 숨긴다는 뜻도 아니다. 정상 대조군 통과와 네 결함의 검출이 모두 충족됐다는 별도 검증 결과다.

이 검증은 네 보안 불변식의 시험 민감도를 확인한다. 전체 공격면 탐색, DDoS 방어, 배포 인프라 보안, 실사용자 데이터 검증을 주장하지 않는다. 모든 사건·이유·신원은 합성 값이며 비밀키/실사용자 자료는 사용하지 않는다.
