# 개인 투표 접수 (#15)

## 범위

현재 투표 라운드에 유죄·무죄·기권 한 표를 접수한다. 유죄/무죄 이유는 필수, 기권 이유는 선택이다. 접수 뒤 수정·철회하지 않는다. 모두 제출하거나 마감돼도 이 단계에서는 결과를 만들지 않는다. 마감·정산은 #16이다.

## 서버의 권한과 원자성

`POST /api/rooms/:code/games/:gameId/vote`에는 `roundNumber`, `requestId`, `choice`, `reason`만 받는다. actor는 HttpOnly 세션 쿠키에서만 읽고 기존 same-origin 명령 검사를 적용한다. 현재 방 멤버십이 시작 때 고정된 투표 가능 참가자와 일치해야 한다. 피고·후발 관전자·퇴장 멤버십은 거절한다.

별도 `SubmitVote` 유즈케이스의 SQLite immediate 트랜잭션 안에서 현재 게임·라운드·투표 상태·미마감(`serverNow < deadline`)을 확인한다. 기존 `votes`의 게임/라운드/멤버 PK와 게임/라운드/requestId unique가 중복을 막는다. 기존 스키마로 충분하므로 마이그레이션은 추가하지 않았다. `rounds.closed_at`은 포트에서 읽어 이미 닫힌 라운드도 거부한다.

이유는 문자열 2,000 코드포인트 이하, 앞뒤 공백을 제거한다. 줄바꿈·탭 외 제어/포맷 문자는 거절한다. 정규화된 같은 이유·선택·요청 키를 재전송하면 기존 본인 접수를 확인한다. 이 재확인은 마감 뒤에도 가능하지만 새 표를 만들지 않는다. 명령 응답은 `{snapshot, receipt}`이며 receipt에 요청한 gameId/roundNumber/choice/reason을 명시한다. 최신 snapshot이 이미 2차 라운드여도 1차 재확인을 2차 제출 성공으로 표시하지 않는다. 다른 내용이나 새 키로 바꾸면 충돌이다. 현재 멤버십/투표 자격 검사는 재시도에서도 생략하지 않는다.

## 비공개 경계

접수는 공용 방/게임 version을 증가시키지 않는다. 다른 사람이 polling으로 접수 횟수를 추론하는 별도 진행 카운터도 없다. `game.ownVote`에는 현재 요청자의 해당 라운드 접수(라운드 번호·선택·이유)만 넣는다. requestId, 제출 시각, 세션/투표자 식별자는 전달하지 않는다. 타인의 진행 중 선택·이유·제출 표수는 공개하지 않는다. 이미 공개된 라운드 결과와 중단 이력 정책은 각각 후속 단계 및 #33의 범위다.

## 검증

`tests/integration/votes.test.mjs`는 실제 HTTP 권한·CSRF·입력·같은/다른 요청 동시 제출·마감 경계·늦은 관전자·타인 비공개를 검사한다. 초기 RED는 미구현 경로의 404로 2개 실패했다. `tests/database/votes.test.mjs`는 실제 임시 SQLite에서 삽입 후 실패 rollback, 재연결 후 재시도, 공용 버전 불변, closed_at/이전 라운드/퇴장 멤버십을 검사한다. 전체 실행 증거는 해당 작업 기록과 하네스 보고서에 남긴다. 시험 데이터는 합성 데이터이며 실사용 DB나 외부 배포를 사용하지 않는다.

리뷰에서 발견한 두 번의 clock 읽기는 변경되는 fake clock로 RED(저장182000, 기대181999)를 재현하고 동일 now를 검사/저장에 공유하도록 수정했다.

## 브라우저 동작과 시각 확인

폼은 접수 응답 또는 본인 receipt가 포함된 폴링 snapshot을 받은 뒤에만 성공을 표시한다. 불확실한 요청은 선택·이유·requestId를 고정하여 재확인한다. 입력/다중 클릭 잠금은 동시에 작동한다. 같은 공용 version의 오래된 응답이 본인 접수를 지우지 않도록 같은 멤버·게임·라운드에만 기존 receipt를 유지한다. 다음 라운드나 새 멤버십에는 넘기지 않는다. 명령 응답 receipt는 원본 명령과 엄격히 비교하고, 최신 snapshot만 화면에 반영한다.

`tests/browser/votes.spec.mjs`의 실제 API 연동 Chromium 3개 시험은 접수 전 성공 없음·중복 제출 한 번·이유 텍스트 이스케이프·재방문·늦은 빈 snapshot·접수 전 실패 재시도·접수 후 응답 유실의 폴링 복구를 확인했다. 추가 1개의 서버 마감 응답 fixture 시험은 로컬 시간 양수여도 제출을 종료하는 경계를 확인했다. `artifacts/votes/receipt-mobile.png`를 직접 확인했다. 390px viewport 내 300px 본문에서 접수 상태, 본인 판단, HTML처럼 보이는 이유의 문자 그대로 출력, 수정 불가와 비공개 안내가 잘리지 않고 읽힌다. 이는 브라우저 에뮬레이션이며 실제 모바일 기기/키보드 검증은 아니다.
