# 재판 시작과 고정 명단 (#13)

현재 방장이 실제 게임을 변론 단계로 시작한다. 시작/게임 저장은 별도 `StartTrial` 유스케이스다. 변론 제출·투표 시작은 #14 이후이며 화면에 아직 실행되지 않는 버튼을 가장하지 않는다.

## 한 트랜잭션의 시작 조건

서버 시계로 15초 이상 응답하지 않은 멤버를 다시 검사한다. 표시만 연결됨인 오래된 클라이언트는 포함하지 않는다. 연결된 서로 다른 멤버가 피고 포함 최소 3명, 연결된 피고가 정확히 1명, 저장된 사건/벌칙이 비어 있지 않고 현재 피고의 현재 벌칙 수락이 유효해야 한다. 방장=피고는 한 명으로 센다. 5명 또는 6명 이상도 허용한다. 요청의 초안·역할·결정 버전과 서버 현재 값도 일치해야 한다.

조건, 현재 방장, 게임 생성, 연결된 멤버의 고정 역할/투표권, 요청 영수증 저장을 한 SQLite immediate transaction에 넣는다. 중간 실패는 게임과 명단을 모두 롤백한다. 시작 순간 피고 외 연결된 참가자만 투표권을 받는다. 사건·벌칙·해당 게임 명단은 저장된 snapshot이며 이후 대기실 초안에서 재계산하지 않는다.

시간은 현재 초안값으로 초기화하지만 영구 잠금 의미는 아니다. #14에서 첫 투표 전 조절을 구현하고 첫 투표가 시작되면 두 라운드의 시간을 고정한다. 현재 게임 상태는 defense뿐이며 실제 변론 제출은 아직 없다.

## 재시도

POST `/api/rooms/:code/start`는 requestId 및 expectedDraftVersion/expectedRoleRevision/expectedDecisionVersion만 받는다. migration 5의 start_receipts는 방·요청 ID, 요청자 세션, 의도 버전 묶음과 게임 ID를 영속 보관한다. 같은 요청자/같은 의도의 재시도는 기록된 게임을 반환하고 종료·서버 재시작 후에도 새 게임을 만들지 않는다. 다른 요청자는 영수증을 읽을 수 없고 같은 ID의 다른 의도는 충돌이다. UI도 실패했다고 새 ID로 자동 재시도하지 않는다. 조건 변경 시 이전 요청을 명시적으로 버리고 새로 확인한다. 종료 뒤 새 요청 ID로 다음 게임을 곧바로 만드는 것은 현재 거부한다. 다음 게임 준비 전환은 #23에서 명시적으로 구현한다.

## 늦은 참가와 공개 범위

시작 때 끊겨 있던 멤버와 늦게 온 멤버는 게임 투표권을 얻지 않는다. 진행 중 방 참가/heartbeat에서 관전자 참여만 기록한다. 관전자는 현재 사건·벌칙을 볼 수 있지만 고정 투표 명단에 들어가지 않는다. 단순 GET은 참여 권한을 만들지 않는다.

게임 종료 후 새 방 참가자는 그 게임 참여 행을 얻지 않는다. RoomSnapshot의 이전 게임과 저장 초안 사건/벌칙·수락 상태도 가려져, 히스토리 endpoint를 우회해 이전 내용을 읽지 못한다. GET·join·heartbeat 세 경로를 검사한다. 실제 참여자는 종료 후 해당 기록을 읽을 수 있으나 현재 명령 권한과는 별개다. 중단 공개 규칙 #33은 미결정이므로 interrupted 게임은 현재 최소 공개로 게임 내용/초안 내용을 가린다. 다음 게임 초안 전환은 #23에서 이 경계를 유지하며 설계한다.

## 검증

실제 API로 2명 실패/3명 성공, 동시 동일 요청 한 게임, 현재 방장 권한, 늦은 관전자, 종료 뒤 동일 요청 재시도, 새 참가자 교차 endpoint 비공개를 확인한다. 임시 DB에서는 6명 시작/5명 투표자, stale 피고와 거절 경합, 처음 끊긴 사람의 관전자 복귀, 영수증 실패 rollback, 재시작 뒤 영수증 재사용을 검사한다. 브라우저는 독립 5컨텍스트 시작·6번째 관전자·재방문·반복 요청과 실패 재시도 의도 보존을 검사한다. 전체 한 판 E2E·실기기·외부 배포 완료는 아니다.

## 화면 확인

390px Chromium 화면의 시작 완료 영역을 `artifacts/start/started-mobile.png`로 캡처하고 직접 확인했다. 변론 단계, 본인 피고 역할·투표 불가, 저장된 사건/벌칙, 시간, 현재 게임 참여 인원과 고정 투표 대상 인원이 구분되어 읽힌다. 역할/설정/수락 편집은 시작 뒤 숨기며 아직 없는 변론 제출/투표 버튼은 표시하지 않는다. 관전자가 늘어날 수 있어 참여 인원을 시작 명단 숫자라고 부르지 않는다. 실기기 검증은 아니다.
