# 사용자에게 조작을 넘기지 않는 기본 흐름 검증

## 범위

실제 Kakao 로그인은 별도 격리 서버에서 사용자가 완료했고 계정·유효 세션 생성으로 확인했다. 해당 사용자 브라우저의 제어 surface가 없어 그 쿠키를 추출하거나 인증을 우회하지 않는다. 운영 DB/서비스와 사용자 로그인 테스트 DB는 변경하지 않는다.

이번 추가 시험은 임시 DB의 실제 React/Nest/SQLite와 3개 독립 브라우저 context를 사용한다. 인증 제공자 교환만 합성이다. 실제 사용자 계정으로 다인 게임을 실행한 증거가 아니며 실제 Kakao·실기기·운영 인수로 확대 해석하지 않는다.

## 추가 확인

`travel-ui-journey-real-api.spec.mjs`: 화면에서 방 생성, 초대 발급, 다른 두 명 참여, 새로고침, 팀 나누기, 새로고침 후 이력 조회, 한 참가자 로그아웃, 새 context에서 같은 합성 identity로 다시 로그인. 이전 membershipId·3인 명단·이력이 유지되고 로그아웃 세션은 401, 다른 로그인 세션은 200임을 단언한다. 사용자 쿠키를 복사하지 않는다.

초기 진단 실패는 실제 accessible name의 필수 표기 누락과 합성 인증 코드 재사용이었다. 후자는 서버의 정상 일회성 코드 보호에 의해 거절됐다. 새 로그인마다 새로운 합성 코드를 사용하고 callback 200 외에 실제 authenticated 세션을 추가 확인했다. 보호장치를 약화하지 않았다. 독립 소스 검토 승인 후 focused 시험과 전체 travel E2E를 다시 실행한다.
