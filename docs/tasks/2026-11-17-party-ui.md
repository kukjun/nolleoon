# 파티룸 UI 개편

상태: 구현 중

## 목표와 범위
승인한 캐릭터 무대 대기실과 단계별 단일 행동을 React 화면에 적용한다. 기존 재판 정책·익명성·신원 경계를 유지한다. 팀/제비는 서버 계약에 따라 구현하며 클라이언트 합성 결과를 사용하지 않는다. 운영 배포·기존 중단 WIP 변경은 범위 밖이다.

## 미결정과 가정
제비 미공개 장기 이탈은 별도 정책 결정 전 자동 공개/완료하지 않는다. 이 문서는 기존 사용자 정책을 대체하지 않는다.

## 합격 기준
320/390px 현재 행동 접근, 긴 글/키보드/초점/재접속, 미저장 보존, 중복 전송 잠금, 익명 표 정보 미노출. 실제 서버 기반 다인 E2E는 통합 후 검사한다.

## 실행과 증거
#77: party-tokens.test.mjs 먼저 실행해 누락 CSS ENOENT로 RED 확인. 토큰 추가 후 동일 시험 GREEN. 상태행렬 문서와 scoped token만 추가, 기존 화면 스타일에는 아직 미적용.

#85: 실제 API/임시 DB의 독립 2브라우저 로비 시험을 먼저 실행해 캐릭터 무대 부재 RED 확인. 로비 추가 후 같은 시험 GREEN 1/1, 320px 가로 overflow 없음. Node 24/Chromium emulation, 실기기 아님. 초기 fallback은 닉네임 이니셜이며 아바타 통합은 #84로 분리. 기존 준비 UI는 숨겨도 마운트를 유지하여 대기실 왕복에 입력이 사라지지 않도록 한다. 도입용 별도4184 Playwright 설정/서버를 추가했고 기존4179 하네스는 바꾸지 않았다.

#87: 단계 버튼 부재 RED 뒤 CourtSetup을 구현했다. 설정→역할·동의→시작 대기, hidden mount로 작성 내용 보존, host 미저장/저장중에는 다음 단계 차단, nonhost 역할 직접 선택 유지. 동일 4184 테스트 2/2 GREEN(로비+새 단계), build/type/scoped ESLint PASS. 테스트는 실제 API의 저장/역할/수락과 min3 시작 잠금까지 확인했다. 전체 다인 재판 회귀/최종 디자인/실기기는 아직 미실행이다.

#88: 실제 3인 재판 test에서 사건 문맥 button 부재 RED 후 모달 패널/투표 dock 구현. 변론/이전 라운드 이유는 보조 패널, 투표입력은 유지, 현재 역할·시간·접수 상태 노출. 동일 테스트+로비+준비 3/3 GREEN, 투표 320px CTA가844px 첫viewport 내에 있으며 screenshot 확인. 타인 이유 미공개, 모달 전후 선택·입력 유지, 제출 후 새로고침 영수증 유지 검사. 기존 모든재판 회귀 및 실기기 전체합격은 아직 아님.

#86 기반: 공통 타입에 맞춘 별도 Party API adapter와 polling hook/선택 카드 컴포넌트. adapter RED(module부재)→GREEN2/2, 타입/lint PASS. 영수증 action/request/run 일치 검증, 알려지지 않은 응답키/타인 결과 거부, trial 참조는 기존 공개권한에 위임. 아직 실제 Party API 화면 통합/브라우저는 대기 중이며 #86 완료가 아니다.
