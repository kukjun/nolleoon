# 작업 제목

상태: 제안 / 승인 / 진행 / 검증 / 완료

## 목표와 범위
사용자가 원하는 결과, 바꾸는 것, 바꾸지 않는 것.

## 미결정과 가정
결정이 필요한 사항과 임시 선택을 분리한다. 제품 규칙을 추측해 구현하지 않는다.

## 합격 기준
관찰 가능한 사례를 적는다. 각 기준을 실제 검사 또는 수동 확인과 연결한다.

## 실행과 증거
실행 명령, 결과, 검사한 코드 상태, 실패 및 미실행 영역.
`node tools/harness/check.mjs`의 통과는 하네스 기반 검증일 뿐 제품 합격이 아니다.

## 회고
놓친 결함은 재현 시험으로 추가한다. 불필요한 규칙은 늘리지 않는다.
