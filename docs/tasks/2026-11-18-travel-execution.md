# 영속 여행방 개편 실행

상태: 진행. 상위 이슈 #117, 세부 #118–144. 웹 구현만 포함하며 Flutter/스토어 출시는 제외한다.

## 목표와 범위

카카오 계정, 영속 여행방, 방 관리자와 한 판 진행자 분리, 선택 참가자와 동시 한 판, 기존 팀/제비/재판 전환 및 메뉴 정하기를 단계적으로 구현한다. 최신 사용자 지시는 의존성 기반 병렬 구현과 테스트·독립 리뷰를 허용한다. 운영 릴리스는 실제 수용 기준을 충족한 뒤만 실행한다.

## 작업 격리

- 기준: remote main `fef022dbb12311e7d58b7ed9167615fcc84bccf6` (시작 시 fetch 확인).
- 기존 미완성 작업은 변경하지 않는다. 별도 integration/auth/backend/ui worktree를 사용한다.
- 인증은 인증 담당, additive schema/여행방은 backend 담당, React UX는 UI 담당이 소유하고 공통 계약을 먼저 합의한다.
- 테스트는 합성 데이터와 격리 SQLite 파일을 사용한다. 운영 DB·진행 중 게임·서비스는 구현 작업에 사용하지 않는다.

## 미결정과 가정

- #119 삭제·공동 기록·마지막 관리자 및 예외, #135 메뉴 상세, #116/#140 보관/용량은 큰 결정을 숨겨 확정하지 않는다.
- 명시적으로 승인된 제비 정책: 미공개 참가자가 연결 끊김 후 10분 내 돌아오지 않으면 미완료 종료, 이미 공개된 결과만 남기고 새 판에서 새 배정. 여행방 멤버십은 유지한다.
- #33 중단된 재판의 상세 필드, #36 원격 CI, #63 실물 기기는 미해결 상태를 별도로 보고한다.
- 카카오 실제 설정/자격증명 없이 mock 테스트를 실서비스 로그인 성공이라고 표현하지 않는다.
- 계정 삭제/영구 기록 삭제, 보관기간 임의 설정과 자동 데이터 삭제를 하지 않는다.

## 합격 기준

선행 이슈별 TDD와 단위/API/DB/브라우저 회귀, 단계별 draft PR과 독립 리뷰·수정·재리뷰, 통합 exact commit 전체 하네스, 실제 provider 및 실물 기기/외부 검증의 결과를 구분한다. 기존 기록·사진·세션 권한을 보존하고 기존 닫힌 방을 새 여행방으로 자동 생성하지 않는다. 마이그레이션/복구 및 권한 매트릭스를 검증한다. 실패·미실행 gate가 있으면 제품 전체 완료 또는 배포 가능으로 표현하지 않는다.

## 실행과 증거

기준선 전체 검증을 실행 중이다. 검증 결과와 실제 커밋은 실행 완료 후 추가한다. 이 문서의 계획은 통과 증거가 아니다.
