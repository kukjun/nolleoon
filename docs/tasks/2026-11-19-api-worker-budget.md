# API 파일 워커 예산 · #190

상태: 검증

## 목표와 범위
API 파일들을 한 워커로 실행하여 자식 프로세스 시작 검사와 같은 CPU를 놓고 경쟁하는 시험 부하를 제한한다. npm discovery와 전체 하네스는 동일 실행 인수 함수를 사용한다. 비즈니스 코드, 테스트 선택/내용, 개별 production 2초 및 durability 4초 제한, 다른 suite 병렬 정책은 변경하지 않는다.

## 미결정과 가정
42f0edd의 같은 46파일/151개를 비교했다. 표준 병렬 실행은 50.8초에 149 통과/2 production 시작·종료 실패였고, 다른 작업을 멈춘 뒤 파일 직렬 실행은 실제 99.038초에 151 통과/실패·skip 0이었다. 이 관측은 실행 경합 가설을 지지하지만 모든 장치의 시작 성능이나 제품 전체 합격을 입증하지 않는다.

## 합격 기준
- API에만 `--test-concurrency=1`을 적용한다. npm과 전체 하네스가 같은 탐색 결과 및 인수 정책을 쓴다.
- 중첩 파일 누락 없이 실행하며 skip/빈 시험을 통과 근거로 인정하지 않는다.
- 전체 API gate 예산을 기존 15초에서 **180초**로 명시적으로 변경한다. 약 99초 실측에 여유를 두는 suite 예산이며 개별 시작 deadline을 늘리지 않는다.
- 독립 리뷰 및 최종 통합 RC의 전체 검사 전에는 완료/출시로 판단하지 않는다.

## 실행과 증거
신규 계약 시험은 예산/공유 인수 함수 부재로 2개 RED를 확인한 후 구현했다. 동일 파일 목록을 synthetic fixture에서 npm 실행 인수와 aggregate runner 출력으로 비교하며, 기존 runner의 timeout/실패/skip 방지 회귀도 함께 검사한다.
전체 API의 직렬 진단은 수정 전 42f0edd 증거다. 이 변경의 최종 통합 전체 API/제품 하네스 결과와 혼동하지 않는다. 운영·원격 CI·실기기 검사는 수행하지 않는다.

## 회고
테스트 부하와 제품 시작 요구사항은 별개다. 무한 재시도나 개별 timeout 완화로 문제를 숨기지 않고, worker 예산과 suite 예산을 따로 검토한다.
