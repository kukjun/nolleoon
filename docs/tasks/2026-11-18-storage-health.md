# 백업/용량 읽기 전용 상태 점검

## 목표와 경계

일1회·최근7일·RPO24시간의 기존 백업 도구를 보완한다. 기존 복원/삭제 ledger를 중복 구현하지 않고 최근 snapshot 시각과 용량 경보를 명시적으로 검사한다. 운영 경로/사용자 데이터/스케줄/권한/외부 서비스는 건드리지 않는다.

## 합격 기준

- 정확한24시간 경계, 과거 timestamp없는 manifest, 변조/미래/잠금/원본불일치/누락은 정직한 상태로 보고한다.
- 예산초과는 경보이며 hard quota로 주장하지 않는다. 출력에 경로나 내용이 없고 검사만으로 파일을 바꾸지 않는다.
- 기존 일일 보관/원본 alias보호는 계속 통과한다.

## 실제 검증

신규 모듈 없는 RED(import 실패) 확인 후 구현했다. 합성 임시 파일의 신규6+기존5 단위시험, lint 검사를 수행했다. 브라우저/API/전체 하네스는 이 스토리지 CLI만 변경하는 작업에서 별도 재실행하지 않았다. 운영 서비스에 스케줄/감시를 설치하지 않았다.
