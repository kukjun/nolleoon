# #217 여행방 홈·로비 시각 계층

상태: 구현, 합성 회귀 검증 중 / 사용자 시각 인수 전

## 목표와 범위
같은 웹 색감에서 참가자와 현재 판을 중심으로 읽는다. 상시 프로필/탈퇴/휴지통 줄은 계정 메뉴로 옮기고, 방 관리/기록은 방 더보기로 묶는다. 판이 없을 때 게임 고르기 한 가지 주 CTA, 친구 초대는 보조다. 현재 판이 있으면 기존 현재 판 보기만 주 CTA다. 종료 방에는 새 게임 CTA를 제공하지 않는다. 기존 callback/세션/권한/API와 저장소는 바꾸지 않는다.

FeatureShell·RoomsScreen 및 관련 fixture만 소유한다. #218 GameScreen onExit 계약에 기존 FeatureSession.home을 연결하며 방 ID를 유지한다. 게임/서버 상태를 바꾸는 명령이 아니다. 실제 운영/키/시뮬레이터/4189 접근 없음.

## 미결정·가정
이번 화면은 사용자 승인 요구사항을 구현한 후보이며 픽셀/디자인 최종 인수와 다르다. 색은 기존 AppTokens 그대로 유지한다. 좁은 화면에서 관리 메뉴가 본문 높이를 계속 차지하지 않도록 소유 DialogRoute를 사용한다.

## 합격 기준
- 최초 홈에서 개인 메뉴 항목 숨김, 메뉴 열기/닫기/뒤로/중복 탭으로 API mutation 없음.
- 메뉴는 자기 route만 소유하며 scope 변경·배경·dispose 시 회수한다. 오래된 callback으로 다른 세션을 이동시키지 않는다.
- 320×568/2.0, 390×844/1.6 긴 한국어 이름에서도 스크롤·조작 가능, overflow 없음.
- 로비 참가자가 현재 판/새 게임 CTA보다 앞, 관리/기록은 더보기 안으로 이동.
- 기존 프로필·초대·판 생성·투표·삭제/회복·아바타 기능 단언 유지.

## 실행과 증거
신규 두 widget 시험은 기존 구현에서 상시 개인 메뉴 노출로 RED. 메뉴 구현 후 시스템 뒤로가 nested navigator의 dialog에 전달되지 않는 것을 발견하여 root Navigator의 소유 route로 연결하고 회귀를 유지했다.

기존 root fixture는 숨겨진 메뉴를 먼저 열도록 변경했다. 참가자 중심 배치로 현재 판 CTA가 스크롤 끝 경계에 걸리는 기존 fixture에서 tap miss 4건을 확인했다. 단언을 삭제하지 않고 Scrollable.ensureVisible(alignment:.5)와 hitTestable 단언으로 실제 버튼 중심을 보이게 한 뒤 동일 기능 시험을 실행했다.

최종 전체 Flutter 281 PASS, analyzer no issues. #218의 2996be0 GameScreen을 검증용으로 포함했으며 이 작업 커밋에는 해당 파일을 넣지 않는다. 실제 API·OS·실기기·새 시각 캡처는 이 widget 시험의 범위가 아니다.
