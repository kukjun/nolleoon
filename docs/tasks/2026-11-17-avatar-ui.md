# 아바타 UI · #81 / #84

상태: 구현 및 집중 검증 중

## 목표와 범위
입장 전 오리지널 캐릭터 10종 또는 직접 고른 사진을 저장하고, 같은 브라우저 신원으로 입장·방·진행·결과에서 일관되게 표시한다. 캐릭터는 장식이며 방장/피고 권한을 바꾸지 않는다. 익명 투표·이유에 캐릭터를 연결하지 않는다.

## 구현 경계
- 별도 avatar API를 사용하여 기존 RoomSnapshot 응답을 변경하지 않는다. 프로필 조회 실패 시 기본 캐릭터로 게임 흐름은 유지한다.
- 내 사진은 PNG/JPEG/WebP, 원본 파일 1MiB/4MP 이내. 브라우저에서 확대·가로/세로 위치를 고른 256px 정사각 WebP를 미리 보고 저장한다. 실제 저장은 서버 검증/재인코딩 및 방 권한 검사에 의존한다.
- 편집 취소는 전송하지 않으며 object URL과 bitmap을 해제한다. 저장 오류는 편집창을 닫지 않는다. 선택한 사진이 다른 참가자에게 보인다는 설명을 저장 전에 표시한다.
- 사진을 선택해도 저장 버튼 전에는 업로드하지 않는다. 사진 원본을 저장소/정적 디렉터리에 넣지 않는다.
- 현재 프로필을 방과 결과에 표시한다. 과거 기록의 불변 초상 스냅샷은 구현하지 않는다.
- 이미지 조회 권한이 사라지거나 로드가 실패하면 기본 캐릭터로 표시한다. 이미지 URL은 앱 내부의 지정된 아바타 API 경로만 허용한다.
- 새 게임 종류, 운영 배포/데이터 마이그레이션은 이 작업의 범위가 아니다.

## 에셋
실제 생성 원본 10종을 확인한 뒤 256px WebP로 변환했다. 안정적 ID와 출처는 `apps/web/src/assets/avatars/README.md`에 기록한다. 프리셋 변경은 현재 게임 역할에 영향을 주지 않는다.

## 검증
`node --test tests/unit/avatar-*.test.mjs`: 6개 통과. 응답/URL 검증, 파일 크기·타입, crop 경계, 10개 WebP 실제 크기와 import 검증.

브라우저 `avatar-picker.spec.mjs`는 아바타 API 응답만 route mock으로 대체하는 프런트엔드 상호작용 시험이다. 별도의 실제 backend 연동 인수, 보안 검증, 실기기 검증을 대체하지 않는다. 서버 구현 통합 후 실제 저장·타 참가자 표시를 재검증해야 한다.

집중 브라우저 3/3 통과(320px Chromium, retries 0): 프리셋 저장·새로고침 복원·Escape 취소/초점 복귀, 잘못된 파일 타입 거절·crop 미리보기·취소 시 미전송, 256px WebP 실제 전송 내용·409 실패 시 편집 유지·재시도. 최초 1/3 실패에서 발견된 320px 모달 가로넘침과 닫기 버튼 폭 충돌을 수정했다. 재실행에서 선택지 44px 이상과 모달 가로넘침 없음도 검증했다. 최종 화면 `artifacts/party-ui/avatar-picker-320.png`를 실제 육안 확인했다. 아바타 API는 이 시험에서 mock이며, 운영에 배포하지 않았다.
