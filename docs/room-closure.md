# 방 종료와 안전한 중단 기록 (#22)

## 종료 조건

현재 방장의 `POST /api/rooms/:code/close` 또는 마지막 멤버의 확정 퇴장으로 방을 닫는다. 연결이 끊겼지만 10분 유예 중인 멤버가 남으면 자동 종료하지 않는다. 확정된 마지막 expiry의 논리 시각으로 종료한다. 닫힌 방에는 새 참여나 새 게임·변론·투표 같은 명령을 허용하지 않는다. 없는 링크는 404, 닫힌 방의 새 참여는 `ROOM_CLOSED` 410으로 구분한다.

수동 종료는 정상 투표를 조기에 판결하는 기능이 아니다. 진행 게임을 판결 없이 중단하며 이미 마감한 라운드는 먼저 정산한다. deadline이 종료 효력보다 빠르거나 같으면 정산을 먼저 적용한다. 그때 최종 결과로 끝났으면 결과를 보존한다. 첫 동률 상태라면 진행 게임이므로 중단한다. 미완료 표로 결과를 만들지 않으며 닫힌 뒤 monitor가 중단을 판결로 덮어쓰지 않는다.

## 원인과 공개 경계

v8 migration은 최초 중단 원인(`defendant-left`, `room-closed`, `legacy-private`) 및 방 종료 시각/종료 멤버를 저장한다. 중단 원인과 종료 기록은 DB trigger로 수정·삭제를 막는다. 기존 중단 데이터는 원인을 추정해 공개하지 않고 `legacy-private`로 보수적으로 이전한다. migration 1~7은 바꾸지 않는다. 기존 `legacy-private`의 interrupted_at에 넣은 created_at은 실제 중단 시각을 복원한 값이 아니라 기존 데이터에 시간이 없다는 보수적 대체값이다. 이 값은 API에 공개하지 않으며 후속 이력에서도 실제 중단 시각으로 표시하면 안 된다. 신규 원인 기록만 실제 효력 시각을 가진다.

방 종료가 실제 원인이었던 중단만 그 게임 참가자에게 사건 내용과 중단 상태를 보여준다. 벌칙·변론·미완료 표·이유는 표시하지 않는다. 피고 퇴장으로 이미 중단된 게임을 나중에 방 종료했다고 `room-closed`로 재분류하지 않는다. 마지막 퇴장자가 피고였으면 피고 퇴장 중단이 먼저 기록되므로 이 경우도 비공개다. [미결정 #33](https://github.com/kukjun/trip-court/issues/33)의 공개 범위를 임의로 넓히지 않는다.

완료 게임은 실제 게임 참여 이력이 있는 신원에게만 그대로 조회된다. 방에 가입한 이력이나 초대 링크만으로 과거 게임 권한을 만들지 않는다. 닫힌 방의 GET/heartbeat는 읽기만 수행하고 멤버 touch·관전자 추가·타이머 재개를 하지 않는다. 응답은 빈 현재 명단과 비활성 명령 상태를 제공한다. 별도 개인 이력 목록/진입 UI는 #24에서 다룬다.

## 재시도와 경합

종료 명령은 쿠키 신원과 `expectedMemberId` 소유권/현재 방장을 확인한다. 종료 응답이 유실되면 원래 종료한 멤버만 같은 완료를 재확인할 수 있다. 다른 참가자가 닫힌 뒤 방장인 척 새 종료를 승인받을 수 없다. 마지막 나가기의 기존 멤버십 재확인은 닫힌 뒤에도 추가 상태 변경 없이 가능하다.

종료·마지막 표·후발 참여는 쓰기 transaction으로 직렬화된다. 마지막 표가 먼저 처리돼 전원 완료됐으면 결과를 유지하며, 종료가 먼저면 새 표를 거절한다. 후발 참여가 먼저 승인됐으면 관전 참가 이력을 유지하지만 종료 뒤 신규 참여는 거절한다. 중간 저장 실패는 게임 중단·원인·방 상태 전체를 rollback한다.

## 검증

신규 endpoint 부재 RED 후 실제 API/SQLite로 권한·재시도·마감 전/동시/후·유예 마지막 만료·기존 원인 보존·완료 결과 권한·마지막 표/참여 경합을 검사했다. migration 재실행, 기존 데이터의 비공개 backfill, 불변 trigger, 실패 rollback/재개방도 검사했다.

실제 Chromium에서 수동 종료 확인, 동시 클릭 및 응답 유실 재시도, 외부 방문 차단, 완료 결과 재방문을 확인했다. 이 과정에서 종료/나가기 컴포넌트의 같은 React key가 중복 버튼을 만들던 실제 결함을 발견해 접두어를 분리했다. 320px 캡처에서 종료·판결 없음·허용된 사건만 표시되는 것을 직접 확인했다. 실기기 또는 외부 배포 검증을 의미하지 않는다.
