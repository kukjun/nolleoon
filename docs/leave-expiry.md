# 나가기와 10분 유예 (#20)

## 효력과 신원

명시적 나가기는 즉시 해당 멤버십의 `left_at`을 기록한다. `POST /api/rooms/:code/leave`는 `{expectedMemberId}`만 받고 쿠키 신원의 소유 멤버십인지 서버에서 확인한다. 이미 나간 같은 멤버십 재시도는 성공을 재확인할 뿐 새 재참여 멤버십을 건드리지 않는다. 요청 응답이 유실되면 UI는 같은 멤버십을 재확인한다.

연결 단절 감지 시각 `disconnectedAt`부터 600,000ms가 지나면 자동 퇴장이다. 599,999ms 복귀는 같은 멤버십을 복구하지만 정확히 600,000ms부터는 heartbeat가 되살릴 수 없다. 새 참여는 새 멤버십이며 진행 중 게임에는 관전자로 들어간다. 같은 브라우저의 여러 멤버십은 화면 참여 인원에서는 한 신원으로 세고, 시작 시 동결한 투표 대상은 변경하지 않는다. 신원 식별자는 응답에 공개하지 않는다.

독립 1초 monitor와 요청 경계가 같은 유지보수 함수를 사용한다. 유지보수는 이후 명령의 권한 오류와 별도 커밋하므로 403으로 만료 처리가 롤백되지 않는다. 각 명령은 이후 transaction에서 현재 멤버십 권한을 다시 확인한다. 클라이언트 시각은 사용하지 않는다.

## 투표와 피고 퇴장의 시간 순서

서버가 지연되거나 재시작되어 여러 기한이 지난 경우에도 논리 시각을 기준으로 처리한다. 투표 deadline이 피고 퇴장 효력보다 빠르거나 같으면 먼저 정산한다. 최종 결과로 끝났다면 이후 퇴장으로 중단되지 않는다. 첫 동률이면 정산을 보존한 뒤 피고 퇴장으로 중단한다. 피고 만료가 먼저면 진행 라운드를 중단하고 뒤늦은 판결을 만들지 않는다.

단순 단절은 중단 사유가 아니다. 고정 투표자는 퇴장해도 분모에서 빼지 않으며 이미 받은 표도 보존한다. 미제출분은 마감 때만 기권으로 집계하며 사용자 제출 영수증을 만들지 않는다. 기존 deadline은 연장하지 않는다.

중단된 게임은 최소 중단 표시만 제공하고 사건·벌칙·이유는 숨긴다. 이미 저장된 1차 정산은 DB에서 보존하지만 중단 이후 공개 정책은 [미결정 이슈 #33](https://github.com/kukjun/trip-court/issues/33)이며 이 구현은 공개 허가로 해석하지 않는다.

## 단계별 범위

방장이 나가면 현재 포인터를 비우고 UI에 공석을 표시한다. 랜덤 위임은 #21이다. 전원이 나갔을 때 방을 닫는 작업은 #22이며 이 단계에서는 자동 폐쇄를 주장하지 않는다. 기존 회원·게임·표를 삭제하지 않고 새 migration 없이 기존 스키마를 사용한다.

## 검증

초기 RED는 leave endpoint 404와 만료 경계 heartbeat 201(기대403)이었다. 실제 SQLite/API 시험으로 두 monitor 실행 순서와 마감 이전·동시·이후 만료, 직접 명령 거부에도 만료 커밋, 중간 저장 실패 rollback과 저장소 재개방, 퇴장 표 보존을 검사한다. 브라우저는 실제 나가기·관전자 재참여·응답 유실 재시도·다른 탭 재참여 뒤 늦은 옛 응답 무시를 검사한다. 10분 경계는 주입 서버 시계 시험이며 실제 10분 대기나 실기기 백그라운드 시험을 했다는 뜻은 아니다.

모든 명령은 요청에서 한 번 캡처한 서버 시각을 유지보수·유예 판정·touch/퇴장·투표 시작에 공유한다. 증가하는 fake clock에서 경계 직전 판정 뒤 경계 이후 touch를 쓰던 RED(601000, 기대600999)를 재현하고 요청 시각을 통일했다. 이는 요청 시작 시각 기준 정책이며 네트워크의 클라이언트 전송 시각을 신뢰하는 정책이 아니다.
