# 같은 브라우저의 개인 게임 기록 (#24)

## 접근 기준

`GET /api/history`와 `GET /api/history/:gameId`는 쿠키의 서버 신원으로 실제 game_participants와 room_members의 세션 연결을 확인한다. 방 가입이나 같은 닉네임만으로 과거 게임을 볼 수 없다. 진행 중 입장해 관전자로 등록된 사람은 그 게임 기록을 갖고, 종료 후 방에 들어온 사람은 이전 게임 기록을 갖지 않는다. 퇴장·방 종료 뒤에도 같은 유효 신원의 실제 참여 기록은 유지한다. 여러 멤버십으로 같은 게임에 참여했어도 EXISTS 조회로 게임당 한 항목만 반환한다.

목록도 UI 필터가 아니라 서버 권한 조건으로 제한한다. 다른 세션의 cursor/gameId를 넣거나 다른 방 경로로 gameId를 바꾸면 접근을 거절한다. sessionId 같은 임의 query로 신원을 고를 수 없다. 응답은 no-store이며 클라이언트 기록은 화면 메모리에만 보관한다.

## 목록과 상세 공개

완료 게임은 사건·판정 요약과 기존 결과/두 라운드 익명 이유를 보여준다. 진행 중 게임은 사건과 진행 중 상태만 표시하며 목록·개인 상세에서 진행 중 표·이유·벌칙은 제공하지 않는다. 이는 실제 투표 화면의 대체 명령 UI가 아닌 읽기 전용 기록이다.

방 종료가 원인이었던 중단은 사건과 중단 상태만 표시한다. defendant-left/legacy-private 중단은 사건 제목·snippet·벌칙·역할·표수·이유·추정 중단시각을 목록 또는 상세로 우회 공개하지 않는다. #33의 미결정 공개 규칙은 그대로다.

## 페이지·복구·보관

한 페이지는 20개이며 다음 항목이 있으면 nextCursor를 반환한다. 생성시각과 게임 ID의 내림차순 keyset으로 이어 읽는다. cursor 자체는 소유 게임 ID이며 내부 시간값을 싣지 않는다. 같은 생성시각도 ID로 순서가 정해지고 새 기록이 앞에 추가되어도 이어 읽던 과거 페이지가 밀려 중복되지 않는다. 새 항목은 처음부터 새로 읽을 때 나타난다. UI는 더 보기로 나머지 기록이 있음을 표시하며 처음 20개를 전체라고 주장하지 않는다.

계정/다른 기기 복구 기능은 없다. 쿠키 삭제·신원 만료 뒤 같은 닉네임으로 이전 기록을 되찾을 수 없다. 신원 쿠키의 90일 갱신 정책과 서버 기록 보관은 별개다. 초기 자동 삭제 작업은 없지만 영구 보존이나 영구 접근을 보장하지 않는다.

기록 화면 동안 현재 방 컴포넌트는 숨긴 상태로 연결을 유지하여 단순 탐색을 퇴장으로 바꾸지 않는다. 닫기/화면 정리 시 요청을 abort하고 신원 소실 때 목록·상세를 제거한다. 이전 신원의 늦은 응답이 새 신원 화면을 복구하지 못하게 요청 세대/abort를 확인한다. history detail은 현재 room snapshot에 병합하지 않는다.

## 검증

endpoint 부재 RED(404, 기대200) 이후 실제 API/SQLite로 관전자·종료 후 참가·다른 쿠키·같은 닉네임·퇴장/닫힌 방·중복 멤버십·private 중단·26개 keyset과 페이지 중 새 항목·두 라운드 이유·cross-room ID를 검사했다. 기록 탐색 전후 신원/명단/초안/동의 불변과 만료 쿠키401도 검사한다.

실제 Chromium에서 두 게임·닫힌 방·reload·다른 브라우저 빈 기록·지연 응답과 쿠키 소실을 확인했다. 추가 페이지 UI는 20→21 항목 계약 fixture로 검증했으며 실제 21게임을 브라우저로 진행했다고 주장하지 않는다. 서버 페이지 회귀는 실제 SQLite 기록을 사용한다. 320px 캡처를 직접 확인했으며 실기기/외부 배포 검증은 아니다. 새 migration은 없다.

최종 clean clone 전체 검사에서 상단 기록 진입 버튼이 모바일 결과를 아래로 밀어 기존 결과 우선 기준을 깨뜨린 회귀가 발견됐다(집계 영역 y=189, 기준 y<180). 기존 assertion을 바꾸지 않고 기록 진입을 현재 방/결과 내용 뒤로 이동했다. 원래 결과 시험과 개인 기록 동선을 다시 검사하며, 최종 통과는 재검증 보고서로 확인한다.
