# 남은 결정과 구현 검증

핵심 한 판 규칙은 [현재 규칙](00-current-rules.md)으로 기준선을 잡았다. 아래를 완료 사실로 처리하지 않는다.

## 제품 결정 대기
- [#33](https://github.com/kukjun/trip-court/issues/33): 피고 퇴장 중단 이력에서 보여줄 필드, 이미 공개했던 1차 이유를 계속 보여줄지. 방 종료 중단의 정책을 무조건 이 경우에도 복사하지 않는다. 확인 전 미정 필드 공개를 차단하는 보수적 제안이며 최종 인수는 결정 후 검증한다. 독립 기능 작업은 진행 가능하다.

## 위임된 구현 선택·측정
- 입력 길이·닉네임 정규화·방 인원 운영 상한, 세션 유지 기간·쿠키 복구, 폴링/단절 감지 간격은 각 기능 티켓에서 경계 시험과 함께 고정한다. 6명 참여를 임의로 막지 않는다.
- 정확한 패키지 버전·Node 호환성은 초기 구성과 설치 시 확인해 lockfile에 기록한다. 문서만으로 지원을 주장하지 않는다.
- 서버 재시작 후 마감/10분 유예 복구, 운영 백업/복구, 실제 모바일 백그라운드 동작은 해당 후속 시험 전 미검증이다. SQLite 기본 잠금·rollback 시험과 전체 운영 복구를 구분한다.
- 실제 도메인/Tunnel 설정·포트·배포 경로는 기존 서비스와 분리해 배포 티켓에서 확인한다.

## 다음 단계 게이트
기능 티켓마다 실패 시험→최소 구현→리팩터→검증 증거, 최종 E2E와 리뷰에서 미해결 항목을 공개한다. 미정/blocked를 통과로 세지 않는다.
