# 4단계 A: 게임 규칙·상태 설계

> 24차 일괄 확정: [최신 예외 규칙](00-current-rules.md)이 아래 과거 미정/제안보다 우선한다. 1~11 승인 및 25차 이유 공개 확정. 첫 동률 집계+익명 이유 공개, 최종 양 라운드 이유·무판결 기권 이유 공개.

> 23차 사용자 정정(이전 역할 가정 대체): 방장은 방 관리·게임 설정·시작 권한이며 게임 역할과 독립이다. 게임을 만든 뒤 역할을 선택하고 방장도 피고가 될 수 있다. 피고는 무작위 방장 이양 후보에서도 제외하지 않는다. 작성자=원고/방장≠피고 가정은 폐기하며 원고 역할은 정의되지 않았다.

> 22차 우선 적용: 끊김 후 10분 미복귀는 나감, 전원 나가면 방 종료. 방장 10분 미복귀 시 남은 참가자 중 무작위 이양(없으면 종료). 이전 이양 없음/방장 부재 시 새 방 필수 규칙은 대체되었다. 이양 후보 접속 기준·자발적 방장 나가기 세부는 미정.

> 최신 도메인 기준(20차): 같은 방에서 사건을 순차 진행하며 기존 참가자는 재입장하지 않는다. 사건마다 피고·벌칙 수락·투표 자격을 새로 정한다. 아래 이전 차수의 사건 링크/참가자 모델은 사건 내부 정책의 이력이며, 방과 사건을 분리해 읽는다. 21차에서 방 링크 유지·방장만 게임 설정·사건별 기록 접근·방 종료가 추가 확정되었으며 이후 결정이 과거 미정 문구보다 우선한다. 세부 미정은 02-open-questions.md 참조.

## 결론

서버가 사건 상태, 벌칙 버전, 방장 재판 시작 시점의 투표자 집합과 라운드 마감을 관리하는 구조를 제안한다. UI 진행과 실제 상태 변경을 분리한다. 재판 시작에서 벌칙을 고정한다. 투표자 집합도 방장이 재판을 시작할 때 고정한다. 반론 중 신규 참가자는 제외하고 첫 투표 개시는 고정 명단을 사용한다.

```text
DRAFT(클라이언트 초안)
  → LOBBY(사건 공유·참여·벌칙 확인)
      거절 → 작성자 수정·재제안 → 최신 벌칙 수락
  → DEFENSE(방장 재판 시작, 벌칙·투표자 고정; 선택 반론)
  → VOTING_R1(방장이 동시 개시, 라운드 마감)
      ├─ 유효 동률 → FINAL_DEFENSE → VOTING_R2 → CLOSED
      └─ 비동률/0유효표 → CLOSED
  R2 유효 동률은 무죄; 어느 라운드든 0유효표는 무판결
```

DEFENSE를 별도 상태로 둘지는 제안. 일반 반론 선택·방장의 투표 개시, 피고 선택 최후 변론·방장 재투표 개시는 확정이다. 일반/최후 변론은 작성 또는 건너뛰기가 가능하고 방장이 투표를 개시한다. 무응답 때도 방장이 반론 없이 진행할 수 있으며 피고에게 종료를 안내한다. 별도 반론 타이머는 없다. 취소·만료된 링크 상태도 운영 정책 확정 후 추가한다.

|---|---|---|---|

| 역할 선택/변경 | 참가자 본인 | 변경은 재판 시작 전, 피고 1명·방장도 선택 가능 | 역할 변경·피고 교체 시 기존 수락 무효화 |

| 투표 제출 | 고정 투표자 | 투표 중·마감 내·입력 유효 | 중복 방지 키·선택·이유 접수 |

| 재투표 개시 | 방장 | 피고 작성/건너뛰기 완료 또는 방장 무응답 진행 | 동일 투표자·원래 설정 기간, 새 라운드 시작/마감. 이전 표 재사용 금지 제안 |

## 집계

- G: 유죄 표, N: 무죄 표, A: 직접 기권, U: 만료 미제출. 실질 유효표 수는 G+N.
- G=1, N=0, A+U=3이면 유죄 사례 확정.
- G+N=0이면 판결 없이 종료 확정.
- G=N>0: 1차는 최후 변론 후 재투표, 2차는 무죄 확정. G+N=0 분기를 먼저 적용한다.
- G>N이면 유죄, N>G이면 무죄로 확정. A/U는 유효표 분모와 비교에서 제외한다.
- 직접 기권 이유는 선택이고 제출 완료에 포함한다. E를 방장 재판 시작에 고정된 자격자 수라고 할 때 G+N+A=E이면 전원 완료로 라운드를 종료한다. U는 시간 만료에만 생성한다.
- 끊김은 접속 표시이지 투표자 집합 변경이나 기권 제출이 아니다.

## 경합 처리 제안

- 투표 제출과 종료는 트랜잭션/동등 원자 처리로 직렬화. 서버 마감 이후 접수는 거절하고 실패 안내한다. 정확한 동시 경계는 서버 접수 시각 `< deadline` 기준을 제안하되 구현 전 명시한다.
- 라운드 종료는 동일 사건·라운드에 한 번만 처리하고 최종 판결은 사건당 하나만 생성. 재요청은 저장된 결과 반환.
- 벌칙 수정/수락 경합은 버전 조건으로 오래된 수락을 거절. 시작 조건을 같은 원자 처리에서 다시 검사.
- UI에서 버튼을 숨기는 것만으로 권한을 강제하지 않는다.
- 마감 시 클라이언트가 모두 닫혀도 종료 가능한 서버 작업/지연 정산 설계 필요. 정확한 방법은 아키텍처 선택 후 결정.

## 미결정

제출 후 수정/철회, 방장 미복귀 시 새 사건 안내·기존 사건 유지/만료 처리, 자발적 나가기 UI, 사건 취소·보관 만료. 이들 권한은 기본 허용으로 추정하지 않는다.

## 공개 단계
1차 동률 뒤에는 유죄·무죄·기권 집계와 1차 익명 이유를 공개한 뒤 최후 변론으로 진행한다. 최종 결과에서는 1·2차 익명 이유를 모두 공개한다. ‘라운드 종료’와 ‘최종 판결’은 서로 다른 공개 트리거다. 전원 기권 무판결에서도 직접 작성한 기권 이유를 공개한다.

## 복구와 상태의 구분
같은 기기·브라우저의 재접속은 기존 참가자/방장 복원이며 새 참가자 생성이나 라운드 상태 초기화가 아니다. 다른 기기/브라우저 닉네임 일치는 신원이 아니다. 브라우저 데이터 삭제 복구는 보장하지 않는다. MVP에서 방장 미복귀 시 새 사건을 만들며 기존 사건의 방장을 자동 이양하지 않는다. 새 사건 생성이 기존 사건 강제 취소 권한을 뜻하지 않는다.

연결 이상은 본인/다른 참가자에게 표시하고 복귀 시 서버 snapshot으로 재동기화한다. 감지 임계값은 실측 후 정하며 표시만으로 자격 집합이나 표를 바꾸지 않는다. 참가자별 라운드별 중복 방지는 확정 요구다.

개인 기록 조회는 게임 진행 상태를 바꾸지 않는 별도 기능으로 설계한다. 서버 기록이 남을 수 있으나 CLOSED가 영구 보관 또는 링크 공개를 뜻하지 않는다. 초기 자동 삭제 기한은 없으며 향후 삭제 정책은 미정이다. 완료 후 기존 참가자만 결과·이유를 조회한다.

12차 기록 정책: 개인 이력은 참여한 게임의 전체 결과·익명 이유를 제공. 초기 서버 자동 삭제 기한 없음, 추후 정책 결정. 이 결정은 CLOSED 사건을 초대 링크 누구에게나 공개하거나 영구 보관한다는 뜻이 아니다.

종료 후 신규 참여로 결과 조회 권한을 얻을 수 없다. 기존 참가자는 결과·이유를 조회하고 비참가자는 종료 안내만 본다. 첫 투표 뒤 입장자의 투표 불가는 재판 전체(재투표 포함)에 적용한다.

16차 상태 계약: DEFENSE/FINAL_DEFENSE에서 피고 제출·skip을 기록하고 방장이 투표 개시한다. 무응답이어도 방장 개시 허용. 변론은 이 전환에서 닫히고 피고에게 종료 안내가 전달된다. 별도 변론 타이머 없음. 제출/개시 경합은 원자 처리하며 이미 투표 상태면 변론 제출을 거절·실패 안내하는 설계. 이는 VOTING 조기 종료가 아니다.

## 17차 대기실 원자성 설계 제안
역할 변경·피고 지정·명단 제거·재입장·수락·재판 시작을 사건 revision 기준으로 직렬화한다. 시작이 먼저 확정되면 역할 변경/명단 제거를 거절하며 자격을 수정하지 않는다. 변경/제거가 먼저면 시작 시 현재 명단 인원, 피고 유일성, 방장 권한과 게임 역할 분리와 현 피고의 수락을 다시 검사한다. 피고 없는 대기는 가능하나 시작 불가. 피고 교체·제거 시 이전 수락을 무효화하고 이전 피고의 지연된 수락 요청도 거절한다. 동일 사람이 다시 피고가 되어도 교체 전 수락을 자동 부활시키지 않는 설계를 제안한다.
제거는 영구 차단이나 자동 연결 끊김 처리와 다르다. 시작 전 재입장은 가능하나 역할 자리와 수락 조건을 다시 검증한다. 재입장과 시작 경합은 같은 순서 기준을 적용하며 시작 후에는 기존 자격 명단을 변경하지 않는다. 제거된 채 시작된 사람의 이후 조회 권한/이력은 별도 미정이며 기존 참가자와 같다고 추정하지 않는다.

## 18차 시작 조건·자격의 구분
재판 시작 시 접속 중인 서로 다른 참가자 최소 3명(방장·피고 포함, 두 역할 겸임 가능)과 현 피고의 최신 벌칙 수락을 검사하고 부족한 조건을 안내한다. 끊김 인원은 최소 인원에 세지 않는다. 벌칙 변경은 이전 수락을 무효화한다. 시작/연결 상태 변경/벌칙 수정 경합을 동일 서버 기준으로 처리하는 설계를 제안한다. 연결 감지 임계값은 아직 미정. 19차로 접속 3명 이상이어도 시작 시 끊긴 참가자는 동결 자격에서 제외하는 것으로 확정. 이후 복귀해도 명단에 추가하지 않는다.

## 19차 동결 알고리즘 경계
/start에서 서버의 최종 접속 판정으로 현재 명단 중 접속 중인 피고 외 자격자를 한 번 동결한다. 최소 인원은 접속 중인 서로 다른 참가자 3명(방장·피고 겸임 가능)이고 피고는 투표 집합에 포함하지 않는다. 시작 당시 끊긴 추가 참가자의 이후 복귀는 자격을 생성하지 않는다. 동결 후 끊김은 기존 자격을 제거하지 않는다. 따라서 위 끊김이 집합을 바꾸지 않는다는 설명은 동결 이후에 적용한다. presence는 실제 연결의 완벽한 즉시 증명이 아니며 감지 지연 가능성을 명시하고 시작/복귀 경합을 서버에서 일관되게 판정하는 설계를 제안한다.

## 20차 방 생명주기와 사건 생명주기 분리
방은 사건 A의 CLOSED 이후에도 참가 신원을 유지하고 사건 B를 준비할 수 있다. 사건 내부 상태 머신은 사건마다 별도로 실행한다. 이전 사건 CLOSED를 LOBBY로 되돌리는 것이 아니라 새 caseId의 LOBBY를 생성하는 설계를 제안한다.
방 흐름 후보: 참여 유지 → 사건 A 준비/진행/종료 → 사건 B 준비/진행/종료. 다음 사건 생성 권한·방장 관계·방 종료/만료 상태는 아직 확정하지 않는다. 이전 사건 표/수락/자격은 불변 기록으로 두고 다음 사건에 재사용하지 않는다.
다음 사건 생성 중복·동시 요청, 이전 사건 지연 명령, 현재 사건 포인터 변경은 서버에서 원자 처리하는 설계. 모든 명령에 caseId를 검증하여 A의 재시도/이벤트가 B를 바꾸지 않도록 한다. 방 접속 복구는 현재 방과 사건별 접수 상태를 구분하여 재동기화한다.

## 21차 최신 확정: 방 설정·접근·종료
- 흐름: 방 생성 → 방 안에서 게임 설정 → 플레이 → 같은 방에서 다음 게임 설정. 방 링크는 유지한다.
- 매 게임 설정은 방장만 한다. 방장이 시작하며 방장도 피고를 선택할 수 있고 참가자의 시작 전 본인 역할 선택/변경을 유지한다. 방장이 피고를 강제로 지정할 권한을 추가하지 않는다. 사건·피고·벌칙·시간을 게임별 설정으로 구성하는 UI 세부는 제안이며 시간 기본값 승계 등은 미정이다.
- 게임 1 종료 뒤 방에 들어온 사람은 게임 1 결과·이유를 볼 수 없고 게임 2에는 참여할 수 있다. 게임 1 참가자는 자기 기록에서 게임 1을 조회한다. 서버는 방 멤버십이 아닌 게임별 참여 권한을 검사한다. 24차: 진행 중 후발 참가자는 투표 불가·진행/최종 결과 조회·자기 이력 허용.
- 방장은 방을 종료할 수 있다. 종료 방에서는 신규 참가·신규 게임을 받지 않는다. 완료된 이전 게임은 해당 조회 자격자의 개인 기록에 남는다. 진행 중인 게임은 중단/판결 없음으로 처리한다. 24차: 방 종료 중단 이력은 중단·사건 내용만, 미완료 표·이유 비공개.
- 방장 복구는 같은 브라우저로 한다. 돌아올 수 없으면 새 방을 만든다. 이전 '새 사건' 안내를 방 모델에 맞춰 대체하며 MVP 이양은 추가하지 않는다. 자동 만료 시간은 미정이다.
- 기존 투표 조기 종료 금지는 정상 라운드 마감을 방장 임의로 당겨 판결하는 기능에 적용한다. 방 종료는 별도 명시적 예외로 진행 게임을 **중단·무판결** 처리하며 제출된 표로 승패를 계산하지 않는다.

### 방 종료 경합 설계 제안
Room OPEN → CLOSED는 방장만 실행한다. 방 종료와 신규 join/게임 생성/투표/정산을 원자 순서로 처리한다. 종료가 먼저면 진행 게임은 INTERRUPTED/NO_VERDICT로 정리하고 후속 명령을 거절한다. 이미 정상 완료가 먼저 확정된 게임은 기존 결과를 보존하는 일관된 순서를 제안한다. 정확한 동시 경계 계약은 구현 설계이며 종료 후 재개/새 게임 허용을 임의 추가하지 않는다. 타이머 작업이 중단 게임에 정상 판결을 덮어쓰지 않게 한다.

## 22차 나가기·복구·방장 이양 확정
- 명시적 나가기는 즉시 나감으로 처리한다. 연결이 끊긴 사람은 10분 안에 돌아오지 않으면 나간 것으로 처리한다. 10분 안 같은 브라우저로 복귀하면 기존 참가 신원을 복원한다. 연결 끊김을 즉시 나감으로 처리하지 않는다.
- 모두 나가면 방이 종료된다. 방장의 명시적 방 종료 기능도 유지한다. 투표 마감은 별도로 진행하며 연결 복구 유예 10분이 투표 시간을 연장하지 않는다. 동결 투표 자격과 접속/나감 상태를 혼동하지 않는다.
- 방장이 끊긴 뒤 10분 동안 돌아오지 않으면 남은 참가자 중 무작위로 방장을 넘긴다. 남은 참가자가 없으면 방을 종료한다. 기존 방장 이양 없음·방장 부재 시 새 방 필수는 이 규칙으로 대체한다.
- 미정: 무작위 후보가 접속 중인 사람만인지, 다른 끊김 유예자도 포함하는지; 피고도 무작위 방장 후보에 포함(확정); 진행 중 재판에서 새 방장 권한·게임 역할 처리; 방장 명시적 나가기의 이양 시점/동작. 무작위 정책을 이 항목들에 확대 적용하지 않는다.
- 10분 계시의 기술 기준(끊김 감지 시각/마지막 확인 시각), 재접속과 만료의 정확한 경계/서버 지연 보정은 구현 설계가 필요하다. 감지 자체가 완벽하게 즉시 이루어진다는 보장은 없다. 나감 판정 뒤 복귀 시 재입장/역할/기존 기록·자격 처리도 기존 확정 범위를 넘겨 추정하지 않는다.

22차 경합 설계 제안: 서버에서 참가 상태 CONNECTED/RECONNECT_GRACE/LEFT와 10분 만료 작업을 관리한다. 복귀/만료/명시적 나가기/전원 나감 종료/방장 이양을 원자 처리하고 작업 재시도로 중복 이양하지 않는다. 이미 종료된 방에서는 이양으로 재개하지 않는다. 한 번의 이양이 이전 사건의 게임 역할·표 작성자·판결 기록을 재작성하지 않게 식별자를 분리하는 설계이나, 진행 사건에서 새 방장 권한 범위는 미정이다.

## 23차 방장과 게임 역할 분리
방장은 방 관리·게임 설정·시작을 담당한다. 게임 생성 뒤 참가자들이 역할을 선택하며 방장도 피고가 될 수 있다. 원고라는 별도 게임 역할·작성자와 원고의 연결을 만들지 않는다. 방장 무작위 이양 후보에는 피고도 포함하고 피고라는 이유로 제외하지 않는다. 24차: 후보는 접속자만, 명시적 나가기 즉시 무작위 이양. 후보 없고 복귀 유예자가 있으면 대기.
권한은 두 축으로 검사한다: 방장 여부로 설정/시작/방 관리, 해당 게임 역할로 피고의 수락·변론 및 피고 외 자격자의 투표. 방장이 피고이면 피고 기능과 방장 기능을 모두 가지되 투표는 불가하다. 방장 이양만으로 게임 역할·동결 투표 자격·과거 표를 바꾸지 않는 설계로 분리한다. 참가자 최소 수는 서로 다른 사람 3명이며 방장·피고 겸임을 두 명으로 세지 않는다.

24차: HOST_VACANT_WAITING 상태 후보는 연결자 없이 복귀 유예자만 남을 때 방을 살려두고 복귀자 중 무작위 이양한다. 명시적 방장 leave와 10분 만료를 같은 이양 함수로 다루되 실행 시점은 구별. 피고 LEFT는 사건 중단, voter LEFT는 Electorate 불변. 재입장 새 참여 상태로 옛 자격 부활 금지. 방 종료 중단은 미완료 표로 판결하지 않음.

## 25차 결과 공개 최종 정정
첫 라운드 동률은 유죄·무죄·기권 수와 1차 익명 이유를 먼저 보여준 뒤 피고 선택 최후 변론, 2차 투표로 이어진다. 최종 결과는 1·2차 익명 이유 모두 표시하며 전원 기권 무판결에서도 작성된 기권 이유를 보여준다. 진행 중인 라운드의 미완료 표·이유는 비공개지만 이미 종료된 1차 공개 결과를 2차가 진행 중이라는 이유로 다시 숨기지 않는다. 신원·이름은 계속 숨기며 추론 방지 보장은 하지 않는다. 방 종료로 중단된 게임의 미완료 표/이유 비공개 정책은 유지한다.
