# 2단계: 모바일 화면·상태 흐름

> 24차 일괄 확정: [최신 예외 규칙](00-current-rules.md)이 아래 과거 미정/제안보다 우선한다. 1~11 승인 및 25차 이유 공개 확정. 첫 동률 집계+익명 이유 공개, 최종 양 라운드 이유·무판결 기권 이유 공개.

> 23차 사용자 정정(이전 역할 가정 대체): 방장은 방 관리·게임 설정·시작 권한이며 게임 역할과 독립이다. 게임을 만든 뒤 역할을 선택하고 방장도 피고가 될 수 있다. 피고는 무작위 방장 이양 후보에서도 제외하지 않는다. 작성자=원고/방장≠피고 가정은 폐기하며 원고 역할은 정의되지 않았다.

> 22차 우선 적용: 끊김 후 10분 미복귀는 나감, 전원 나가면 방 종료. 방장 10분 미복귀 시 남은 참가자 중 무작위 이양(없으면 종료). 이전 이양 없음/방장 부재 시 새 방 필수 규칙은 대체되었다. 이양 후보 접속 기준·자발적 방장 나가기 세부는 미정.

> 최신 도메인 기준(20차): 같은 방에서 사건을 순차 진행하며 기존 참가자는 재입장하지 않는다. 사건마다 피고·벌칙 수락·투표 자격을 새로 정한다. 아래 이전 차수의 사건 링크/참가자 모델은 사건 내부 정책의 이력이며, 방과 사건을 분리해 읽는다. 21차에서 방 링크 유지·방장만 게임 설정·사건별 기록 접근·방 종료가 추가 확정되었으며 이후 결정이 과거 미정 문구보다 우선한다. 세부 미정은 02-open-questions.md 참조.

상태: 개발 전 전체 초안 / UI와 기술 방식은 제안 · 2026-11-16

## 결론

모바일 웹에서 **방에서 사건 준비 → 링크 참여 → 피고 수락 → 방장 시작 → 선택 반론 → 투표 → 결과 → 같은 방의 다음 사건 준비**를 경험한다. 정상 화면뿐 아니라 제출 중·실패·끊김·복귀 화면까지 설계한다. 여기의 화면 이름·버튼·레이아웃은 구현된 UI가 아니다.

## 사용자와 역할

- 방장: 방 관리·게임 설정·시작 권한. 게임 생성 후 다른 참가자와 동일하게 게임 역할을 선택하며 피고도 가능. 원고 역할은 정의하지 않는다.
- 피고: 한 명. 벌칙 수락/거절, 선택 반론, 투표 불가.
- 참여자: 첫 투표 시작 뒤 신규 참여자는 투표 불가. 그 이전의 자격 고정 시점은 방장 재판 시작으로 확정.
- 동일 참가자의 재접속: 신규 입장과 다름. 시간 내 투표 가능하나 같은 기기·브라우저 링크 복귀 시 자동 복원. 다른 기기/브라우저와 데이터 삭제는 복구 보장 안 됨.
- 방장은 시작 전 끊김/이탈자를 대기 명단에서 제거할 수 있다. 영구 차단·타인 역할 강제 변경·중간 종료·개별 표 열람은 추가하지 않는다.

| M-01 사건 작성 | 닉네임, 사건 내용, 벌칙, 생성 버튼 | 필수값 오류, 생성 중 재클릭, 실패 재시도. 성공 후 같은 사건 링크 표시 | REQ-001~002 |
| M-02 사건 공유·대기 | 공유 링크, 사건·벌칙, 역할별 참가 현황, 최소 3명 안내 | 공유 취소, 링크 복사 실패, 아직 피고 없음, 끊김 표시 | REQ-003~006 |
| M-03 링크 입장 | 사건 요약, 닉네임, 피고/참여자 선택 | 만료/없는 링크, 닉네임 정책 미정, 피고 선점 충돌, 진행 중 사건의 투표 불가 안내 | REQ-003~005, 009 |
| M-04 벌칙 확인 | 피고에게 현재 벌칙 수락/거절, 나머지는 대기 | 거절 시 방장 수정·재제안, 이전 내용에 대한 늦은 수락 거부 제안 | REQ-007 |
| M-05 시작 준비 | 방장: 인원·피고 수락 확인, 시작 버튼. 투표 시간 기본 3분 설정 제안 | 조건 미충족 버튼 설명, 시작 중 재클릭, 다른 참가자는 기다림 | REQ-006, 008~010 |
| M-06 반론 | 피고 선택 반론. 제출 또는 건너뛰기 버튼 제안 | 빈 제출 처리, 저장 중 실패, 피고 끊김. 방장이 개시, 무응답도 진행 가능·피고 종료 안내 | REQ-011 |
| M-07 투표 | 사건·벌칙·반론, 유죄/무죄/기권, 이유 입력, 남은 시간, 제출 상태 | 필수 이유 오류, 재클릭, 접수 여부 불명, 마감과 제출 경합 | REQ-010, 012~017 |
| M-08 제출 완료·대기 | 자신의 접수 완료, 남은 시간, 다른 표·이유 숨김 | 재접속 시 서버 접수 상태 복원. 제출 후 변경·철회 불가(24차) | REQ-013, 018 |
| M-09 결과 | 유죄/무죄 또는 판결 없음, 집계와 이름 없는 표·이유 | 전원 완료/만료 자동 전환, 복귀 시 이미 종료됨, 확정 집계·동률·0표 규칙 적용 | REQ-014~017 |

결과에서 유죄일 때 사전 벌칙을 안내하고 무죄/무판결이면 벌칙 부과하지 않는 방향은 기존 목업 기반 **제안**이다. 최종 문구·수행 체크는 미정이다.

## 모바일 공통 동작 제안

- 세로 화면 우선. 키보드가 떠도 입력칸·오류·제출 버튼에 접근 가능하게 스크롤한다.
- 상태와 오류는 색상만으로 구분하지 않는다. 버튼·입력에 접근 가능한 이름을 제공한다.
- 제출 중 중복 클릭을 UI에서 억제하되 실제 중복 방지는 서버가 담당한다.
- 뒤로 가기·새로고침은 서버의 게임 상태를 되돌리지 않는다. 미제출 초안 보존 여부는 미정이다.
- 화면 잠금·백그라운드 복귀 시 현재 상태·마감·자신의 접수 결과를 재조회한다. 클라이언트 카운트다운만 믿지 않는다.
- 끊긴 화면에서 투표가 저장됐다고 표시하지 않는다. 확인 불가능하면 ‘접수 확인 중’, 복구 후 서버 상태로 정정한다.
- 참가자 끊김 표시가 실제 이탈 의사를 뜻하지 않음. 본인과 타인에게 표시하고 복귀 시 재동기화한다. 감지 임계값은 실측 후 정하며 백그라운드 오탐을 고려한다.

## 대표 시나리오

- SC-01: 5개 기기, 피고 수락, 방장 시작, 선택 반론, 투표, 자동 결과.
- SC-02: 3명으로 시작, 5명 초과 참여도 별도 검증. 인원 상한은 미정.
- SC-03: 피고 벌칙 거절 → 방장 수정 → 다시 수락 → 시작.
- SC-04: 투표 중 끊김 → 같은 참가자 복귀 → 남은 시간 내 제출.
- SC-05: 제출 응답 유실 → 복귀/재시도 → 한 표만 존재.
- SC-06: 만료에 미제출 기권. 직접 기권은 유죄/무죄 집계 제외. 전원 기권은 무판결 종료.
- SC-07: 시작 후 링크 입장 → 투표 불가. 기존 참가자 복귀는 자격 유지.
- SC-08: 결과에 이름이 없어도 소수 인원·표현으로 추론 가능함을 안내.

## 아직 고정하지 않는 것

인앱 브라우저 범위, 화면 폭·성능 수치, 입력 글자 수, 닉네임 중복 정책, 역할 충돌 안내 UX, 초안 저장, 제출 후 변경, 결과 보존/공유, 방장 이탈 시 새 사건 안내·세션 구현.

## 추가 확정 흐름: 동시 시작과 재투표

- M-06에서 방장은 ‘투표 시작’을 누른다. 서버의 한 시작 이벤트·마감을 반영하며 각 참가자가 들어온 시점부터 3분을 따로 재지 않는다. 방장이 개시하며 피고 작성/건너뛰기 후 또는 무응답으로 변론 없이 진행할 수 있다. 별도 타이머는 없다.
- M-07: 유죄/무죄는 이유 필수, 기권은 이유 선택. 기권 선택을 취소/뒤로 가기와 구분한다.
- M-10 1차 동률: 최종 무죄/벌칙 결과가 아니라 ‘최후 변론 후 재투표’ 표시. 1차 집계·익명 이유 공개(25차 정정)하며 신원만 숨긴다.
- M-11 최후 변론: 피고가 선택적으로 작성한다. 방장이 재투표를 시작한다. 작성/건너뛰기 뒤 방장 개시. 무응답이면 방장이 없이 진행하고 피고에게 변론 종료 안내. 별도 타이머 없음.
- M-12 재투표: 라운드 번호·새 접수 상태를 구분하는 제안. 같은 투표자와 원래 설정 기간으로 진행한다. 이전 선택/이유 자동 복사는 허용 결정이 없다. 새 라운드의 공통 개시 시점으로부터 원래 기간을 적용하는 설계다.
- 2차 동률은 무죄. 전원 기권/미제출로 유효표 0이면 무판결이며 재투표 동률과 다르다.

- SC-09: 방장 개시 → 모든 참가자 동일 마감 기준 → 지연 접속자는 남은 시간 표시.
- SC-10: 1차 유효 동률 → 최후 변론 → 재투표 → 2차 유효 동률 무죄. 같은 투표자·원래 기간 유지, 방장 재개, 1차 집계·익명 이유 공개(25차 정정)·최종 판결 뒤 이유 공개를 함께 검증.
- SC-11: 1차 제출 응답 유실/재시도 요청이 2차에 도착 → 다른 라운드 표로 접수되지 않음(설계 제안).
- SC-12: 방장 끊김·세션 유실·종료 후 링크·만료 링크. 같은 기기·브라우저 복원, 복구 불가 방장은 새 사건 안내. 세션 구현·만료 정책은 미정. 종료 링크는 기존 참가자만 결과·이유 조회.

## 참여·복원 확정 UX

- 입장에 로그인 없이 닉네임·역할을 사용한다. 같은 기기·브라우저에서 링크를 다시 열면 기존 참가자/방장, 투표 자격·접수 상태를 자동 복원한다.
- 이미 투표한 참가자에게 새 투표 입력을 열어 중복 제출하게 하지 않는다. 라운드별 표의 동일인 연결은 서버에서도 검증한다.
- 다른 기기/브라우저에서 같은 닉네임을 입력해도 기존 참가자나 방장으로 자동 복구하지 않는다. 닉네임 오인 UI를 피한다.
- 방장 복구 실패 시 MVP는 방장 이양 대신 새 사건 생성 안내. 기존 사건에 임의 새 방장 지정 금지. 기존 사건 강제 취소 여부까지 승인된 것은 아니다.
- 브라우저 데이터 삭제 시 자동 복원을 보장하지 않는다는 안내를 제공한다. 인앱 브라우저와 외부 브라우저는 다른 저장 공간일 수 있음을 실제 지원 환경에서 확인한다.

- SC-13: 동일 기기·브라우저 링크 재방문 → 기존 역할·표 복원 → 중복 투표 불가. 다른 브라우저/데이터 삭제로 기존 신원 복구는 보장 안 함.

## 확정된 지원·시간·연결 UX

현재 iPhone Safari·Android Chrome을 우선으로 검증하고 PC에서도 사용 가능하게 한다. 시험 당시 실제 OS/브라우저 버전을 기록하며 인앱 브라우저 지원을 자동 포함하지 않는다. 본인 연결 이상과 타인 끊김을 표시하고 복귀 시 서버 상태·마감·접수 결과를 다시 맞춘다. 마감은 서버 기준이고 늦은 제출은 명확한 실패 안내를 제공한다. 중국 본토에서의 접속/실시간 동기화는 배포 후 실제 네트워크 검증 전까지 미확인이다.

- SC-14: 기기 시간을 바꾸거나 느린 네트워크로 늦게 도착한 투표 → 서버 마감으로 거절 및 실패 안내. 본인/타인의 끊김 표시 후 복귀 상태 재동기화.

## 링크·개인 기록 추가

초대 링크 접근과 서버 기록 유지 가능, 브라우저에서 자신이 참여한 게임의 개인 기록을 보는 방향은 확정이다. M-13 개인 기록 목록/상세는 **화면 제안**이며 전체 결과·익명 이유 조회와 초기 자동 삭제 기한 없음은 확정이며 세부 목록 필드·정렬·추후 삭제 정책은 미정이다. 기록 식별은 기존 참가자 복구 정책과 정합되게 설계하되, 브라우저 데이터 삭제 뒤 이력 복구를 보장하지 않는다. 7일 자동 삭제·개인정보 입력 안내는 승인된 UX가 아니다. 텍스트 전용은 24차 확정.

- SC-15: 브라우저에서 자신이 참여한 게임 기록을 확인한다. 타인 이력 노출 방지, 목록/상세·완료 후 권한·보관 기간은 확정 후 구체화한다.

## 개인 기록 확정 상세

M-13은 자신이 참여한 게임의 **전체 결과와 익명 이유**를 볼 수 있게 한다. 브라우저별 기록이며 데이터 삭제/다른 기기 전환으로 이력을 잃을 수 있음을 안내한다. 서버에 기록이 남아도 브라우저 접근 자격이 없으면 개인 이력을 복구할 수 있다고 약속하지 않는다. 초기 서버 자동 삭제 기한은 없고 정책은 추후 결정한다. 완료 후 기존 참가자는 결과·이유, 비참가자는 종료 안내만 본다.

## 종료 후 링크·브라우저 이력 확정

진행 중 링크로 입장할 수 있으나 방장 재판 시작 뒤 신규 입장자는 반론 중이라도 해당 재판의 어느 라운드에도 투표하지 않는다. 종료된 링크는 기존 참가자에게 결과·이유를 보여주고 비참가자에게 ‘종료된 재판’ 안내만 제공한다. 종료 뒤 처음 들어온 사람을 참가자로 등록해 결과 권한을 부여하지 않는다. 개인 이력은 이 브라우저에서 참여한 게임만 보이며 데이터 유실/새 브라우저로 복구할 수 없다.

- SC-16: 진행 중 입장 → 첫 투표 뒤 자격 없음; 종료 후 기존 참가자 결과 조회 가능, 비참가자 종료 안내만. 새 브라우저·닉네임 일치로 결과/개인 이력 권한 취득 불가.

자격 고정 시점: 15차 Q-26 확정으로 방장 재판 시작에서 고정한다. 반론 중 신규 입장도 투표 불가이며 동일 명단 재투표를 유지한다.

14차 UX: 기권도 제출 완료로 표시하고 전원 완료 시 자동 결과/라운드 전환. 집계는 기권 제외 G>N 유죄/N>G 무죄, 유효 동률은 재투표 규칙, 전원 기권은 무판결. 미제출은 마감까지 기다리고 시간 만료에 기권 처리한다.

15차 최종 자격 UX: M-05 방장 재판 시작 순간 명단 고정. M-06 반론 중 신규 입장해도 투표 불가 안내. M-07 투표 시작 버튼은 고정 명단을 다시 생성하지 않는다. 같은 참가자의 복귀는 자격 유지. 늦은 참가자의 조회 정보는 기존 승인 범위만 적용한다.

## 16차 변론 화면 확정

M-06 일반 반론과 M-11 최후 변론: 피고에게 작성·건너뛰기 선택, 방장에게 투표 시작. 피고가 완료하면 방장이 시작하며, 무응답이면 방장은 변론 없이 진행할 수 있다. 이때 피고 화면에 변론 종료 안내를 표시하고 제출 UI를 닫는다. 연결이 끊긴 피고도 복귀 snapshot에서 종료 상태를 확인한다. 별도 변론 카운트다운은 없다. 늦은 제출은 저장 성공으로 표시하지 않는다(원자 경합 처리는 기술 설계).

- SC-17: 일반/최후 변론 각각 작성·건너뛰기·무응답의 3경로 → 방장 개시. 무응답 진행 때 피고 종료 안내, 별도 타이머 없음.

## 17차 대기실 흐름
M-02에서 참가자는 시작 전 역할을 변경한다. 방장에게도 피고 선택을 제공하고 이미 피고가 있으면 충돌을 안내한다. 피고 교체 후 이전 수락 완료 표시를 지우고 새 피고의 수락을 기다린다. 방장은 끊김/이탈자만 대기 명단에서 제거하며 영구 차단으로 표현하지 않는다. 제거된 사람은 시작 전 링크로 재입장 가능. 재판 시작 뒤 역할 변경·명단 제거 컨트롤은 잠그고 서버도 거절한다.
- SC-18: 대기실 역할 변경 → 피고 교체 → 벌칙 재수락 → 최소 인원/방장 권한 확인 후 시작 → 역할·투표자 고정.
- SC-19: 끊김/이탈자 방장 제거 → 시작 전 재입장 가능. 제거/재입장/재판 시작 경합은 확정된 서버 상태로 안내하며 시작 후 자격을 추가·축소하지 않음.

## 18차 시작 준비 화면
M-02에서 접속 중인 서로 다른 참가자 최소 3명(방장·피고 포함, 두 역할 겸임 가능), 현 벌칙 수락의 충족 여부를 보여주고 부족 조건을 안내한다. 끊김 인원은 최소 인원 표시에서 제외. 벌칙 수정 시 수락 완료 표시를 취소하고 재수락 요청.
- SC-20: 접속 2명+끊김 1명은 시작 불가 → 접속 중인 서로 다른 참가자 3명(방장·피고 겸임 가능) 충족 및 현 벌칙 수락 → 시작. 벌칙 수정 시 수락 무효화, 부족 조건 안내. 명단에 추가로 남은 끊김자는 19차 확정에 따라 투표 자격에서 제외되며 복귀해도 투표 불가.

## 19차 복귀 시 자격 안내
- SC-21: 방장·피고·다른 참가자 접속, 추가 참가자는 끊김 → 재판 시작 시 접속 중인 피고 외 자격자만 동결 → 추가 참가자 복귀 시 투표 불가 안내 및 기존 허용 관전 범위만 제공. 반대로 동결 자격자가 시작 뒤 끊겼다가 복귀하면 기존 자격 유지. 화면의 오래된 접속 표시보다 시작 시 서버 판정이 기준이다.

## 20차 같은 방의 다음 사건
결과 화면에서 기존 참가자는 같은 방에 머문다. 다음 사건 준비 시 다시 링크를 열거나 닉네임을 등록하지 않는다. 피고를 새로 선택하고 새 벌칙 수락·접속 최소 인원 확인·자격 동결을 반복한다. 다음 사건 만들기 버튼의 표시 주체는 작성 권한 결정 전 제안 UI로만 취급한다.
- M-14 같은 방의 다음 사건 대기/준비(제안): 현재 방과 사건을 구분, 이전 결과와 새 사건 입력을 섞지 않음. 누가 생성하는지·방 링크/사건 링크의 동작은 미정.
- SC-22: 사건 A 종료 → 같은 방에 참가자 유지 → 사건 B 준비 → 새 피고·벌칙 수락 → 시작 시 접속 중인 자격자 동결. 재입장 불필요.
- SC-23: A에서 투표 불가였거나 후발 입장한 사람이 B에서 자격 요건을 충족할 수 있는 흐름을 설계하되 B의 참여 등록 정책은 미정. A의 자격/표/수락을 복사하지 않음. 방 신규 입장으로 A 결과를 자동 공개하지 않음.
화면에서 현재 사건이 바뀌더라도 A 결과를 보고 있던 사람의 이동 강제 여부, 뒤로 가기·딥링크·다음 사건 알림 UX는 제안이며 추가 확정이 필요하다.

## 21차 최신 확정: 방 설정·접근·종료
- 흐름: 방 생성 → 방 안에서 게임 설정 → 플레이 → 같은 방에서 다음 게임 설정. 방 링크는 유지한다.
- 매 게임 설정은 방장만 한다. 방장이 시작하며 방장도 피고를 선택할 수 있고 참가자의 시작 전 본인 역할 선택/변경을 유지한다. 방장이 피고를 강제로 지정할 권한을 추가하지 않는다. 사건·피고·벌칙·시간을 게임별 설정으로 구성하는 UI 세부는 제안이며 시간 기본값 승계 등은 미정이다.
- 게임 1 종료 뒤 방에 들어온 사람은 게임 1 결과·이유를 볼 수 없고 게임 2에는 참여할 수 있다. 게임 1 참가자는 자기 기록에서 게임 1을 조회한다. 서버는 방 멤버십이 아닌 게임별 참여 권한을 검사한다. 24차: 진행 중 후발 참가자는 투표 불가·진행/최종 결과 조회·자기 이력 허용.
- 방장은 방을 종료할 수 있다. 종료 방에서는 신규 참가·신규 게임을 받지 않는다. 완료된 이전 게임은 해당 조회 자격자의 개인 기록에 남는다. 진행 중인 게임은 중단/판결 없음으로 처리한다. 24차: 방 종료 중단 이력은 중단·사건 내용만, 미완료 표·이유 비공개.
- 방장 복구는 같은 브라우저로 한다. 돌아올 수 없으면 새 방을 만든다. 이전 '새 사건' 안내를 방 모델에 맞춰 대체하며 MVP 이양은 추가하지 않는다. 자동 만료 시간은 미정이다.
- 기존 투표 조기 종료 금지는 정상 라운드 마감을 방장 임의로 당겨 판결하는 기능에 적용한다. 방 종료는 별도 명시적 예외로 진행 게임을 **중단·무판결** 처리하며 제출된 표로 승패를 계산하지 않는다.

- SC-24: 방 생성·링크 공유 → 방장 게임 설정 → 참가자 본인 역할 선택 → 플레이 → 같은 방 링크/참가 신원 유지 → 방장이 다음 게임 설정.
- SC-25: 게임 1 종료 후 신규 방 입장 → 게임 1 결과·이유 거절 → 게임 2 참여 가능. 기존 게임 1 참가자는 자기 기록 조회.
- SC-26: 방장 방 종료 → 신규 게임·참가 차단, 진행 게임 중단·무판결, 기존 완료 게임 기록 유지. 같은 브라우저 방장 복구 및 복구 불가 새 방 안내.

## 22차 나가기·복구·방장 이양 확정
- 명시적 나가기는 즉시 나감으로 처리한다. 연결이 끊긴 사람은 10분 안에 돌아오지 않으면 나간 것으로 처리한다. 10분 안 같은 브라우저로 복귀하면 기존 참가 신원을 복원한다. 연결 끊김을 즉시 나감으로 처리하지 않는다.
- 모두 나가면 방이 종료된다. 방장의 명시적 방 종료 기능도 유지한다. 투표 마감은 별도로 진행하며 연결 복구 유예 10분이 투표 시간을 연장하지 않는다. 동결 투표 자격과 접속/나감 상태를 혼동하지 않는다.
- 방장이 끊긴 뒤 10분 동안 돌아오지 않으면 남은 참가자 중 무작위로 방장을 넘긴다. 남은 참가자가 없으면 방을 종료한다. 기존 방장 이양 없음·방장 부재 시 새 방 필수는 이 규칙으로 대체한다.
- 미정: 무작위 후보가 접속 중인 사람만인지, 다른 끊김 유예자도 포함하는지; 피고도 무작위 방장 후보에 포함(확정); 진행 중 재판에서 새 방장 권한·게임 역할 처리; 방장 명시적 나가기의 이양 시점/동작. 무작위 정책을 이 항목들에 확대 적용하지 않는다.
- 10분 계시의 기술 기준(끊김 감지 시각/마지막 확인 시각), 재접속과 만료의 정확한 경계/서버 지연 보정은 구현 설계가 필요하다. 감지 자체가 완벽하게 즉시 이루어진다는 보장은 없다. 나감 판정 뒤 복귀 시 재입장/역할/기존 기록·자격 처리도 기존 확정 범위를 넘겨 추정하지 않는다.

- SC-27: 참가자 연결 끊김 → 10분 내 복귀하면 기존 신원 복원; 미복귀면 나감. 명시적 나가기는 즉시. 전원 나감 시 방 종료, 투표는 원래 마감 유지.
- SC-28: 방장 끊김 → 10분 미복귀 → 남은 참가자 중 무작위 이양 또는 아무도 없으면 종료. 후보 접속 기준/진행 권한은 미정 테스트로 남김.

## 23차 방장과 게임 역할 분리
방장은 방 관리·게임 설정·시작을 담당한다. 게임 생성 뒤 참가자들이 역할을 선택하며 방장도 피고가 될 수 있다. 원고라는 별도 게임 역할·작성자와 원고의 연결을 만들지 않는다. 방장 무작위 이양 후보에는 피고도 포함하고 피고라는 이유로 제외하지 않는다. 24차: 후보는 접속자만, 명시적 나가기 즉시 무작위 이양. 후보 없고 복귀 유예자가 있으면 대기.
권한은 두 축으로 검사한다: 방장 여부로 설정/시작/방 관리, 해당 게임 역할로 피고의 수락·변론 및 피고 외 자격자의 투표. 방장이 피고이면 피고 기능과 방장 기능을 모두 가지되 투표는 불가하다. 방장 이양만으로 게임 역할·동결 투표 자격·과거 표를 바꾸지 않는 설계로 분리한다. 참가자 최소 수는 서로 다른 사람 3명이며 방장·피고 겸임을 두 명으로 세지 않는다.

- SC-29: 방장 게임 생성 → 방장도 피고 역할 선택 → 피고 수락/변론 및 방장 시작 UI 공존, 투표 불가. 방장 이양 무작위 후보에 피고 포함, 역할 강제 변경 없음.

## 24차 추가 흐름
- SC-30: 방장 명시적 나감 즉시 연결자 랜덤 이양, 연결자 0+복귀 유예자 존재는 대기 후 복귀자 중 지정. 모두 나감이면 종료.
- SC-31: 진행 중 입장·10분 퇴장 뒤 재입장 → 투표 불가, 진행/최종 결과 관전·개인 이력. 종료 뒤 입장자는 과거 결과 차단.
- SC-32: 표/이유 제출 → 수정·철회 불가, 응답 유실이면 기존 접수 확인.
- SC-33: 피고 나감은 중단, 투표자 나감은 수 유지·마감 미제출 기권. 방 종료 중단은 이력에 중단/사건만, 미완료 표·이유 비공개.
- SC-34: 텍스트만 작성·닉네임 중복 오류·길이 안내, 시간 1~10분/1분 단위·새 게임 3분, 벌칙은 안내만.
- SC-35: 방장 설정 중 끊김/나감 → 방 존속 → 저장된 설정을 새 방장이 이어서 작성. 저장 중·실패 상태 표시 설계 필요.

## 25차 결과 공개 최종 정정
첫 라운드 동률은 유죄·무죄·기권 수와 1차 익명 이유를 먼저 보여준 뒤 피고 선택 최후 변론, 2차 투표로 이어진다. 최종 결과는 1·2차 익명 이유 모두 표시하며 전원 기권 무판결에서도 작성된 기권 이유를 보여준다. 진행 중인 라운드의 미완료 표·이유는 비공개지만 이미 종료된 1차 공개 결과를 2차가 진행 중이라는 이유로 다시 숨기지 않는다. 신원·이름은 계속 숨기며 추론 방지 보장은 하지 않는다. 방 종료로 중단된 게임의 미완료 표/이유 비공개 정책은 유지한다.

- SC-36: 1차 동률 집계+익명 이유 확인 → 최후 변론 → 2차 투표 → 최종 1·2차 이유 모두. 전원 기권 분기에서도 직접 작성 이유 표시. M-10 중간 결과와 M-11 최후 변론 사이 공개 패널을 명시하는 UI 설계.
