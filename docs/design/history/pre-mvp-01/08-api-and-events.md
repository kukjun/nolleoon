# 4단계 D: API·이벤트 계약 제안

> 24차 일괄 확정: [최신 예외 규칙](00-current-rules.md)이 아래 과거 미정/제안보다 우선한다. 1~11 승인 및 25차 이유 공개 확정. 첫 동률 집계+익명 이유 공개, 최종 양 라운드 이유·무판결 기권 이유 공개.

> 23차 사용자 정정(이전 역할 가정 대체): 방장은 방 관리·게임 설정·시작 권한이며 게임 역할과 독립이다. 게임을 만든 뒤 역할을 선택하고 방장도 피고가 될 수 있다. 피고는 무작위 방장 이양 후보에서도 제외하지 않는다. 작성자=원고/방장≠피고 가정은 폐기하며 원고 역할은 정의되지 않았다.

> 22차 우선 적용: 끊김 후 10분 미복귀는 나감, 전원 나가면 방 종료. 방장 10분 미복귀 시 남은 참가자 중 무작위 이양(없으면 종료). 이전 이양 없음/방장 부재 시 새 방 필수 규칙은 대체되었다. 이양 후보 접속 기준·자발적 방장 나가기 세부는 미정.

> 최신 도메인 기준(20차): 같은 방에서 사건을 순차 진행하며 기존 참가자는 재입장하지 않는다. 사건마다 피고·벌칙 수락·투표 자격을 새로 정한다. 아래 이전 차수의 사건 링크/참가자 모델은 사건 내부 정책의 이력이며, 방과 사건을 분리해 읽는다. 21차에서 방 링크 유지·방장만 게임 설정·사건별 기록 접근·방 종료가 추가 확정되었으며 이후 결정이 과거 미정 문구보다 우선한다. 세부 미정은 02-open-questions.md 참조.

상태: 경로·필드·통신 방식 제안 / 구현 명세 확정 전 · 2026-11-16

## 명령과 조회

방장 조기 종료 API는 만들지 않는다. 비공개 표 조회 API를 방장에게 자동 부여하지 않는다. 시작 전 본인 역할 변경·대기 명단 제거는 아래 17차 계약으로 제안하며 사건 취소 API는 미정이다. 방장 이양 API는 MVP에서 만들지 않는다. 복원은 아래 확정 정책에 맞춰 설계한다.

## 응답·실패 규약 제안

성공 응답: 변경된 revision, phase, self 상태, 필요 시 snapshot. 오류: code, 사용자용 message, retryable, requestId. HTTP 상태는 400 입력, 401 세션 없음, 403 권한 없음, 404 미존재/접근 불가, 409 충돌, 410 만료 후보. 실제 노출 정책에 맞춰 확정한다.

예시 오류 코드: DEFENDANT_TAKEN, CONSENT_STALE, NOT_READY, NOT_ELIGIBLE, DEADLINE_PASSED, ALREADY_SUBMITTED, VERSION_CONFLICT. 같은 requestKey 재전송은 기존 결과를 반환하는 방향이며, 다른 payload로 같은 키 재사용 시 충돌 처리한다.

## 공개 snapshot과 이벤트

진행 중 snapshot은 사건·벌칙·상태·본인 접수 상태만 제공한다. 타인 표·이유는 보내지 않는다. 제출자별 완료 표시나 전체 완료 개수 노출은 익명 추론 영향이 있어 별도 선택한다.

폴링이면 snapshot revision으로 변경 여부 확인. SSE를 선택하면 다음 **후보 이벤트**를 사용한다: case.updated, participant.changed, consent.changed, phase.changed, presence.changed, result.ready. 이벤트에 투표 내용·이유를 실어 방송하지 않는다. 공개 vote.submitted 이벤트도 신원/시점 추론 위험 때문에 자동 채택하지 않는다.

끊김·이벤트 누락 후에는 마지막 이벤트를 맹신하지 않고 snapshot을 다시 읽는다. 결과 정산은 서버에서 한 번만 확정한다. 마감 경계 요청과 조회 정산의 순서는 상태 설계에서 명확히 정한 뒤 구현한다.

## 동시 개시·라운드 계약 추가 제안

- POST /cases/{id}/rounds/1/open: 방장 전용. expectedRevision/requestKey, 공통 openedAt/deadline 반환. 클라이언트가 마감을 생성하지 않음.
- POST /cases/{id}/final-defense: 피고 선택 작성. 작성/건너뛰기 가능, 방장 개시로 종료. 무응답 진행 허용·피고 안내, 별도 타이머 없음.
- POST /cases/{id}/rounds/2/open: 방장 개시. 같은 투표자와 원래 설정 기간을 서버에서 적용. 180초로 무조건 초기화하거나 새 참가자를 추가하지 않음.
- snapshot에 phase와 roundNo를 포함하고 투표 요청은 라운드 검증. 1차 재시도가 2차를 오염시키면 안 됨.
- round.closed는 1차 동률의 중간 집계와 사건 최종 result.ready를 구별한다. 1차 동률 뒤에는 집계와 1차 익명 이유를 공개. 최종 결과는 두 라운드 익명 이유 모두, 전원 기권 무판결은 작성된 기권 이유 공개.

## 링크 복귀 API 제안
GET snapshot은 유효한 기존 참가자 세션이 있으면 기존 역할·라운드 접수 상태를 반환한다. join을 다시 호출해도 동일 세션을 신규 참가자로 만들지 않는 계약을 제안한다. 세션 없이 닉네임만 제시한 복구/방장 승격 요청은 허용하지 않는다. 쿠키 소실·다른 브라우저는 복구 불가 안내, 방장 미복귀는 새 사건 안내. 브라우저 데이터 삭제를 감지할 수 있다고 주장하지 않고 인증 상태 부재로 처리한다.

서버 마감 이후 votes 요청은 DEADLINE_PASSED 등 명시적 실패를 반환하고 UI가 실패를 안내하도록 한다. 연결 이상은 본인·타인 표시 정책을 따르며 복귀 snapshot으로 재동기화한다. 감지 임계값은 실측 전 하드 SLA로 노출하지 않는다. 동일 참가자·라운드의 재시도는 중복표를 만들지 않는다.

## 개인 기록 API 후보
GET /self/history 및 사건 상세 조회는 브라우저에서 자신이 참여한 게임의 기록을 보는 요구에 대한 **계약 제안**이다. 브라우저 자격 증명/서버 연결 방식은 미선택이며 닉네임 검색으로 개인 이력을 제공하지 않는다. 전체 결과·익명 이유 및 완료 후 참가자 제한은 확정. 세부 목록 필드·페이지네이션·향후 삭제 계약은 미정이며 초기 자동 삭제 기한은 없다. 초대 링크 접근 동의가 모든 완료 기록 공개를 의미하지 않는다.

12차 계약 경계: self/history의 허용 참가자는 자신의 참여 게임 전체 결과·익명 이유 조회 가능. 브라우저 자격을 잃었거나 새 기기에서 닉네임만 같은 요청으로 이력을 복구하지 않는다. 서버 자동 삭제 기한은 초기 미설정. 완료된 사건의 초대 링크만 보유한 비참가자는 종료 안내만 받으며 개인 이력 API 권한을 확대 적용하지 않는다.

13차 API 권한 확정: 진행 중 join은 가능하나 첫 투표 후이면 해당 재판 모든 라운드 투표 자격 없음. CLOSED에서는 새 join으로 참가 이력을 만들지 않는다. 기존 참가자의 result는 허용하고 비참가자에게는 종료 상태만 반환한다. result/private history 권한은 초대 링크·닉네임만으로 충족되지 않는다. join과 방장 재판 시작의 경합은 원자 판정한다.

14차: 직접 기권 POST도 제출 완료로 응답하고 전원 완료 집계에 포함한다. 미제출은 마감 전 완료로 세지 않는다. 집계 결과는 기권 제외 더 많은 쪽, 동률 재투표/2차 무죄, 0유효표 무판결 규칙을 따른다.

15차 /start 계약: 방장 재판 시작이 자격 명단 동결 트랜잭션이다. 이후 join은 반론 단계라도 자격 없음. /rounds/1/open 및 /rounds/2/open은 동결 명단만 참조하고 추가 참가자를 편입하지 않는다. 진행 중/종료 후 조회는 기존 범위만 적용한다.

16차 방장 open 계약은 피고 무응답이어도 허용하며 일반/최후 변론을 닫고 단계 변경·피고 종료 안내를 반환/전파한다. 피고 defense submit/skip은 변론 단계에서만 수락하는 설계. 방장 open이 먼저 확정되면 늦은 변론 제출은 DEFENSE_CLOSED 등 실패, UI에 종료 안내. 별도 변론 타이머 API 없음.

## 17차 대기실 API 후보
- PATCH /cases/{id}/self/role: requestedRole, expectedRevision. 시작 전 본인만, 피고 유일성·방장 권한과 게임 역할 분리 검사. 피고 교체 시 수락 무효화.
- POST /cases/{id}/participants/{participantId}/remove-from-lobby: 방장만, 시작 전 끊김/이탈 대상만. 영구 차단 레코드를 생성하지 않음. 대상 상태·시작 경합을 원자 검사.
- join은 제거된 참가자의 시작 전 재입장을 허용하되 닉네임이 아닌 기존 브라우저 신원으로 중복 명단을 방지. 역할 재선택/복원 UX는 미정.
- consent에 현 피고의 식별자와 역할 배정 버전까지 검증하는 설계. /start는 최신 명단·현 피고 수락을 재검증하여 자격 동결.
- 오류 후보: ROLE_LOCKED, NOT_REMOVABLE, CONSENT_STALE. 이벤트는 명단·역할·수락 상태를 재조회하게 하며 타인 표 공개와 무관하다.

18차 /start: 서버 접속 판정으로 방장·피고·다른 참가자 최소 3명 및 현재 벌칙 수락을 재검사. 실패 시 missingConditions 등의 구조로 부족 조건 반환을 제안한다. punishment 변경 시 수락 무효화 확정. 19차 확정으로 /start의 서버 최종 접속 판정에서 접속 중인 피고 외 자격자만 동결한다. 이후 복귀로 편입하지 않는다.

19차 snapshot 복귀 응답은 self의 실제 동결 자격을 반환한다. /start 당시 끊김으로 제외된 참가자가 복귀하면 NOT_ELIGIBLE이며 기존 조회 권한만 적용한다. 이미 동결 자격이 있는 참가자의 복구는 기존대로 허용. 서버 시작 최종 검사에 연결 상태를 사용하며 stale presence/경합 정책과 감지 지연을 기술 설계에서 명시한다.

## 20차 방/연속 사건 API 재구성 제안
기존 /cases 계약은 사건 내부 명령으로 유지하되 생성/참여/복구의 단일 사건 가정을 개편한다. 경로·모델은 구현 제안이다.
- POST /rooms 및 POST /rooms/{roomId}/join: 방 생성/참여 후보. 생성 플로와 공통 초대 링크 정책은 미정.
- GET /rooms/{roomId}/snapshot: 방 참가 상태·현재 사건 식별자와 허용된 상태. 방 멤버에게 과거 결과 전체를 기본 포함하지 않음.
- POST /rooms/{roomId}/cases: 다음 사건 생성 후보. 호출 권한은 미정이므로 누구나/이전 방장으로 임의 확정하지 않음. 중복 생성·순차 진행 검사 제안.
- 기존 /cases/{caseId}/start, consent, defense, votes, result는 해당 사건 신원·역할·참여·자격 검사. 방 접속만으로 사건 결과 권한 충족하지 않음.
- 기존 /cases/{id}/join은 방 join과 사건별 참여 등록을 혼합한 초안이다. 사건 참여 등록 시점/종료 접근이 정해지기 전 그대로 구현하지 않는다. 종료 사건 신규 참여 금지를 방 전체 신규 입장 금지로 확대하지 않는다.
- room.current_case.changed 등 후보 이벤트는 roomId/caseId/revision을 포함. 이전 사건 지연 요청/중복 키가 다음 사건에 적용되지 않음.
- /self/history는 사건별 참여 근거로 반환. 방 전체 과거 기록 공개·새 참가자 소급 조회는 확정된 요구가 아니다.

## 21차 최신 확정: 방 설정·접근·종료
- 흐름: 방 생성 → 방 안에서 게임 설정 → 플레이 → 같은 방에서 다음 게임 설정. 방 링크는 유지한다.
- 매 게임 설정은 방장만 한다. 방장이 시작하며 방장도 피고를 선택할 수 있고 참가자의 시작 전 본인 역할 선택/변경을 유지한다. 방장이 피고를 강제로 지정할 권한을 추가하지 않는다. 사건·피고·벌칙·시간을 게임별 설정으로 구성하는 UI 세부는 제안이며 시간 기본값 승계 등은 미정이다.
- 게임 1 종료 뒤 방에 들어온 사람은 게임 1 결과·이유를 볼 수 없고 게임 2에는 참여할 수 있다. 게임 1 참가자는 자기 기록에서 게임 1을 조회한다. 서버는 방 멤버십이 아닌 게임별 참여 권한을 검사한다. 24차: 진행 중 후발 참가자는 투표 불가·진행/최종 결과 조회·자기 이력 허용.
- 방장은 방을 종료할 수 있다. 종료 방에서는 신규 참가·신규 게임을 받지 않는다. 완료된 이전 게임은 해당 조회 자격자의 개인 기록에 남는다. 진행 중인 게임은 중단/판결 없음으로 처리한다. 24차: 방 종료 중단 이력은 중단·사건 내용만, 미완료 표·이유 비공개.
- 방장 복구는 같은 브라우저로 한다. 돌아올 수 없으면 새 방을 만든다. 이전 '새 사건' 안내를 방 모델에 맞춰 대체하며 MVP 이양은 추가하지 않는다. 자동 만료 시간은 미정이다.
- 기존 투표 조기 종료 금지는 정상 라운드 마감을 방장 임의로 당겨 판결하는 기능에 적용한다. 방 종료는 별도 명시적 예외로 진행 게임을 **중단·무판결** 처리하며 제출된 표로 승패를 계산하지 않는다.

21차 API 후보 보완: POST /rooms/{roomId}/cases는 방장만, POST /rooms/{roomId}/close도 방장만. close 뒤 join/create를 거절하고 이전 완료 게임의 result/history는 게임별 권한을 계속 검사한다. room.closed와 case.interrupted 이벤트는 연결된 화면에 중단·무판결을 전달하며 중단 게임 이유를 자동 노출하지 않는다. 방 복구는 기존 브라우저 증명으로 수행한다. 일반 참가자 게임 설정·종료 요청은 서버에서 거절한다.

## 22차 나가기·복구·방장 이양 확정
- 명시적 나가기는 즉시 나감으로 처리한다. 연결이 끊긴 사람은 10분 안에 돌아오지 않으면 나간 것으로 처리한다. 10분 안 같은 브라우저로 복귀하면 기존 참가 신원을 복원한다. 연결 끊김을 즉시 나감으로 처리하지 않는다.
- 모두 나가면 방이 종료된다. 방장의 명시적 방 종료 기능도 유지한다. 투표 마감은 별도로 진행하며 연결 복구 유예 10분이 투표 시간을 연장하지 않는다. 동결 투표 자격과 접속/나감 상태를 혼동하지 않는다.
- 방장이 끊긴 뒤 10분 동안 돌아오지 않으면 남은 참가자 중 무작위로 방장을 넘긴다. 남은 참가자가 없으면 방을 종료한다. 기존 방장 이양 없음·방장 부재 시 새 방 필수는 이 규칙으로 대체한다.
- 미정: 무작위 후보가 접속 중인 사람만인지, 다른 끊김 유예자도 포함하는지; 피고도 무작위 방장 후보에 포함(확정); 진행 중 재판에서 새 방장 권한·게임 역할 처리; 방장 명시적 나가기의 이양 시점/동작. 무작위 정책을 이 항목들에 확대 적용하지 않는다.
- 10분 계시의 기술 기준(끊김 감지 시각/마지막 확인 시각), 재접속과 만료의 정확한 경계/서버 지연 보정은 구현 설계가 필요하다. 감지 자체가 완벽하게 즉시 이루어진다는 보장은 없다. 나감 판정 뒤 복귀 시 재입장/역할/기존 기록·자격 처리도 기존 확정 범위를 넘겨 추정하지 않는다.

22차 API 후보: POST /rooms/{id}/leave는 본인의 명시적 나가기, 서버 유예 만료 작업은 10분 미복귀 나감·전원 종료·방장 이양을 처리한다. room.host.changed/participant.left/room.closed 이벤트와 snapshot으로 상태 복구. 일반 참가자가 임의 지정 이양할 API를 추가하지 않는다. 서버는 최신 방장 권한을 검사하되 진행 사건 권한·피고도 방장 가능하며 후보의 접속 기준은 정책 확정 필요. 이전 방장 세션 복원만으로 이양된 권한을 되돌리지 않는 방향은 설계 제안이며 재입장 세부 미정이다.

## 23차 방장과 게임 역할 분리
방장은 방 관리·게임 설정·시작을 담당한다. 게임 생성 뒤 참가자들이 역할을 선택하며 방장도 피고가 될 수 있다. 원고라는 별도 게임 역할·작성자와 원고의 연결을 만들지 않는다. 방장 무작위 이양 후보에는 피고도 포함하고 피고라는 이유로 제외하지 않는다. 24차: 후보는 접속자만, 명시적 나가기 즉시 무작위 이양. 후보 없고 복귀 유예자가 있으면 대기.
권한은 두 축으로 검사한다: 방장 여부로 설정/시작/방 관리, 해당 게임 역할로 피고의 수락·변론 및 피고 외 자격자의 투표. 방장이 피고이면 피고 기능과 방장 기능을 모두 가지되 투표는 불가하다. 방장 이양만으로 게임 역할·동결 투표 자격·과거 표를 바꾸지 않는 설계로 분리한다. 참가자 최소 수는 서로 다른 사람 3명이며 방장·피고 겸임을 두 명으로 세지 않는다.

23차 계약: self/role에서 방장이라는 이유로 피고 선택을 거절하지 않는다. /start는 방장 권한, consent/defense는 피고 역할, votes는 해당 사건 동결 자격과 피고 제외로 각각 검사한다. 방장도 피고면 votes 거절. 이양 후보 조회/선정에서 피고 제외 필터 금지.

24차: votes 수정/삭제 API 제공하지 않고 우회 변경 거절. 진행 중 join은 해당 게임 view/history 접근, vote는 불가. room close에 의한 interrupted result/history는 중단/사건 내용만 반환. /rooms/{id}/draft GET/PATCH 후보는 현재 방장 권한·revision으로 저장/승계. 빈 후보면 10분 유예자 복귀까지 이양 대기. 대기/초안 이벤트에 표·이유를 섞지 않음.

## 25차 결과 공개 최종 정정
첫 라운드 동률은 유죄·무죄·기권 수와 1차 익명 이유를 먼저 보여준 뒤 피고 선택 최후 변론, 2차 투표로 이어진다. 최종 결과는 1·2차 익명 이유 모두 표시하며 전원 기권 무판결에서도 작성된 기권 이유를 보여준다. 진행 중인 라운드의 미완료 표·이유는 비공개지만 이미 종료된 1차 공개 결과를 2차가 진행 중이라는 이유로 다시 숨기지 않는다. 신원·이름은 계속 숨기며 추론 방지 보장은 하지 않는다. 방 종료로 중단된 게임의 미완료 표/이유 비공개 정책은 유지한다.

25차 공개 projection: 1차 종료 동률 응답/snapshot에 counts와 anonymizedReasons를 반환하고 final-defense/round2에서도 종료 라운드 공개 결과 조회 허용. 진행 중 2차 이유는 제외. 최종 result는 라운드별 익명 이유 배열, 무판결은 작성된 기권 이유 배열을 제공하는 계약 제안. 참가자 ID/작성 순서·정밀 시각 등 식별 메타데이터는 공개 모델에서 제외 검토.
