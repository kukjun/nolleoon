# 제품 설계 문서

> 24차 일괄 확정: [최신 예외 규칙](00-current-rules.md)이 아래 과거 미정/제안보다 우선한다. 1~11 승인 및 25차 이유 공개 확정. 첫 동률 집계+익명 이유 공개, 최종 양 라운드 이유·무판결 기권 이유 공개.

> 23차 사용자 정정(이전 역할 가정 대체): 방장은 방 관리·게임 설정·시작 권한이며 게임 역할과 독립이다. 게임을 만든 뒤 역할을 선택하고 방장도 피고가 될 수 있다. 피고는 무작위 방장 이양 후보에서도 제외하지 않는다. 작성자=원고/방장≠피고 가정은 폐기하며 원고 역할은 정의되지 않았다.

> 22차 우선 적용: 끊김 후 10분 미복귀는 나감, 전원 나가면 방 종료. 방장 10분 미복귀 시 남은 참가자 중 무작위 이양(없으면 종료). 이전 이양 없음/방장 부재 시 새 방 필수 규칙은 대체되었다. 이양 후보 접속 기준·자발적 방장 나가기 세부는 미정.

> 최신 도메인 기준(20차): 같은 방에서 사건을 순차 진행하며 기존 참가자는 재입장하지 않는다. 사건마다 피고·벌칙 수락·투표 자격을 새로 정한다. 아래 이전 차수의 사건 링크/참가자 모델은 사건 내부 정책의 이력이며, 방과 사건을 분리해 읽는다. 21차에서 방 링크 유지·방장만 게임 설정·사건별 기록 접근·방 종료가 추가 확정되었으며 이후 결정이 과거 미정 문구보다 우선한다. 세부 미정은 02-open-questions.md 참조.

상태: **1단계 결정 25차 반영 + 2~5단계 전체 초안 / 구현 전 리뷰** · 2026-11-16

## 결론

모바일에서 친구들이 사건 링크로 참여해 재판 게임을 즐기는 제품이다. 확정 정책을 바탕으로 모바일 경험·요구사항·상태·기술·검증 초안을 연결했다. **문서의 제안은 사용자 결정이 아니며 앱 구현이나 검증 완료도 아니다.**

## 확정·제안·미결정의 의미

- **확정**: 사용자 발언으로 확인. 넓은 동의로 세부 숫자·권한까지 확정하지 않는다.
- **제안**: 구현을 구체화하기 위한 추천. 검토 전 기본값으로 확정하지 않는다.
- **미결정**: 제품 정책 또는 설계 검토가 필요하다.
- **목업 구현**: 시연 동작. 승인된 요구나 제품 구현 완료와 다르다.
- **AC/시험**: 개발 후 확인할 기준. 통과 기록은 별도 실행 증거가 필요하다.

현재 가장 중요한 미결정은 최종 이유 공개 세부, 확정 복원 정책의 세션 구현과 링크 접근, 기술·보관 정책이다. 이미 확정된 선택 반론·전원기권 무판결·첫 동률 재투표/두 번째 무죄·기권 이유 선택·방장 투표 개시를 다시 미정으로 되돌리지 않는다.

## 관리 원칙

결정은 날짜·선택·이유·영향을 기록한다. 이유를 사용자가 밝히지 않았다면 지어내지 않는다. 중대한 기술 선택은 기존 `../decisions/`에 ADR로 남기며 채택 전에는 별도 확정 ADR을 만들지 않는다.

개발 기준은 저장소 문서, [기획·목업 Site](https://trip-court-product.lxx3380.chatgpt.site)는 검토용이다. Site v2는 이번 문서 결정 전체와 동기화된 상태가 아니다. 이번 작업은 로컬 문서만 변경하며 Site·앱·하네스·GitHub·배포 변경은 하지 않았다. Site 본문 재조회는 네트워크 제한으로 불가했던 범위를 명시한다.

기존 [하네스 v0](../harness.md)는 유지한다. 제품 테스트 `not-configured` 상태를 문서 작성으로 통과로 바꾸지 않는다. 공개 예시에는 가상 데이터만 사용한다.

개인 참여 기록(브라우저 조회·서버 저장 가능) 방향을 반영했다. 개인 이력의 전체 결과·익명 이유 조회, 초기 자동 삭제 기한 없음·삭제 정책 추후 결정, 브라우저별 이력 유실 가능은 확정이다. 완료 후 기존 참가자만 결과·이유/비참가자는 종료 안내가 확정이며 기술 식별은 설계이며 텍스트 전용 제한은 확정하지 않았다.

정정 이력: 13차의 첫 투표 고정 단정은 철회했고, 15차 사용자 결정으로 방장 재판 시작 고정을 확정했다. 다른 정책은 유지한다.

Q-26은 15차에 해결: 방장이 재판 시작할 때 명단 고정, 반론 중 신규 입장도 투표 불가. 이전 확인 대기 기록은 이 결정으로 대체한다.

16차로 일반/최후 변론 작성/건너뛰기·무응답 진행·방장 개시·피고 종료 안내·별도 타이머 없음이 확정됐다. 이전 변론 대기 질문은 해결되었다.

17차: 시작 전 역할 변경, 대기 명단 정리·재입장, 피고 교체 시 벌칙 재수락, 방장 권한과 게임 역할 분리 확정. 시작 후 역할·자격 고정.

18차: 접속 중인 서로 다른 참가자 최소 3명(방장·피고 포함, 두 역할 겸임 가능), 현 벌칙 수락, 부족 조건 표시, 벌칙 수정 후 재수락 확정. 19차로 시작 시 끊김 참가자는 동결 자격에서 제외로 확정.

19차: 재판 시작 시 접속 중인 자격자만 투표 명단 동결. 시작 시 끊긴 추가 참가자는 복귀해도 투표 불가. 서버 최종 검사와 presence 지연 한계 명시.

20차 주요 변경: 사건 하나로 끝나는 참여 모델에서 같은 방의 순차 사건 모델로 확장. 재입장 없이 참가 유지, 사건별 피고·벌칙 수락·자격 재결정. 다음 작성자·방장·링크·사건 참여/기록 접근·방 수명은 결정 대기.

21차: 방 생성→게임 설정→플레이→다음 설정. 방 링크 유지·방장만 설정, 종료 뒤 입장자 과거 기록 차단, 방장 방 종료·진행 게임 중단/무판결·완료 이력 유지·복구 불가 새 방 확정. 진행 중 후발/중단 게임 접근은 미정.

22차: 끊김 10분 미복귀 나감·전원 나감 방 종료, 방장 미복귀 무작위 이양 확정. 이전 이양 금지 대체. 후보 접속 기준/진행 권한/명시적 방장 나가기 미정.

## 23차 방장과 게임 역할 분리
방장은 방 관리·게임 설정·시작을 담당한다. 게임 생성 뒤 참가자들이 역할을 선택하며 방장도 피고가 될 수 있다. 원고라는 별도 게임 역할·작성자와 원고의 연결을 만들지 않는다. 방장 무작위 이양 후보에는 피고도 포함하고 피고라는 이유로 제외하지 않는다. 24차: 후보는 접속자만, 명시적 나가기 즉시 무작위 이양. 후보 없고 복귀 유예자가 있으면 대기.
권한은 두 축으로 검사한다: 방장 여부로 설정/시작/방 관리, 해당 게임 역할로 피고의 수락·변론 및 피고 외 자격자의 투표. 방장이 피고이면 피고 기능과 방장 기능을 모두 가지되 투표는 불가하다. 방장 이양만으로 게임 역할·동결 투표 자격·과거 표를 바꾸지 않는 설계로 분리한다. 참가자 최소 수는 서로 다른 사람 3명이며 방장·피고 겸임을 두 명으로 세지 않는다.

24차 [최신 예외 처리 규칙](00-current-rules.md)에 일괄 승인과 출처 정리. 더 잘게 사용자 질문을 늘리지 말고 이유 공개 시점 확정에 따라 기술 선택·배포·완료 기준으로 이동.

## 25차 결과 공개 최종 정정
첫 라운드 동률은 유죄·무죄·기권 수와 1차 익명 이유를 먼저 보여준 뒤 피고 선택 최후 변론, 2차 투표로 이어진다. 최종 결과는 1·2차 익명 이유 모두 표시하며 전원 기권 무판결에서도 작성된 기권 이유를 보여준다. 진행 중인 라운드의 미완료 표·이유는 비공개지만 이미 종료된 1차 공개 결과를 2차가 진행 중이라는 이유로 다시 숨기지 않는다. 신원·이름은 계속 숨기며 추론 방지 보장은 하지 않는다. 방 종료로 중단된 게임의 미완료 표/이유 비공개 정책은 유지한다.
