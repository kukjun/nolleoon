# 규칙 확정 질문

> 24차 일괄 확정: [최신 예외 규칙](00-current-rules.md)이 아래 과거 미정/제안보다 우선한다. 1~11 승인 및 25차 이유 공개 확정. 첫 동률 집계+익명 이유 공개, 최종 양 라운드 이유·무판결 기권 이유 공개.

## 현재 결정 상태 (24차)
[24차 일괄 결정](00-current-rules.md)에 1~4·6~11을 확정했다. 5번도 25차에 첫 동률 집계·익명 이유 공개 후 최후 변론·재투표로 확정했다. 최종 양 라운드 이유·무판결 기권 이유도 공개한다. 이전 A/B 목록에서 이미 승인된 정책을 다시 질문하지 않는다. 다음 단계는 기술 선택·배포 조건·완료 기준이다.
아래는 과거 결정 과정이며 현재 pending 목록으로 사용하지 않는다.

> 23차 사용자 정정(이전 역할 가정 대체): 방장은 방 관리·게임 설정·시작 권한이며 게임 역할과 독립이다. 게임을 만든 뒤 역할을 선택하고 방장도 피고가 될 수 있다. 피고는 무작위 방장 이양 후보에서도 제외하지 않는다. 작성자=원고/방장≠피고 가정은 폐기하며 원고 역할은 정의되지 않았다.

> 22차 우선 적용: 끊김 후 10분 미복귀는 나감, 전원 나가면 방 종료. 방장 10분 미복귀 시 남은 참가자 중 무작위 이양(없으면 종료). 이전 이양 없음/방장 부재 시 새 방 필수 규칙은 대체되었다. 이양 후보 접속 기준·자발적 방장 나가기 세부는 미정.

> 최신 도메인 기준(20차): 같은 방에서 사건을 순차 진행하며 기존 참가자는 재입장하지 않는다. 사건마다 피고·벌칙 수락·투표 자격을 새로 정한다. 아래 이전 차수의 사건 링크/참가자 모델은 사건 내부 정책의 이력이며, 방과 사건을 분리해 읽는다. 21차에서 방 링크 유지·방장만 게임 설정·사건별 기록 접근·방 종료가 추가 확정되었으며 이후 결정이 과거 미정 문구보다 우선한다. 세부 미정은 02-open-questions.md 참조.

## 14차 집계·완료 확정

- 기권을 제외하고 유죄가 더 많으면 유죄, 무죄가 더 많으면 무죄.
- 유효 동률은 첫 회 최후 변론/재투표, 두 번째는 무죄.
- 직접 기권은 제출 완료에 포함. 미제출은 시간 만료 시 기권.
- 실질 유효표 0, 전원 기권은 무판결. 직접 기권을 포함해 전원 제출했다면 자동 종료한다.
- 자격자 고정 시점(Q-26)은 이번 결정으로 해결되지 않으며 그대로 미정이다.

## 팀이 설계해서 제안할 것 — 사용자에게 기술 숙제 넘기지 않음

- 재접속 식별과 최소 권한 원칙, 역할 선택 충돌의 서버 처리
- 동시 요청·중복 제출 방지, 서버 시간 기준 투표 시간 처리 제안(정확한 만료·동시 도착 정책은 결정 후 반영)
- 데이터 모델·상태 전이·API 오류 규약
- 민감 정보 없는 로그와 운영 관찰
- 브라우저 호환성·접근성·보안 검증

비용·계정·공개 범위·데이터 보관에 영향을 주는 선택은 이유와 대안을 제시한다. 기술 스택이나 숫자 목표를 아직 확정하지 않는다. 전체 초안의 기술 선택은 [아키텍처 비교](06-architecture.md)를 참고한다.

## 결정 기록 형식

`질문 ID / 결정 / 이유 / 날짜 / 영향을 받는 문서·요구사항`

사용자 이유가 별도로 제시되지 않은 경우 이유를 지어내지 않는다. 기존 목업이나 추천을 답변으로 대체하지 않는다.

## 전체 초안 리뷰에서 먼저 결정할 묶음

1. **구현 검토:** 일반/최후 변론 진행은 16차로 해결. 방장 개시/피고 제출 경합·연결 복귀의 기술 계약 검토.
2. **진행/복구:** 일반·최후 변론의 제출/건너뛰기·무응답 대기 및 방장 개시 전제, 동일 브라우저 복원 구현. 최후 변론의 피고/선택·방장 재개는 확정.
3. **최종 공개:** 재투표 사건의 1·2차 이유 공개 범위, 무판결 종료의 이유 공개 여부. 1차 동률 뒤 집계·익명 이유 공개(25차 정정)는 확정.
4. **접근/생명주기:** 후발 입장 관전 범위, 사건 재사용·종료 후 새 사건·보존/만료, 역할 정정은 17차 확정; 충돌 안내 UX는 설계 검토.
5. **기술/운영:** 스택·비용·시간 입력 범위·데이터 보관. 구현은 별도 작업.

같은 재투표자·원래 설정 기간을 유지한다. 2차 신규 참가 허용·3분 강제 초기화·1차 이유 즉시 공개를 임의 적용하지 않는다. 강퇴·계정 생성·유료 서비스·공개 배포는 이 문서 요청만으로 실행하지 않는다.

닉네임 중복 표시 정책과 링크 유출 방지는 미정이지만, 이를 이유로 로그인·다른 기기 신원 복구·방장 이양을 MVP에 추가하지 않는다.

개인 기록의 기본 질문: 무엇을 목록/상세에 보여줄지, 같은 브라우저 신원과 어떻게 연결할지, 데이터 삭제/다른 브라우저에서 무엇을 잃는지, 서버 보관 기간과 삭제 방식. 7일을 기본 확정값으로 사용하지 않는다.

12차 이후 남은 이력 질문: 정렬/목록 필드·1/2차 세부 이유 표시 등 UI 구조, 종료 후 참가자 권한 검사 구현, 추후 삭제 정책. 전체 결과·익명 이유 개인 조회와 초기 자동 삭제 기한 없음은 다시 미정으로 묻지 않는다.

현재 완료 후 링크 정책은 확정이다. 위 11~12차의 미정 문구는 이력이며 13차로 대체한다.

## 정정: 투표자 고정 시점 확인 필요

이전 사용자 동의의 ‘시작 시점에 투표할 사람 고정’은 방장이 재판을 시작할 때를 가리킬 수 있다. 이후 ‘투표 시작 후 입장자는 투표 불가’는 이를 첫 투표 개시로 늦추라는 명시적 변경이 아니다. 따라서 이전 문서의 ‘첫 투표 시작으로 명확화’ 단정은 철회한다.

- 해석 A: 방장의 재판 시작에서 명단 고정. 반론 중 신규 입장자는 투표 불가.
- 해석 B: 첫 투표 개시에서 명단 고정. 재판 시작 이후라도 첫 투표 전에 입장하면 투표 가능.
- 사용자 확인 전 A/B 어느 쪽도 새 확정 규칙으로 구현하지 않는다.
- 공통 확정: 첫 투표 시작 후 신규 입장자는 해당 재판 투표 불가, 재투표는 같은 투표자 집합.
- Q-26: **반론 중 새로 들어온 사람도 투표할 수 있는가?** 이 답으로 명단 고정 시점을 확정한다.

종료 후 참가자 조회 제한·개인 기록·나머지 정책은 이 정정으로 바꾸지 않는다.

Q-05 일반 집계와 Q-23 기권 완료는 14차로 해결되었다. 과거 차수의 미정 문구는 당시 이력이며 재질문 대상이 아니다. Q-26 자격 고정 시점은 여전히 확인 대기다.

## 15차 Q-26 해결 — 최신 결정

방장이 **재판을 시작할 때** 투표자 명단을 고정한다. 첫 투표 시작 때가 아니다. 따라서 반론 중 새로 입장한 사람도 해당 재판의 1·2차 투표에 참여할 수 없다. 기존 참가자 재접속은 명단 유지다. 재투표는 같은 명단을 유지한다.

위 A/B 해석 대기와 Q-26 질문은 해결되었으며 새 결정으로 대체한다. 진행 중 링크 참여 및 종료 후 참가자 조회 정책은 그대로이고, 신규 입장자에게 기존 결정 이상의 관전/개별 정보 접근을 부여하지 않는다.

## 16차 Q-06/Q-24 변론 진행 확정

일반 반론·최후 변론 모두 피고가 작성하거나 건너뛸 수 있다. 완료 후 방장이 투표를 시작한다. 피고 무응답이면 방장은 변론 없이 투표를 시작할 수 있고, 피고에게 변론이 종료됐다는 안내를 보여준다. MVP에는 별도 변론 타이머를 두지 않는다.

이전 반론 대기/투표 개시 전제 미정은 해결되었다. 진행 중 투표 조기 종료 권한은 여전히 없다. 제출과 방장 개시 동시 발생은 상태를 원자 판정하고 이미 닫힌 변론 제출을 실패 안내하는 기술안으로 정리한다.

## 17차 대기실 정책 확정
참가자는 재판 시작 전 역할을 바꿀 수 있고 피고는 한 명이다. 방장과 게임 역할은 별개이며 방장도 피고가 될 수 있다. 방장은 끊겼거나 떠난 사람을 대기 명단에서 제거할 수 있으나 영구 차단은 아니며 제거된 사람은 시작 전 다시 입장할 수 있다. 피고가 바뀌면 새 피고의 벌칙 재수락이 필요하다. 재판 시작 뒤 역할과 자격은 고정한다. 앞선 역할 변경/강퇴 권한 미정 표현 중 이 범위만 대체한다.

미정 경계: 연결 감지 임계값, 떠남 표시 방식, 제거 후 재입장의 역할 복원/선택 UX, 제거 상태로 재판 시작된 사람의 이후 접근·개인 이력. 이 결정만으로 지속 차단·접속 중인 임의 참가자 제거·타인 역할 강제 변경·방장 제거/이양·시작 후 명단 축소를 허용하지 않는다.

## 18차 시작 조건 확정 및 남은 질문
접속 중인 서로 다른 참가자 최소 3명(방장·피고 포함, 두 역할 겸임 가능), 현 벌칙 수락, 부족 조건 안내, 벌칙 변경 시 수락 무효화/재수락 확정. 끊김 인원은 최소 인원에서 제외.
**19차 해결:** 접속자 3명 이상이어도 시작 시 끊긴 추가 참가자는 투표자 집합에서 제외하고 복귀 후 편입하지 않는다. 연결 감지 임계값은 실측 전 미정이다.

## 19차 자격 포함 기준 확정
시작 시 접속 중인 자격자만 동결. 끊긴 추가 참가자는 복귀해도 투표 불가. 기존 관전/조회 승인 범위는 그대로 유지. 서버가 시작 시 최종 판정하되 presence는 지연될 수 있으며 감지 임계값·경계 구현은 검토 대상이다. 즉시 실제 접속을 완벽 판별한다는 보장은 하지 않는다.

## 20차 방/연속 사건 확정과 우선 결정
확정: 같은 방에서 여러 사건 순차 진행, 기존 참가자 재입장 불필요, 사건별 피고·벌칙 수락·자격 동결 새로 수행. 아래가 이전 사건 재사용/방 경계 질문을 대체한다.
1. 다음 사건은 방장만 만드는가, 모든 참가자가 만드는가? 21차 방장만 설정으로 해결, 원고 역할은 정의하지 않음.
2. 방장은 방 전체에 유지되는가, 사건 작성자가 사건별 진행자가 되는가? 기존 작성자=방장·방장 권한과 게임 역할 분리·이양 없음 규칙과 정합화 필요. 방장 미복귀 때 같은 방에 새 사건 생성 가능한지도 함께 확인.
3. 초대 링크는 방 공통인가, 사건별도 있는가? 진행/종료/다음 사건 사이 링크 진입 목적지.
4. 방에 있던 사람은 언제 각 사건의 참가자로 기록되는가? 후발 입장·연결 끊김·제거·다음 사건 대기자의 사건별 결과/개인 이력 범위. 방 멤버십을 모든 과거 결과 권한으로 자동 확장하지 않음.
5. 방은 얼마나 유지하는가? 명시적 종료·최대 비활성 시간·만료와 복귀 UX. 서버 기록 삭제 기한 미설정과 방 수명은 별개.
대기 명단 제거가 방 단위인지 다음 사건만인지, 다음 사건 기본 시간값의 승계, 이전 결과 화면에서 다음 사건 이동 UX도 미정이다.

## 21차 최신 확정: 방 설정·접근·종료
- 흐름: 방 생성 → 방 안에서 게임 설정 → 플레이 → 같은 방에서 다음 게임 설정. 방 링크는 유지한다.
- 매 게임 설정은 방장만 한다. 방장이 시작하며 방장도 피고를 선택할 수 있고 참가자의 시작 전 본인 역할 선택/변경을 유지한다. 방장이 피고를 강제로 지정할 권한을 추가하지 않는다. 사건·피고·벌칙·시간을 게임별 설정으로 구성하는 UI 세부는 제안이며 시간 기본값 승계 등은 미정이다.
- 게임 1 종료 뒤 방에 들어온 사람은 게임 1 결과·이유를 볼 수 없고 게임 2에는 참여할 수 있다. 게임 1 참가자는 자기 기록에서 게임 1을 조회한다. 서버는 방 멤버십이 아닌 게임별 참여 권한을 검사한다. 24차: 진행 중 후발 참가자는 투표 불가·진행/최종 결과 조회·자기 이력 허용.
- 방장은 방을 종료할 수 있다. 종료 방에서는 신규 참가·신규 게임을 받지 않는다. 완료된 이전 게임은 해당 조회 자격자의 개인 기록에 남는다. 진행 중인 게임은 중단/판결 없음으로 처리한다. 24차: 방 종료 중단 이력은 중단·사건 내용만, 미완료 표·이유 비공개.
- 방장 복구는 같은 브라우저로 한다. 돌아올 수 없으면 새 방을 만든다. 이전 '새 사건' 안내를 방 모델에 맞춰 대체하며 MVP 이양은 추가하지 않는다. 자동 만료 시간은 미정이다.
- 기존 투표 조기 종료 금지는 정상 라운드 마감을 방장 임의로 당겨 판결하는 기능에 적용한다. 방 종료는 별도 명시적 예외로 진행 게임을 **중단·무판결** 처리하며 제출된 표로 승패를 계산하지 않는다.

### 현재 우선 미결정 (이전 20차 질문 중 해결된 항목 대체)
1. 진행 중 입장자의 사건 참여/관전 및 종료 결과 접근 범위.
2. 방 종료로 중단된 게임의 개인 이력·표/이유 공개 여부.
3. 방 자동 만료·유지 기간, 대기 명단 제거의 방/게임 경계.
4. 게임별 시간 기본값 승계, 최종 라운드별 이유 공개 세부 및 입력 제한.
방 링크 유지·방장만 설정·다음 게임 참여·종료 후 신규 차단·방장 복구 실패 새 방은 더 이상 미정이 아니다.

## 22차 나가기·복구·방장 이양 확정
- 명시적 나가기는 즉시 나감으로 처리한다. 연결이 끊긴 사람은 10분 안에 돌아오지 않으면 나간 것으로 처리한다. 10분 안 같은 브라우저로 복귀하면 기존 참가 신원을 복원한다. 연결 끊김을 즉시 나감으로 처리하지 않는다.
- 모두 나가면 방이 종료된다. 방장의 명시적 방 종료 기능도 유지한다. 투표 마감은 별도로 진행하며 연결 복구 유예 10분이 투표 시간을 연장하지 않는다. 동결 투표 자격과 접속/나감 상태를 혼동하지 않는다.
- 방장이 끊긴 뒤 10분 동안 돌아오지 않으면 남은 참가자 중 무작위로 방장을 넘긴다. 남은 참가자가 없으면 방을 종료한다. 기존 방장 이양 없음·방장 부재 시 새 방 필수는 이 규칙으로 대체한다.
- 미정: 무작위 후보가 접속 중인 사람만인지, 다른 끊김 유예자도 포함하는지; 피고도 무작위 방장 후보에 포함(확정); 진행 중 재판에서 새 방장 권한·게임 역할 처리; 방장 명시적 나가기의 이양 시점/동작. 무작위 정책을 이 항목들에 확대 적용하지 않는다.
- 10분 계시의 기술 기준(끊김 감지 시각/마지막 확인 시각), 재접속과 만료의 정확한 경계/서버 지연 보정은 구현 설계가 필요하다. 감지 자체가 완벽하게 즉시 이루어진다는 보장은 없다. 나감 판정 뒤 복귀 시 재입장/역할/기존 기록·자격 처리도 기존 확정 범위를 넘겨 추정하지 않는다.

## 23차 방장과 게임 역할 분리
방장은 방 관리·게임 설정·시작을 담당한다. 게임 생성 뒤 참가자들이 역할을 선택하며 방장도 피고가 될 수 있다. 원고라는 별도 게임 역할·작성자와 원고의 연결을 만들지 않는다. 방장 무작위 이양 후보에는 피고도 포함하고 피고라는 이유로 제외하지 않는다. 24차: 후보는 접속자만, 명시적 나가기 즉시 무작위 이양. 후보 없고 복귀 유예자가 있으면 대기.
권한은 두 축으로 검사한다: 방장 여부로 설정/시작/방 관리, 해당 게임 역할로 피고의 수락·변론 및 피고 외 자격자의 투표. 방장이 피고이면 피고 기능과 방장 기능을 모두 가지되 투표는 불가하다. 방장 이양만으로 게임 역할·동결 투표 자격·과거 표를 바꾸지 않는 설계로 분리한다. 참가자 최소 수는 서로 다른 사람 3명이며 방장·피고 겸임을 두 명으로 세지 않는다.

## 25차 결과 공개 최종 정정
첫 라운드 동률은 유죄·무죄·기권 수와 1차 익명 이유를 먼저 보여준 뒤 피고 선택 최후 변론, 2차 투표로 이어진다. 최종 결과는 1·2차 익명 이유 모두 표시하며 전원 기권 무판결에서도 작성된 기권 이유를 보여준다. 진행 중인 라운드의 미완료 표·이유는 비공개지만 이미 종료된 1차 공개 결과를 2차가 진행 중이라는 이유로 다시 숨기지 않는다. 신원·이름은 계속 숨기며 추론 방지 보장은 하지 않는다. 방 종료로 중단된 게임의 미완료 표/이유 비공개 정책은 유지한다.
