# 4단계 C: 데이터 모델 제안

> 24차 일괄 확정: [최신 예외 규칙](00-current-rules.md)이 아래 과거 미정/제안보다 우선한다. 1~11 승인 및 25차 이유 공개 확정. 첫 동률 집계+익명 이유 공개, 최종 양 라운드 이유·무판결 기권 이유 공개.

> 23차 사용자 정정(이전 역할 가정 대체): 방장은 방 관리·게임 설정·시작 권한이며 게임 역할과 독립이다. 게임을 만든 뒤 역할을 선택하고 방장도 피고가 될 수 있다. 피고는 무작위 방장 이양 후보에서도 제외하지 않는다. 작성자=원고/방장≠피고 가정은 폐기하며 원고 역할은 정의되지 않았다.

> 22차 우선 적용: 끊김 후 10분 미복귀는 나감, 전원 나가면 방 종료. 방장 10분 미복귀 시 남은 참가자 중 무작위 이양(없으면 종료). 이전 이양 없음/방장 부재 시 새 방 필수 규칙은 대체되었다. 이양 후보 접속 기준·자발적 방장 나가기 세부는 미정.

> 최신 도메인 기준(20차): 같은 방에서 사건을 순차 진행하며 기존 참가자는 재입장하지 않는다. 사건마다 피고·벌칙 수락·투표 자격을 새로 정한다. 아래 이전 차수의 사건 링크/참가자 모델은 사건 내부 정책의 이력이며, 방과 사건을 분리해 읽는다. 21차에서 방 링크 유지·방장만 게임 설정·사건별 기록 접근·방 종료가 추가 확정되었으며 이후 결정이 과거 미정 문구보다 우선한다. 세부 미정은 02-open-questions.md 참조.

상태: 논리 모델 초안 / DB·스키마 미구현 · 2026-11-16

## 엔티티

| 엔티티 | 주요 값 | 관계·제약 제안 |
|---|---|---|
| Room | id, status, revision | 여러 순차 사건의 경계. 방장·초대 링크·만료 필드는 정책 확정 뒤 정의 |
| RoomMember | id, roomId, browserIdentityId, nickname, presence | 방 내 참가 신원 유지. 방 회원자격만으로 모든 사건 조회 허용하지 않음 |
| Case | id, roomId, content, status, creatorId, defendantId, punishment, punishmentVersion, durationSec, startedAt, votingOpenedAt, deadline, revision | 설정 주체와 게임 역할 분리·피고 최대 1명. 시작 이후 벌칙 잠금 |
| CaseParticipant (기존 Participant 분리) | id, caseId, roomMemberId, role, participationStatus | 사건별 역할·참여·조회 근거. 등록 시점/조건은 미정. 닉네임은 인증키 아님 |
| BrowserSession (기존 ParticipantSession 분리) | browserIdentityId, hashedCredential, expiresAt | 세션 비밀 원문을 로그/공유 데이터에 저장하지 않음. 동일 기기·브라우저 복원 정책 확정, 쿠키·만료 기술 설계 미정 |
| PunishmentConsent | caseId, defendantId, punishmentVersion, decision, decidedAt | 현재 벌칙 버전 수락만 시작 조건 충족 |
| Electorate | caseId, participantId, frozenAt | 방장 재판 시작 시 자격 스냅샷. 피고 제외. 시작 후 신규 입장 제외 |
| Defense | caseId, defendantId, text, submittedAt | 선택 반론. 횟수·수정 정책 미정 |
| Vote | caseId, roundNo, participantId, choice, reason, submittedAt, requestKey | (caseId, roundNo, participantId) 중복 방지 확정, DB 유일 제약은 구현 제안. GUILTY/NOT_GUILTY/ABSTAIN |
| Result | caseId, verdict, guiltyCount, notGuiltyCount, explicitAbstainCount, timeoutAbstainCount, closedAt, closeReason, policyVersion | 사건당 한 결과. NO_VERDICT 별도 값 |

## 중요한 구분

- 미제출은 Vote가 없는 상태이며 마감 때만 timeout abstention으로 집계한다. 직접 기권과 구분해 원인 추적 가능하도록 설계.
- 투표 개수·완료 개수·실질 유효표 수는 서로 다르다. 직접 기권은 완료에 포함 확정.
- API용 익명 공개 모델은 내부 Vote 모델과 분리한다. participantId·세션·원본 접수 시각이 무심코 노출되지 않도록 검토한다.
- 익명 공개는 저장소에서도 작성자 연결이 없다는 보장이 아니다. 재접속/중복 방지 위해 내부 연결을 저장하는 제안의 개인정보 한계를 명시한다.
- Result의 verdict 계산은 G>N 유죄/N>G 무죄, 첫/두 번째 동률과 0유효표 규칙으로 정책 버전을 부여하는 설계다. 최종 이유 공개 세부는 별도 경계다.

## 데이터 생명주기 미결정

사건/링크 만료, 결과 보존, 참가자 삭제, 로그 보존, 링크 재발급, 동일 브라우저 방장 복구(이양 없음), 실제 개인정보 최소 수집 정책. 공개 저장소 fixture는 가상 값만 사용한다. 가입·외부 저장 서비스 선택은 이 문서로 승인되지 않는다.

## 재투표 반영 제안

VotingRound(caseId, roundNo, status, openedAt, deadline, electorateSnapshot, closeReason, counts)를 추가하고 roundNo는 1/2로 제한한다. 1차 동률 정산은 FinalDefense와 2차 진행으로 연결하며 최종 Result와 구분한다. FinalDefense는 피고 선택 작성이다. completedAt/skip 등 종료 표시는 대기 정책 확정 후 정의한다. 2차 electorate는 1차 스냅샷을 유지하고 duration은 원래 설정 기간을 사용한다. 2차 deadline은 방장이 개시한 서버 시점과 해당 기간으로 계산하는 설계다. Vote·requestKey·라운드 결과를 roundNo로 격리한다.

복원 조회는 닉네임 검색이 아니라 저장된 참가자 세션 증명으로 수행하는 제안이다. 동일 브라우저 링크 재방문에 Participant를 중복 생성하지 않는다. 브라우저 데이터 삭제 시 세션 증명이 없어 복구가 보장되지 않는다. 다른 기기/브라우저에서 같은 닉네임을 입력해도 기존 ParticipantSession을 발급하지 않는다.

## 개인 기록 모델 후보
BrowserHistoryEntry 또는 서버 측 ParticipantGameHistory는 개인 참여 이력 기능의 모델 후보다. 사건 ID·참여 연결을 담는 방향이며 구체 필드·정렬·인덱스·브라우저 범위 자격 연결·삭제 연쇄는 미정이다. 닉네임을 기준으로 다른 사람 기록을 합치지 않는다. 서버 기록 보관 가능은 무기한 저장이나 7일 삭제 정책의 확정이 아니다. 완료 후 어느 정보를 볼 수 있는지도 별도로 정한다.

12차 정책에 맞춰 개인 이력은 전체 결과·익명 이유를 조회할 수 있는 참여 연결을 제공한다. 서버 자동 삭제를 위한 7일 expiresAt 기본값 등을 추가하지 않는다. 향후 삭제 정책은 별도 변경으로 설계한다. 브라우저별 접근 자격이 지워지거나 기기가 바뀌면 이력이 보이지 않을 수 있으며 서버 레코드 삭제와 동일한 사건은 아니다.

13차: 진행 중 참가자 등록과 자격 스냅샷을 분리한다. 스냅샷은 방장이 재판을 시작할 때 생성한다. 종료 후에는 신규 Participant를 만들어 결과 접근을 부여하지 않는다. 기존 참가 여부에 대한 서버 기록을 결과 권한 검사에 쓰고, 브라우저 이력은 이 브라우저 참여 자격으로만 조회한다.

16차: 일반/최후 변론은 text 제출 또는 skip과 방장 개시 종료를 구분할 수 있게 설계한다. closedAt/closeReason=submitted_or_skipped/no_response 등의 모델은 제안이며 서버 상태가 원본이다. 별도 defenseDeadline 필드를 필수로 도입하지 않는다.

## 17차 대기실 모델 제안
Participant의 참가 상태(대기 명단 포함/제거)와 접속 상태를 분리한다. 제거는 영구 ban이 아니며 시작 전 재입장 가능. 역할은 시작 뒤 고정하고 서버 제약으로 피고 유일성 및 hostId와 defendantId는 같아도 됨를 검사한다. PunishmentConsent는 punishmentVersion뿐 아니라 defendantId/defendantAssignmentVersion에 연결하여 피고 변경 시 과거 수락의 승계를 막는다. 제거 기록의 보관·개인 이력 및 재입장 역할 UX는 미정. 시작 전 명단의 현재 유효 구성으로 최소 인원을 검사하고 Electorate를 한 번 고정한다.

18차: 시작 준비 인원은 현재 명단 중 접속 중인 서로 다른 참가자 최소 3명(방장·피고 포함, 두 역할 겸임 가능)으로 계산. presence와 Electorate는 서로 다른 개념이다. 19차로 시작 시 접속 중인 자격자만 Electorate에 포함하며 이후 presence 변화로 이를 다시 계산하지 않는다. 벌칙 변경 시 과거 consent를 무효로 판단하는 정책은 확정.

19차 Electorate 생성 기준은 /start의 서버 접속 판정에서 접속 중인 피고 외 자격자다. 이후 presence와 독립된 고정 스냅샷을 유지한다. 시작 시 제외된 참가자의 복귀와 이미 자격이 있는 참가자의 복귀를 분리하며 nickname/참가 이력만으로 자격을 추가하지 않는다.

## 20차 방/사건 분리 설계
Room 1:N Case, RoomMember와 CaseParticipant를 별도 연결한다. 참가 신원은 방에서 유지하되 역할·피고·벌칙 버전/수락·Electorate·Defense·VotingRound·Vote·Result는 caseId로 격리한다. 세션 신원에서 사건별 Participant로의 매핑 방식은 구현 제안이다. 다음 사건의 피고/수락/투표 자격은 새로 정하며 이전 사건 레코드를 reset하거나 덮어쓰지 않는다.
방의 현재 사건 포인터 또는 진행 순번, 방별 동시 활성 사건 방지 제약을 제안한다. 정확한 다음 사건 생성자/방장 권한이 정해지기 전에는 hostId를 이전 사건에서 복사하지 않는다. 방 입장 자체와 사건 참여 등록 시점은 별개 정책 질문이다.
개인 이력은 사건 단위 참여 근거로 연결하고 방 가입만으로 과거 사건을 소급 추가하지 않는다. 사건 CLOSED는 방 CLOSED와 다르다. 사건 기록 보존(초기 자동 삭제 기한 없음)과 방 최대 유지 시간은 다른 정책이며 후자는 미정이다. 방 제거가 과거 사건 결과 권한 삭제나 전체 방 영구 차단을 뜻하는지 추정하지 않는다.

## 21차 최신 확정: 방 설정·접근·종료
- 흐름: 방 생성 → 방 안에서 게임 설정 → 플레이 → 같은 방에서 다음 게임 설정. 방 링크는 유지한다.
- 매 게임 설정은 방장만 한다. 방장이 시작하며 방장도 피고를 선택할 수 있고 참가자의 시작 전 본인 역할 선택/변경을 유지한다. 방장이 피고를 강제로 지정할 권한을 추가하지 않는다. 사건·피고·벌칙·시간을 게임별 설정으로 구성하는 UI 세부는 제안이며 시간 기본값 승계 등은 미정이다.
- 게임 1 종료 뒤 방에 들어온 사람은 게임 1 결과·이유를 볼 수 없고 게임 2에는 참여할 수 있다. 게임 1 참가자는 자기 기록에서 게임 1을 조회한다. 서버는 방 멤버십이 아닌 게임별 참여 권한을 검사한다. 24차: 진행 중 후발 참가자는 투표 불가·진행/최종 결과 조회·자기 이력 허용.
- 방장은 방을 종료할 수 있다. 종료 방에서는 신규 참가·신규 게임을 받지 않는다. 완료된 이전 게임은 해당 조회 자격자의 개인 기록에 남는다. 진행 중인 게임은 중단/판결 없음으로 처리한다. 24차: 방 종료 중단 이력은 중단·사건 내용만, 미완료 표·이유 비공개.
- 방장 복구는 같은 브라우저로 한다. 돌아올 수 없으면 새 방을 만든다. 이전 '새 사건' 안내를 방 모델에 맞춰 대체하며 MVP 이양은 추가하지 않는다. 자동 만료 시간은 미정이다.
- 기존 투표 조기 종료 금지는 정상 라운드 마감을 방장 임의로 당겨 판결하는 기능에 적용한다. 방 종료는 별도 명시적 예외로 진행 게임을 **중단·무판결** 처리하며 제출된 표로 승패를 계산하지 않는다.

21차 모델 보완 제안: Room에 hostIdentityId, status, closedAt/closedBy, 유지되는 invite 식별자를 둔다. Case의 종료 사유 INTERRUPTED_BY_ROOM_CLOSE와 verdict=NO_VERDICT를 정상 전원기권 무판결과 구분한다. 기존 완료 Result는 변경하지 않는다. 방 참가 joinedAt만으로 과거 게임 접근을 허용하지 않고 CaseParticipant 근거를 사용한다. 진행 중 후발/중단 게임 이력 포함 정책은 미정이다.

## 22차 나가기·복구·방장 이양 확정
- 명시적 나가기는 즉시 나감으로 처리한다. 연결이 끊긴 사람은 10분 안에 돌아오지 않으면 나간 것으로 처리한다. 10분 안 같은 브라우저로 복귀하면 기존 참가 신원을 복원한다. 연결 끊김을 즉시 나감으로 처리하지 않는다.
- 모두 나가면 방이 종료된다. 방장의 명시적 방 종료 기능도 유지한다. 투표 마감은 별도로 진행하며 연결 복구 유예 10분이 투표 시간을 연장하지 않는다. 동결 투표 자격과 접속/나감 상태를 혼동하지 않는다.
- 방장이 끊긴 뒤 10분 동안 돌아오지 않으면 남은 참가자 중 무작위로 방장을 넘긴다. 남은 참가자가 없으면 방을 종료한다. 기존 방장 이양 없음·방장 부재 시 새 방 필수는 이 규칙으로 대체한다.
- 미정: 무작위 후보가 접속 중인 사람만인지, 다른 끊김 유예자도 포함하는지; 피고도 무작위 방장 후보에 포함(확정); 진행 중 재판에서 새 방장 권한·게임 역할 처리; 방장 명시적 나가기의 이양 시점/동작. 무작위 정책을 이 항목들에 확대 적용하지 않는다.
- 10분 계시의 기술 기준(끊김 감지 시각/마지막 확인 시각), 재접속과 만료의 정확한 경계/서버 지연 보정은 구현 설계가 필요하다. 감지 자체가 완벽하게 즉시 이루어진다는 보장은 없다. 나감 판정 뒤 복귀 시 재입장/역할/기존 기록·자격 처리도 기존 확정 범위를 넘겨 추정하지 않는다.

22차 모델 후보: RoomMember에 connectionState/disconnectedAt/leaveDeadlineAt/leftAt/leaveReason, Room에 hostMemberId/hostRevision 추가. 타이머의 기준 시각은 아직 기술 검토 필요. 방장 이양 기록과 사건 creator/게임 역할/진행 권한을 분리하여 과거 사건 신원을 덮어쓰지 않는다. 무작위 후보 필터는 사용자 결정 전 고정하지 않는다.

## 23차 방장과 게임 역할 분리
방장은 방 관리·게임 설정·시작을 담당한다. 게임 생성 뒤 참가자들이 역할을 선택하며 방장도 피고가 될 수 있다. 원고라는 별도 게임 역할·작성자와 원고의 연결을 만들지 않는다. 방장 무작위 이양 후보에는 피고도 포함하고 피고라는 이유로 제외하지 않는다. 24차: 후보는 접속자만, 명시적 나가기 즉시 무작위 이양. 후보 없고 복귀 유예자가 있으면 대기.
권한은 두 축으로 검사한다: 방장 여부로 설정/시작/방 관리, 해당 게임 역할로 피고의 수락·변론 및 피고 외 자격자의 투표. 방장이 피고이면 피고 기능과 방장 기능을 모두 가지되 투표는 불가하다. 방장 이양만으로 게임 역할·동결 투표 자격·과거 표를 바꾸지 않는 설계로 분리한다. 참가자 최소 수는 서로 다른 사람 3명이며 방장·피고 겸임을 두 명으로 세지 않는다.

23차 스키마: Room.hostMemberId와 CaseParticipant.role/Case.defendantId는 독립. 둘의 불일치 제약을 두지 않는다. creatorId는 감사 정보일 뿐 원고 역할이나 투표 자격의 근거가 아니다. plaintiff 필드를 정의하지 않는다.

24차: CaseParticipant의 view/history 권한은 진행 중 입장에도 부여하되 vote 권한은 Electorate로 분리. 나감 뒤 재입장 시 과거 투표 신원/접수는 감사 기록으로 유지하고 자격 부활 금지. RoomGameDraft(roomId, content, punishment, durationSec, revision, updatedBy) 후보로 초안을 보존. 중단 이력용 공개 projection은 status/content만. 닉네임 유일성 범위·정규화 및 draft 저장 주기는 기술 초안.

## 25차 결과 공개 최종 정정
첫 라운드 동률은 유죄·무죄·기권 수와 1차 익명 이유를 먼저 보여준 뒤 피고 선택 최후 변론, 2차 투표로 이어진다. 최종 결과는 1·2차 익명 이유 모두 표시하며 전원 기권 무판결에서도 작성된 기권 이유를 보여준다. 진행 중인 라운드의 미완료 표·이유는 비공개지만 이미 종료된 1차 공개 결과를 2차가 진행 중이라는 이유로 다시 숨기지 않는다. 신원·이름은 계속 숨기며 추론 방지 보장은 하지 않는다. 방 종료로 중단된 게임의 미완료 표/이유 비공개 정책은 유지한다.
