# 4단계 B: 아키텍처 제안

> 24차 일괄 확정: [최신 예외 규칙](00-current-rules.md)이 아래 과거 미정/제안보다 우선한다. 1~11 승인 및 25차 이유 공개 확정. 첫 동률 집계+익명 이유 공개, 최종 양 라운드 이유·무판결 기권 이유 공개.

> 23차 사용자 정정(이전 역할 가정 대체): 방장은 방 관리·게임 설정·시작 권한이며 게임 역할과 독립이다. 게임을 만든 뒤 역할을 선택하고 방장도 피고가 될 수 있다. 피고는 무작위 방장 이양 후보에서도 제외하지 않는다. 작성자=원고/방장≠피고 가정은 폐기하며 원고 역할은 정의되지 않았다.

> 22차 우선 적용: 끊김 후 10분 미복귀는 나감, 전원 나가면 방 종료. 방장 10분 미복귀 시 남은 참가자 중 무작위 이양(없으면 종료). 이전 이양 없음/방장 부재 시 새 방 필수 규칙은 대체되었다. 이양 후보 접속 기준·자발적 방장 나가기 세부는 미정.

> 최신 도메인 기준(20차): 같은 방에서 사건을 순차 진행하며 기존 참가자는 재입장하지 않는다. 사건마다 피고·벌칙 수락·투표 자격을 새로 정한다. 아래 이전 차수의 사건 링크/참가자 모델은 사건 내부 정책의 이력이며, 방과 사건을 분리해 읽는다. 21차에서 방 링크 유지·방장만 게임 설정·사건별 기록 접근·방 종료가 추가 확정되었으며 이후 결정이 과거 미정 문구보다 우선한다. 세부 미정은 02-open-questions.md 참조.

상태: 기술 선택 전 초안 / 채택·설치·배포 미실행 · 2026-11-16

## 추천

작은 모바일 웹과 단일 백엔드, 관계형 저장소로 시작한다. 초기에는 읽기 폴링으로 상태를 갱신하고 필요하면 SSE를 추가하는 구성이 단순하다. 이는 결정이 아니라 비교를 위한 제안이다.

```text
모바일 브라우저들
  ├─ 명령: HTTPS JSON API
  └─ 상태: snapshot 조회/주기 폴링 (SSE 후보)
       ↓
단일 애플리케이션 서버
  ├─ 권한·상태·마감·집계 서비스
  ├─ 끊김 추정용 presence
  └─ 마감 정산 작업
       ↓
트랜잭션 가능한 관계형 저장소
```

## 선택지 비교

| 선택 | 장점 | 비용/주의 | 초기 제안 |
|---|---|---|---|
| 단일 풀스택 앱 | 타입·배포 경계 적음 | UI/API 결합 관리 | 우선 비교 |
| 웹 프론트 + FastAPI | 사용자 경험 스택과 친숙한 백엔드 분리 | 배포·타입 계약 2개 | 유효 대안 |
| 읽기 폴링 | 구현·복구 단순, snapshot 원본 사용 | 갱신 지연·요청 증가 | 초기 추천 |
| SSE | 상태 변화 빠른 푸시 | 연결 복구·프록시·배포 지원 확인 | 필요 시 |
| WebSocket | 양방향 통신 | 유지·재연결 복잡성 | 필요 근거 생길 때 |

프레임워크·버전·DB·호스팅은 미선택이다. SQLite는 단일 영속 서버 조건에서 후보, 다중 인스턴스/서버리스는 별도 DB 요구를 검토한다. 현재 하네스가 Node 기반이라는 사실이 앱 스택을 Node로 확정하지 않는다.

## 책임과 신뢰 경계

- 브라우저: 화면·입력·초안·남은 시간 표시. 권한·집계의 원본 아님.
- 서버: 참가자 신원/역할, 사건 접근, 투표 자격, 마감, 결과. 클라이언트 역할 값을 그대로 신뢰하지 않음.
- DB: 피고 1명·한 참가자 한 표 등 불변식과 원자 전환.
- 링크: 접근 자격을 대신할 수 있는 민감한 bearer 값일 가능성. 링크만으로 모든 권한을 주지 않음.
- 방장 권한 증명과 초대 링크를 분리하는 제안. 초대 링크 수신자가 방장 권한을 얻지 않아야 함.

## 접속·복구 제안

로그인 없이 닉네임·역할로 참여하고, 같은 기기·브라우저 링크 복귀에서 참가자/방장 신원과 표를 복원하는 정책은 확정이다. 서버 발급 무작위 세션을 보안 쿠키 등에 저장하고 snapshot으로 복구하는 구현을 제안한다. 닉네임은 인증키가 아니다. 다른 기기/브라우저·저장소 삭제는 기존 신원을 자동 복구하지 않는다. 인앱/외부 브라우저도 저장 공간이 다를 수 있다.

방장도 동일 정책이며 미복귀 시 새 사건을 만든다. MVP에는 방장 이양이나 계정 로그인·복구코드를 추가하지 않는다. 같은 브라우저 복원도 저장된 자격 증명이 남아 있을 때 작동하므로 세션 만료/쿠키 수명과 보관 정책을 함께 설계한다.

heartbeat나 마지막 요청 시각으로 끊김을 추정한다. 실제 종료/백그라운드/네트워크 정체를 완벽히 구분하지 못하며, 감지 간격·오프라인 기준은 계측 후 결정. 연결 이상은 본인과 다른 참가자에게 표시하고 복귀 시 서버 상태를 재동기화한다. 익명 표와 참가자 접속 상태를 불필요하게 결합해 노출하지 않는다.

## 운영 제안

마감 작업은 재시도 가능하고 결과 중복 생성이 없어야 한다. DB 기반 마감 검색+안전한 정산, snapshot 조회 시 정산 보완 중 선택. 서버 재시작 시 복구 시험 필요. 로그는 사건/요청 ID·오류 코드·지연 위주로 남기고 이유·세션 비밀은 기록하지 않는 방향. 데이터 삭제·백업·비용 상한과 공개 배포는 별도 결정.

지원 우선 환경은 현재 iPhone Safari·Android Chrome이며 PC 사용도 가능해야 한다. 마감은 서버 기준, 늦은 제출 실패와 참가자/라운드별 중복 방지는 확정 요구다. 중국 본토 접근 가능성은 호스팅·도메인·외부 의존성을 선택한 뒤 실제 네트워크에서 검증하며 현재 보장하지 않는다.

## 개인 기록 확장 제안
참가자가 브라우저에서 자신이 참여한 게임을 조회하는 방향과 서버 기록 저장 가능은 확정이다. 브라우저에 게임별 접근 자격을 보관하거나 브라우저 범위의 익명 식별로 서버 이력에 연결하는 두 안을 비교할 수 있다. 로그인 없는 기존 정책·다른 기기 닉네임 비신원·저장소 삭제 복구 비보장을 유지한다. 어느 방식도 아직 채택하지 않았으며 초기 자동 삭제 기한은 없고 추후 삭제 정책은 미정이다. 완료 후 참가자 권한은 13차 정책을 따른다.

12차 이력 범위 확정: 참여 게임의 전체 결과·익명 이유, 브라우저별 이력의 데이터 삭제/기기 변경 유실 가능. 초기 자동 삭제 기한 없이 시작하며 향후 삭제 정책을 결정한다. 서버 기록 존재와 조회 자격 보존을 분리해 설계한다. 완료 후 기존 참가자는 결과·이유, 비참가자는 종료 안내로 확정했다.

13차 접근 정책을 서버에서 검사한다: 진행 중 링크 참여 허용, 첫 투표 뒤 신규 입장자 투표 불가, 종료 후 기존 참가자만 결과·이유 허용/비참가자는 종료 안내. 브라우저 개인 기록은 해당 브라우저 참여 자격과 연결하며 데이터 유실·새 브라우저에서 닉네임 복원 경로를 제공하지 않는다.

14차 집계 서비스 정책: G>N 유죄/N>G 무죄, 기권 제외, 직접 기권 완료 포함, 미제출은 만료 기권. 집계 임계값이 미정이라는 이전 표현은 더 이상 유효하지 않다. 명단 고정 시점은 여전히 별도 결정이다.

15차: 자격 스냅샷은 방장 재판 시작의 원자 전환에서 생성한다. 첫 투표/재투표 시작은 같은 명단을 사용하며 반론 중 신규 입장을 투표자에 추가하지 않는다. 진행 중 입장·종료 후 조회의 기존 접근 범위는 유지한다.

변론 대기용 자동 타이머/스케줄러는 MVP에서 필요 없다. 방장 개시로 일반/최후 변론 종료를 서버 상태에 반영하고 피고에게 동기화한다. 실제 투표 마감 작업은 별개로 유지한다.

17차 대기실 권한: 서버에서 본인 역할 변경·방장의 끊김/이탈 명단 제거를 시작 전으로 제한. 명단 제거와 영구 차단을 구분하고 시작 전 재입장을 허용한다. 피고 유일성·방장 권한과 게임 역할 분리·교체 뒤 새 수락을 상태 전환과 같은 원자 경계로 검증한다. 연결 표시만으로 자동 제거하지 않는다.

19차: 서버 /start의 최종 접속 판정으로 접속 중인 피고 외 자격자를 동결한다. 오래된 클라이언트 presence를 자격 증거로 신뢰하지 않는다. 서버 presence도 감지 지연이 있을 수 있으며 임계값은 실측 후 정한다. 시작 시 제외된 끊김 참가자의 복귀는 기존 관전 범위만 유지하며 자격 생성이나 조회 범위 확대가 아니다.

## 20차 방 경계 도입
기존 단일 사건 서비스에 Room/RoomMember와 사건별 참여 권한 경계를 추가하는 구조를 제안한다. 참가 세션은 방에서 지속되고 사건 명령·수락·투표·결과는 caseId로 격리한다. 방 상태와 현재 사건 상태를 함께 복구하되 방 멤버십을 과거 사건 결과 권한으로 사용하지 않는다.
폴링/SSE를 선택하면 room revision과 case revision 또는 동등한 범위를 구분해 오래된 A 이벤트가 B 화면을 덮지 않도록 한다. 실시간 방식/스택 제안은 그대로 미선택. 방장과 사건 작성자의 권한 관계·방 수명·링크 경계는 결정 전 코드로 고정하지 않는다.

## 21차 최신 확정: 방 설정·접근·종료
- 흐름: 방 생성 → 방 안에서 게임 설정 → 플레이 → 같은 방에서 다음 게임 설정. 방 링크는 유지한다.
- 매 게임 설정은 방장만 한다. 방장이 시작하며 방장도 피고를 선택할 수 있고 참가자의 시작 전 본인 역할 선택/변경을 유지한다. 방장이 피고를 강제로 지정할 권한을 추가하지 않는다. 사건·피고·벌칙·시간을 게임별 설정으로 구성하는 UI 세부는 제안이며 시간 기본값 승계 등은 미정이다.
- 게임 1 종료 뒤 방에 들어온 사람은 게임 1 결과·이유를 볼 수 없고 게임 2에는 참여할 수 있다. 게임 1 참가자는 자기 기록에서 게임 1을 조회한다. 서버는 방 멤버십이 아닌 게임별 참여 권한을 검사한다. 24차: 진행 중 후발 참가자는 투표 불가·진행/최종 결과 조회·자기 이력 허용.
- 방장은 방을 종료할 수 있다. 종료 방에서는 신규 참가·신규 게임을 받지 않는다. 완료된 이전 게임은 해당 조회 자격자의 개인 기록에 남는다. 진행 중인 게임은 중단/판결 없음으로 처리한다. 24차: 방 종료 중단 이력은 중단·사건 내용만, 미완료 표·이유 비공개.
- 방장 복구는 같은 브라우저로 한다. 돌아올 수 없으면 새 방을 만든다. 이전 '새 사건' 안내를 방 모델에 맞춰 대체하며 MVP 이양은 추가하지 않는다. 자동 만료 시간은 미정이다.
- 기존 투표 조기 종료 금지는 정상 라운드 마감을 방장 임의로 당겨 판결하는 기능에 적용한다. 방 종료는 별도 명시적 예외로 진행 게임을 **중단·무판결** 처리하며 제출된 표로 승패를 계산하지 않는다.

## 22차 나가기·복구·방장 이양 확정
- 명시적 나가기는 즉시 나감으로 처리한다. 연결이 끊긴 사람은 10분 안에 돌아오지 않으면 나간 것으로 처리한다. 10분 안 같은 브라우저로 복귀하면 기존 참가 신원을 복원한다. 연결 끊김을 즉시 나감으로 처리하지 않는다.
- 모두 나가면 방이 종료된다. 방장의 명시적 방 종료 기능도 유지한다. 투표 마감은 별도로 진행하며 연결 복구 유예 10분이 투표 시간을 연장하지 않는다. 동결 투표 자격과 접속/나감 상태를 혼동하지 않는다.
- 방장이 끊긴 뒤 10분 동안 돌아오지 않으면 남은 참가자 중 무작위로 방장을 넘긴다. 남은 참가자가 없으면 방을 종료한다. 기존 방장 이양 없음·방장 부재 시 새 방 필수는 이 규칙으로 대체한다.
- 미정: 무작위 후보가 접속 중인 사람만인지, 다른 끊김 유예자도 포함하는지; 피고도 무작위 방장 후보에 포함(확정); 진행 중 재판에서 새 방장 권한·게임 역할 처리; 방장 명시적 나가기의 이양 시점/동작. 무작위 정책을 이 항목들에 확대 적용하지 않는다.
- 10분 계시의 기술 기준(끊김 감지 시각/마지막 확인 시각), 재접속과 만료의 정확한 경계/서버 지연 보정은 구현 설계가 필요하다. 감지 자체가 완벽하게 즉시 이루어진다는 보장은 없다. 나감 판정 뒤 복귀 시 재입장/역할/기존 기록·자격 처리도 기존 확정 범위를 넘겨 추정하지 않는다.

## 23차 방장과 게임 역할 분리
방장은 방 관리·게임 설정·시작을 담당한다. 게임 생성 뒤 참가자들이 역할을 선택하며 방장도 피고가 될 수 있다. 원고라는 별도 게임 역할·작성자와 원고의 연결을 만들지 않는다. 방장 무작위 이양 후보에는 피고도 포함하고 피고라는 이유로 제외하지 않는다. 24차: 후보는 접속자만, 명시적 나가기 즉시 무작위 이양. 후보 없고 복귀 유예자가 있으면 대기.
권한은 두 축으로 검사한다: 방장 여부로 설정/시작/방 관리, 해당 게임 역할로 피고의 수락·변론 및 피고 외 자격자의 투표. 방장이 피고이면 피고 기능과 방장 기능을 모두 가지되 투표는 불가하다. 방장 이양만으로 게임 역할·동결 투표 자격·과거 표를 바꾸지 않는 설계로 분리한다. 참가자 최소 수는 서로 다른 사람 3명이며 방장·피고 겸임을 두 명으로 세지 않는다.

24차: 설정 초안은 새 방장에게 전달 가능하도록 서버 공유 저장을 제안. 브라우저 로컬에만 저장하면 REQ-068 충족 불가. 권한 변경과 초안 revision을 검사해 이전 방장의 늦은 저장이 새 설정을 덮지 않게 한다. 실시간 접속과 퇴장 만료·이양 대기·게임 deadline은 별도 상태로 관리.

## 25차 결과 공개 최종 정정
첫 라운드 동률은 유죄·무죄·기권 수와 1차 익명 이유를 먼저 보여준 뒤 피고 선택 최후 변론, 2차 투표로 이어진다. 최종 결과는 1·2차 익명 이유 모두 표시하며 전원 기권 무판결에서도 작성된 기권 이유를 보여준다. 진행 중인 라운드의 미완료 표·이유는 비공개지만 이미 종료된 1차 공개 결과를 2차가 진행 중이라는 이유로 다시 숨기지 않는다. 신원·이름은 계속 숨기며 추론 방지 보장은 하지 않는다. 방 종료로 중단된 게임의 미완료 표/이유 비공개 정책은 유지한다.
