# 여행방 요구사항 검토와 메뉴 ADR 초안

상태: 역사적 검토 제안. 메뉴 후속 채택은 [ADR 0020](../decisions/0020-travel-menu-defaults.md)이 우선한다. 아래 당시 미정이라는 표현은 이후 채택을 취소하지 않는다. 코드·운영·GitHub 이슈 변경 없음. 2026-11-18 GitHub #117–119/#125/#127/#129/#131/#133–135, #33/#116 및 실제 대화 확인. 원래 사용자 확정과 아래 제안을 구분한다. 법률·스토어 적합성 판단은 하지 않았다.

## 1. 확인된 승인 사실

2026-11-18 06:08 UTC의 10개 추천에 사용자가 06:13 UTC ‘좋다. 다 니 추천이 맞아. 진행해봐.’라고 답했다. 06:25 UTC에는 실제 티켓 구현·테스트·코드/내용 리뷰와 문제 해결을 요청했다. Flutter/스토어 출시는 제외된다. 이전 티켓 본문의 ‘이번에는 백로그 생성만’은 생성 당시 실행 범위이며 최신 구현 지시를 부정하지 않는다. 하지만 아직 미정이라 명시한 세부 정책까지 확정되었다는 뜻은 아니다.

- 날짜 선택 입력. 모두 offline이어도 여행방/멤버십 유지. 관리자 종료는 읽기 전용, 관리자가 다시 활성화 가능.
- 카카오 로그인 후 초대 링크로 입장. 유효 링크는 별도 입장 승인 없이 사용. 관리자가 링크 폐기/재발급 및 멤버 내보내기.
- 방 생성자는 관리자. 자동 관리자 위임 없음. 직접 이양 후 관리자 퇴장/계정 삭제.
- 현재 멤버 누구나 판 생성/시작, 생성자는 해당 판 진행자. 참가자는 선택하고 시작 시 동결. 한 여행방 활성 판 1개.
- 진행자 최종 이탈은 해당 판의 남은 가능한 참가자에게 랜덤 위임. 적격자 0명 예외는 미정.
- 일반 결과는 현재 방 멤버, 재판 사건·상세·결과는 현재 방 멤버 AND 해당 판 참가자만. 관리자라는 이유로 재판 참가 조건을 우회하지 않는다.
- 방 퇴장 시 방/기록 접근 즉시 상실. 남은 사람의 공동 결과는 보존하되 탈퇴자 이름/아바타와 계정삭제의 세부 범위는 미정.
- 기존 쿠키로 증명한 자기 기록만 명시적 선택으로 계정 연결. 닉네임/링크만으로 복구하거나 기존 방을 여행방으로 자동 복원하지 않음.
- 팀/제비/재판 유지, 메뉴 추가 자체 승인. 메뉴 구체 규칙은 미정.
- 미공개 제비 참가자 단절 후 10분 미복귀면 그 판 미완료 종료. 이미 공개된 결과만 유지. 자동 공개/재배정 없음. 여행방 멤버십은 그대로.

## 2. 구현 가능한 권한·상태 기준

Account, TravelMembership, Presence, GameParticipant, Administrator, Facilitator는 독립 개념이다. 한 계정의 두 기기는 한 소속/한 참가자이지 두 명이 아니다. Presence timeout만으로 TravelMembership을 삭제하지 않는다.

| actor | 방/일반 결과 | 재판 상세 | 새 판 | 방 관리 |
|---|---|---|---|---|
| 비로그인/외부/퇴장 | 불가, 초대 최소 안내만 | 불가 | 불가 | 불가 |
| 현재 멤버·판 미참가 | 가능 | 불가 | active 방에서 가능 | 불가 |
| 현재 멤버·판 참가 | 가능 | 공개 가능한 해당 판 필드만 | active 방에서 가능 | 불가 |
| 관리자 | 위 조건과 동일 | 참가 조건 면제 없음 | 위 조건과 동일 | 수동 이양/설정/종료 |
| 진행자 | 위 조건과 동일 | 참가 조건과 공개 시점 유지 | 자신의 판 진행 | 관리자 권한 아님 |

여행방 설명상의 active → ended → active는 저장 상태 open → closed → open에 대응하며 기록 삭제가 아니다. 게임 run의 active 상태와는 별개다. ended에서는 게임·설정 변경을 차단하며 재활성화/관리자 이양 등 명시적 관리 명령만 허용 여부를 별도로 정의한다. 게임 terminal과 여행방 ended를 혼동하지 않는다. 메뉴 수집 단계도 활성 판 락에 포함해야 두 판이 동시에 수집/투표하지 않는다.

후발 현재 멤버의 일반 완료 결과 열람은 승인됐지만 미공개 제비는 결과가 아니다. 내부 배정, 당첨 잔여수, 작성자 연결 ID, 재판 목록 제목/썸네일로 권한을 우회하지 않는다. 제비 총 N이 이미 알려진 특성상 잔여값을 논리적으로 추론할 가능성 자체를 없앤다고 약속하지 않는다.

## 3. 메뉴 ADR 제안 (기존 확정 사실 아님)

### 목표
짧은 한 판으로 먹을 후보를 결정한다. 식당 예약/구매/건강 조건 판단은 범위 밖. 알레르기/질병/종교 등 민감정보 입력 필드나 ‘왜 못 먹는지’ 질문을 만들지 않는다. 결과는 식사 안전 보증이 아니다.

### 권장 최소 규칙
1. 시작 시 최소 2명의 선택 참가자를 고정한다. 각자 메뉴 1개 또는 명시적 ‘상관없음’을 제출한다. 후보 수·문자열 상한은 위임 구현 기본값으로 기록한다(예: 1–80 Unicode code points).
2. 제출 전에는 자기 입력만 보인다. 다른 사람의 메뉴·작성자·제출 순서·시각은 공개하지 않는다. 제출 후 수정 불가, 동일 명령 재시도는 멱등. 서버 접수 불확실하면 원래 요청만 재확인한다.
3. 모든 고정 참가자가 후보/패스를 제출하면 즉시 한 트랜잭션으로 마감한다. 기본 시간제한·진행자 강제마감은 없다. 미응답자를 자동 기권으로 바꾸지 않는다.
4. 같은 후보는 NFC, 앞뒤 공백 제거, 연속 공백 하나, Latin 대소문자 정규화로만 묶는다. ‘짜장면/자장면’ 같은 의미 동의어 병합, 기호 제거, AI 추천은 하지 않는다. 기준은 제출 전 안내한다.
5. 가장 많이 나온 후보를 선택하고, 최다 후보가 여러 개면 그 후보들 사이에서 균등 무작위로 딱 한 번 서버 결정·저장한다. 전체 후보 수가 1개면 그 후보, 전원 패스면 ‘후보 없음/결정 없음’으로 종료한다. 별도 투표 단계·재투표는 없다.
6. 현재 여행방 멤버에게 최종 선택 메뉴와 집계 방식만 공개한다. 다른 후보 목록/작성자/개별 패스는 최소안에서 공개하지 않는다. 이것은 더 강한 익명성 보증이 아니라 데이터 최소화다.
7. 메뉴에 벌칙 없음. 새 판은 새 ID이며 기존 결과 재추첨/덮어쓰기 불가. 진행자 교체는 수집 후보나 참가자 집합을 바꾸지 않는다.

### 수집 마감 대안 비교
- 전원 응답: 강제 배제·임의 시간 없음, 가장 작은 기본안. 단점은 응답 안 하는 사람이 있으면 멈춘다. 그러므로 출시 전 명시적 취소/이탈 예외 결정 필요.
- 진행자 ‘현재 제출로 결정’: 빨리 끝나지만 먼저 낸 후보가 유리하고 타인의 참여를 끊는다. 수집 시작 전 이 모드 안내/선택, 누락 인원 표시, 마감 경합 정의까지 필요하므로 기본 제외 권고.
- 정해진 시간 자동 마감: 대기 상한은 있지만 새 timeout·백그라운드·미응답 정책을 만든다. 현재 요구에 없으므로 제외 권고.
- 후보 공개 후 1인1표: 이해하기 쉽지만 단계가 늘고 전략 투표/동률/미응답 처리가 추가된다. 이번 최소안은 후보 빈도를 선호 표현으로 사용하고 별도 투표를 만들지 않는 쪽을 추천.

빈도 우선 규칙도 이전 추천일 뿐 사용자 확정이 아니다. 일반 자율 구현 위임으로 채택한다면 ADR에 ‘구현자가 선택한 기본값’과 게임 시작 전 규칙 안내를 명시해야 한다. 기존 #135가 별도 승인 ADR을 요구하므로 담당 조정자가 위임 범위를 명시적으로 판정하기 전 #136을 완료 처리하지 않는다.

### 최소 반례/검증
0 후보(전원 패스), 1종 후보, 서로 다른 후보 동률, 같은 후보 최다, 모든 공백, NFC 분해문자, emoji 경계, 악성 HTML 문자(텍스트 렌더), 과도한 길이, 다른 계정 사칭, 후발 참가 요청, 두 기기 중복/상충 제출, 마지막 제출/취소 경합, 재시작 후 결과·난수 재선택 금지. 수집 중 raw 제출 내용이 목록/에러/로그/공유 프리뷰에 새지 않는지 검사.

## 4. 보수적인 임시 보호와 진짜 결정 게이트

아래 임시 보호는 제품 정책 최종 완료가 아니다. 독립 기능 진행을 허용하고 관련 AC만 열린 상태로 둔다.

| 미정 경계 | 추천/임시 보호 | 실제 차단 범위 |
|---|---|---|
| 마지막 관리자/유일 멤버 퇴장 | 자동 삭제·임의 위임 금지. 일반 퇴장은 이양까지 거부, 유일 멤버는 여행 종료 후 본인 소유 읽기전용 유지 옵션 | 계정 삭제를 영구 차단하는 해결책으로 삼지 않음. 유일 멤버 계정 탈퇴/삭제는 별도 정책 확정 필요 |
| 활성 판 중 여행 종료 | 판 terminal이 될 때까지 종료409 권고. 자동 무효/벌칙 판정 금지 | 게임 진행/결과 기록 가능, 강제 종료는 미정 |
| 활성 판 참가자 추방/명시적 탈퇴 | 접근 철회와 게임 결과 처리 분리. 임의로 10분 timeout과 같다고 간주 금지 | 미공개 제비·진행자0명·메뉴 미응답자 예외의 해당 명령 정책 |
| 종료 방 초대 입장 | 임시 거부, 관리자 재활성화 후 입장 | 읽기전용 기존 멤버 기록 조회는 계속 가능 |
| 추방자 새 링크 재가입 | 추방 이유만으로 영구 account ban 발명 금지; 재입장 경로는 gate로 차단하거나 별도 관리 해제 요구안 제시 | 관리자가 차단한 사람의 자동 재허용 정책 |
| 나간 사람 표시 | 서버 데이터 삭제 없이 표시 이름 ‘나간 참가자’/기본 아바타로 대체하는 projection 제안 | 실제 비식별 완료 주장 금지. 자유 텍스트에는 이름이 남을 수 있음 |
| 재가입의 옛 재판 권한 | 새 membership을 이전 GameParticipant와 자동 연결하지 않음 | 같은 account_id join만으로 옛 참가 권한을 되살리지 않는 회귀 필요; 권한 회복 여부 결정 |
| 계정 삭제/공동 기록/백업 | 자동 삭제·익명화 완료 약속 금지. 삭제 범위/실패 복구/백업 복원 뒤 삭제 재적용 설계 | #119/#138의 파괴적 동작. 추천만으로 실행 금지 |
| 보관기간/용량 | 숫자 임의 확정·오래된 기록 자동 정리 금지. ‘영구 보장’ 문구도 금지 | #116/#140 실제 운영 상한·보관 AC |
| 재판 피고 이탈 후 중단 필드 | 기존 #33 보수적 비공개 유지. 여행방 관리자가 일반 결과로 우회 열람 불가 | 이미 공개된 1차 결과도 중단 후 공개 허용 자동 승계 금지 |

진행자 적격자 0명은 임시 vacancy로 두고 사용자 입력을 위조하지 않는 쪽이 안전하다. 그러나 메뉴 전원 응답 대기와 결합하면 무기한 락이 생길 수 있으므로 메뉴 기능 출시에는 명시적 취소 주체/미완료 처리 정책이 필요하다. 자동으로 결과를 추첨해 해결하지 않는다.

## 5. 지금 병렬로 진행해도 되는 부분
계정·세션, 영속 소속/접속 분리, 관리자 수동 이양, inactive 판이 없는 여행방 종료/재활성화, 한 판 락, 참가자 동결, 일반/재판 projection, 초대 최소 안내, 기존 기록 선택 연결 및 비파괴 마이그레이션은 위 미정 항목과 분리 가능하다. 메뉴 입력/후보 유효성/저장소·가상 프로토타입은 가능하나 추천을 확정으로 표시하거나 실제 규칙 구현 완료로 주장하지 않는다.

## 후속 상태 정정

메뉴의 진행자 명시적 미완료 취소는 ADR 0020에서 자율 위임 기본값으로 채택했다. 위 3~4절의 취소 미정/프로토타입 한정 설명은 채택 전 역사이며 현재 구현을 차단하지 않는다. 진행자 적격자 0명, 삭제·보관·명시적 탈퇴의 세부 정책은 계속 게이트로 남는다.
