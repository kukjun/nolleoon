# Party UI · 화면과 상태 계약 (#77)

상태: 승인한 시각 방향의 구현 기준. 개별 게임 서버 정책과 API가 최종 권한이며 이 문서로 새로운 게임 규칙을 만들지 않는다.

## 화면 구조

모바일 320/390px에서 한 화면의 현재 행동을 우선한다. 폼 카드의 연속 대신 캐릭터가 모인 대기실을 중심으로 입장 → 대기실 → 게임 선택 → 준비 → 플레이 → 결과 → 같은 방의 다음 게임을 잇는다. 준비 완료 토글이나 전원 ready 같은 새 규칙은 추가하지 않는다. 방장 권한과 게임 역할은 분리한다.

| 화면 | 주요 행동 | 보조 정보 | 잠김/대기/실패 |
|---|---|---|---|
| 입장 | 닉네임·아바타 선택 후 참여 | 사진 제한·신원 복구 경계 | 저장 중 제출 잠금, 실패 시 선택 유지 |
| 대기실 | 방장 게임 선택 | 초대·참가자 상태·나가기 | 참가자는 방장 진행 대기, 연결 불명 상태를 연결됨으로 표시하지 않음 |
| 게임 선택 | 팀 나누기/인원 추첨/재판 중 선택 | 각 게임 규칙 | 서버가 이미 진행 중이면 해당 게임으로 복귀 |
| 재판 설정 | 사건·벌칙·시간 저장 | 이전 저장값 보기 | 미저장 입력 보존, 저장 성공 전 다음 행동 제한 |
| 역할·동의 | 본인 역할, 피고의 최신 벌칙 확인 | 전체 벌칙과 역할 상태 | 벌칙/피고 변경 시 서버 수락 무효화 반영 |
| 변론 | 피고 변론 또는 건너뛰기, 방장 투표 개시 | 사건·합의 벌칙 | 변론 선택, 다른 사람의 입력은 기다림 |
| 투표 | 판단·이유 제출 | 사건·변론, 이전 공개 라운드 | 자신의 접수 이후 변경 불가, 타인 현재 표/이유 비공개 |
| 재판 결과 | 같은 방 다음 게임 | 라운드별 익명 이유·기록 | 첫 동률이면 최후 변론으로 이동, 두 번째 동률 무죄 |
| 팀 준비/결과 | 팀 수 설정·서버 배정 | 확정 참가자와 각 팀 | 인원 균형·벌칙 없음, 결과를 브라우저가 생성하지 않음 |
| 제비 준비 | 당첨 수·대상·벌칙 전문 확인 | 본인에게 배정된 한 장 | 여러 장 중 선택하지 않음 |
| 제비 플레이 | 본인의 한 장만 뒤집기 | 다른 사람 대기/뽑기완료 | 자기 행동이 타인 결과를 공개하지 않음, 미공개 장기이탈 정책 미정이면 임의 완료 금지 |

## 가독성과 행동

- 기본 문장 16px, 보조 정보도 명료한 대비. 잉크/배경·보조/배경·흰색/강조색 WCAG 일반 텍스트 대비 4.5 이상을 토큰 테스트로 확인한다.
- 터치 목표 48px, 최소 44px. 좁은 화면에서도 버튼의 실제 DOM 순서와 시각 순서가 같다.
- 화면당 대표 행동은 하단 dock. safe-area를 포함하고 본문에 같은 높이 여백을 확보한다. 키보드·확대·짧은 화면에서는 입력과 버튼을 스크롤로 접근할 수 있어야 한다.
- 이전 단계 전문은 보조 패널에서 확인. 합의/선택에 필요한 벌칙 전문은 확인 행동과 같은 단계에 노출한다. 긴 내용을 잘라 없애지 않는다.
- 단계 이동은 사용자가 실행한 때 제목으로 초점 이동. polling은 입력·초점·스크롤을 빼앗지 않는다. 실패/재연결은 마지막 서버 상태와 오류를 함께 표시한다.
- 전환 애니메이션은 보조적이며 reduced-motion을 따른다. 색만으로 선택/접수/연결 상태를 구분하지 않는다.

## 아바타와 개인정보

입장·방·진행·결과에서 같은 참가자를 같은 아바타로 표시한다. 아바타는 방/세션 권한으로 조회하고 익명 표·익명 이유에 연결하지 않는다. 프리셋 미로딩은 이니셜 대체. 실제 사진을 저장하기 전 공유 범위를 안내한다. 과거 기록의 현재 아바타 표시 여부는 아바타 API 계약을 따른다.

제비의 미공개 결과를 비밀 보장이라고 부르지 않는다. 정해진 당첨 수와 공개된 결과로 남은 결과가 추론될 수 있다.

## 검사 경계

현재 #77은 토큰/상태 설계 기준만 추가한다. 실제 새 화면, 모바일 브라우저, 서버 동기화/재연결, E2E, 실기기, 운영 배포 통과를 뜻하지 않는다. 다음 이슈에서 기능별 RED→GREEN과 스크린샷을 남긴다.
