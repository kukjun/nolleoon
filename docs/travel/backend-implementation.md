# 여행방 백엔드 실행 · #121 / #125 / #126 / #127 / #129

상태: 승인 범위 구현 중. 운영·카카오 외부 앱 설정·배포·파괴적 삭제는 하지 않는다.

기존 브라우저 세션·방·게임·사진의 ID와 데이터를 그대로 두고, 계정 인증과 여행방은 별도 additive schema로 만든다. 기존 방을 여행방으로 자동 재생성하지 않는다. 여행방 멤버십은 연결 상태와 독립이며 오프라인이 오래되어도 소속이나 관리자 권한을 자동 삭제/위임하지 않는다.

## 보수적 미정 경계
- #119 확정 전 활성 판이 있는 방의 종료·추방·명시 탈퇴를 차단한다.
- 관리자는 이양 전 탈퇴할 수 없으며 마지막 관리자도 예외로 삭제하지 않는다.
- 재가입에 따른 과거 권한 복원·추방 후 재입장 정책은 미정이라 이전 멤버십이 있는 계정의 새 가입을 차단하고 결정 필요로 남긴다. 영구 밴 정책으로 확정한 것이 아니다.
- 참가자 없는 진행자 위임은 자동 종료/삭제하지 않는다. 안전한 대상이 있을 때만 한 판 진행자를 변경하고 방 관리자는 유지한다.
- 비참가 진행자는 단계 제어만 가능하고, 민감 재판 상세·결과·투표·변론 권한은 별도로 차단한다. 참가를 강제하지 않는다.

## 완료 증거
기능별 실패 사례 → 구현 → 단위/저장소/API 검증을 기록한다. 아래 엔진 port만으로 실제 게임 동작을 완료했다고 보고하지 않는다. 등록되지 않은 게임 엔진은 실패 처리한다. 공개 응답에 raw state/settings/result를 그대로 직렬화하지 않는다.

비참가 진행자는 단계 제어만 허용하며 재판 민감 상세·결과·투표·변론은 참가 권한과 분리한다. 진행자를 참가자로 강제하지 않는다.

초대 토큰은 해시만 저장한다. 발급 응답을 잃은 동일 requestId 재시도는 토큰을 재공개하지 않고 STATE_CONFLICT를 반환한다. 관리자가 새 requestId로 재발급하면 이전 링크는 폐기된다.
