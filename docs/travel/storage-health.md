# 읽기 전용 백업·용량 상태 확인

`node tools/storage/storage-health.mjs <원본DB절대경로> <전용백업디렉터리> <budget.json>`

명시적으로 전달한 로컬 경로만 읽는다. 스케줄 설치, HTTP 호출, 원장 초기화, DB/백업 삭제·복원·수정은 하지 않는다. 정상 검사 종료 코드는 0, 상태 불량은 2, 잘못된 호출/예산은 1이다. 결과에는 상태 코드와 크기·경과시간만 있고 경로/파일 내용/식별자/비밀은 없다.

## 무엇을 확인하는가

- 백업 디렉터리의 원본 binding이 현재 realpath/device/inode와 같은지 확인한다.
- 관리 snapshot과 manifest가 일반 파일이고 SHA256이 맞는지 streaming으로 확인한다. 활성 daily lock, 누락/손상 manifest, 미래 시각을 정상으로 간주하지 않는다.
- 신규 일일 manifest에는 `createdAt`(호출 시작 시각, epoch ms)을 기록한다. 최신 백업의 경과가 **24시간 초과**이면 `BACKUP_STALE`이다. 기존 시각 없는 manifest는 자동 변경하지 않고 `BACKUP_TIME_UNKNOWN`으로 표시한다. 날짜만으로 최근 24시간을 증명하거나 mtime을 생성 시각으로 오인하지 않는다.
- 현재 DB/WAL bytes, 관리 백업과 manifest 합계, 원본/백업 볼륨의 최소 가용 공간을 관측한다. 수치는 순간 관측이며 동시 쓰기나 미래 사용량을 예약하지 않는다.
- SHA256 일치는 manifest와 파일의 일치일 뿐 SQLite 무결성 또는 복원 성공 검증이 아니다. 실제 무결성/스키마/FK는 기존 온라인 백업/검증된 복원 경로가 담당한다.

## 예산과 운영 경보

`budget.json`은 양의 안전한 정수인 `databaseBytes`, `walBytes`, `backupBytes`, `minFreeBytes`를 모두 요구한다. 예를 들어 소규모 시험 운영에서 1GiB DB / 256MiB WAL / 8GiB 관리 백업 / 2GiB 여유 공간은 **검토용 시작 예시**다. 승인된 전체 저장 용량 상한이나 프로세스 메모리 제한이 아니다. 호스트 실제 저장 공간·백업 크기·쓰기량 측정 뒤 운영자가 확정해야 한다. 도구는 quota를 적용하거나 오래된 데이터를 임의 삭제하지 않으며 `hardLimitEnforced:false`를 항상 반환한다.

이 검사 역시 자동으로 실행하거나 알림을 전달하지 않는다. 운영 스케줄을 별도로 승인·설치한 뒤 실패/24시간 경과를 사람에게 전달하는 경로, Mac sleep/로그인/저장장치 연결 조건, 전달 실패 점검이 필요하다. 백업을 같은 UTC 날짜에 재실행해도 그날 기존 snapshot을 재사용하므로 지연/누락을 감추지 않는다. 24시간 RPO를 유지하려면 백업 직후 성공 상태뿐 아니라 다음 실행 누락도 감시해야 한다.

## 해결하지 않는 출시 게이트

`healthy`는 이 로컬 파일/용량 검사 범위다. `restoreFreshnessVerified:false`는 항상 유지한다.

기존 삭제 원장 hash chain·checkpoint, DB schema17의 필수 원장 binding/알려진 prefix, 두 원장 잠금 아래 복원→방 replay→계정 replay→VACUUM→검증→no-clobber 게시 및 solo 방 7일 기한 보존은 합성 시험으로 구현되어 있다. 이를 새 도구로 중복하거나 약화하지 않는다.

그러나 DB·원장·anchor 전체가 함께 과거로 돌아간 경우 로컬 관측만으로 최신성을 증명할 수 없다. 독립 authoritative 최신 checkpoint 보관 주체·위치·복원 시 검증 책임, 손상/중단 시 수동 절차, 실제 운영 스케줄/알림 전달은 여전히 필요하다. 잘못된 empty ledger를 '복구'로 만들지 않고, 예전 바이너리/단순 파일복사로 삭제 검증 경로를 우회하지 않는다. 실제 운영 백업/복원과 삭제, 외부 보관/암호화/OS 권한 변경은 이번 작업에서 수행하지 않았다.

SQL 논리삭제/복원본 재구성은 디스크 잔여 바이트의 즉시 물리 삭제 보장이 아니다. 최근 7일 백업 정책도 이 차이를 없애지 않는다.
