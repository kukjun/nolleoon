# 카카오 연결 해제 재시도: #155

2026-11-18 승인 정책: 로컬 계정·글·사진·인증 삭제는 원격 응답을 기다리지 않는다. 실패한 카카오 연결 해제를 위해 별도 현재 큐에 회원번호를 최대 7일 보관한다. 대기 중 같은 회원번호의 가입을 막고, 성공 또는 7일 만료 시 회원번호와 관련 조회용 매핑을 지운다. 만료는 연결 해제 성공으로 표시하지 않으며 비식별 운영 알림만 남긴다.

## 순서와 경계

1. 인증·CSRF·권한·삭제 범위를 확인한다.
2. SQL transaction 안에서 별도 authoritative 큐에 최소 intent를 fsync 준비한다. 실패하면 원장/로컬 삭제를 하지 않는다.
3. 개인번호 없는 계정 삭제 원장을 fsync한 뒤 기존 로컬 삭제를 commit한다. 큐만 준비되고 원장이 실패한 orphan은 원격 호출하지 않는다.
4. worker가 현재 원장의 동일 operation·최초 시각·7일 기한을 확인하고 큐 lease를 잡은 후 transaction 밖에서 unlink를 요청한다.
5. 실패는 큐에 재시도 상태를 보존, 성공은 회원번호 즉시 삭제. provider 미설정이어도 만료 청소는 실행한다. 마감 직전 10초에는 새 원격 요청을 보내지 않는다.

재시도는 최초 deadline을 연장하지 않는다. 원장/SQL 실패 후 같은 요청은 canonical intent를 재생한다. OAuth callback의 최종 가입 transaction 전에 현재 큐의 동일 subject 대기 여부를 다시 검사하므로 늦게 도착한 로그인도 차단한다. 만료/성공 뒤 가입은 새 account ID이며 과거 삭제 자료를 복원하지 않는다.

schema18은 큐의 필수 여부·경로 binding hash·비식별 journal head만 보관한다. 한번 활성화하면 설정이 사라지거나 이전 authority로 바뀐 서버는 기동/요청을 거절한다. 회원번호 또는 그 조회용 hash는 SQLite·영구 삭제 원장·DB 백업에 넣지 않는다. 큐 자체를 DB와 함께 복원하지 않는다. 복원은 별도 현재 authority를 검증해야 한다.

## 운영·검증 한계

- 큐/원장 저장장애는 503 등으로 닫힌다. '즉시 삭제'는 저장안전성 검증 없이 삭제한다는 뜻이 아니다.
- Admin key 미설정이면 원격 요청은 하지 않고 대기/만료 상태만 관리한다. 완료라고 보고하지 않는다.
- 현재 구현시험은 가짜 fetch/합성 DB 및 로컬 HTTP만 쓴다. 실제 연결 해제·키 설정·운영 배포는 실행하지 않았다.
- provider timeout은 원격 처리 취소를 보장하지 않는다. 5초 요청 제한 및 마감 전 10초 안전 여유가 있지만 카카오 서버가 응답 유실 뒤 늦게 처리하는 경우까지 로컬 transaction처럼 원자적이라고 주장하지 않는다.
- 서버가 꺼져 있으면 삭제 작업을 실행할 수 없다. 재기동 때 listener 전에 만료 청소가 필요하며 외부 운영 점검은 만료 잔존/큐 오류를 탐지해야 한다.
