# 여행방 릴리스 준비와 남은 게이트

이 문서는 운영 적용 완료 보고가 아니다. 기존 배포·SQLite·브라우저 세션은 이번 개발 동안 변경하지 않았다. React 웹만 대상으로 하며 Flutter와 스토어 출시는 제외다.

## 분리와 보존

- 신규 계정·여행방 UI는 `/travel` 경로다. 기존 `/`와 query 기반 초대/기록 흐름은 보존한다. 루트 전환은 실제 출시 계획에서 별도 명시해야 하며 조용히 기존 링크를 바꾸지 않는다.
- schema 12–14는 계정/여행방/명시적 과거 연결/계정 사진을 추가한다. 기존 방을 재생성하거나 익명 사진을 자동 복사하지 않는다. 기존 배포 schema 11의 모든 테이블 fixture·세션·이미지 bytes와 manifest 보존 시험이 있다.
- 온라인 SQLite backup API로 새 대상에 일관된 스냅샷을 만들고 검증한다. 현재 백업 검증기는 명시된 schema 9/11 및 최신 schema만 허용한다. 원본이나 기존 백업을 덮어쓰지 않는다.
- 실제 전환 전 진행 중 게임/접속을 확인하고 쓰기를 멈추는 유지보수 구간을 정한다. 운영 경로·자격증명·사용자 데이터는 공개 저장소나 시험 로그에 넣지 않는다.
- 새 릴리스와 별도 복원본으로 사전 검증한 뒤 적용한다. 이전 바이너리를 최신 schema DB 위에 무조건 실행하지 않는다. 백업 복귀는 백업 이후 새 데이터 유실 가능성이 있으므로 자동 rollback으로 간주하지 않고 중단·보존·결정을 우선한다.

## 출시 차단 또는 별도 인수

- #122/#123: 실제 카카오 앱의 공식 설정·callback 일치·인증/취소/오류·모바일 앱 전환 후 복귀 검증. 합성 provider 성공은 이를 대체하지 않는다. 필수 설정이 없으면 provider 미구성 오류로 안전하게 거절한다.
- #119/#138: 계정 탈퇴/공동 자유 텍스트/백업 삭제와 마지막 관리자·활성 판 도중 종료·재가입 권리의 확정 정책. 미결 파괴적 처리는 구현·운영 실행하지 않는다. 현재 활성 판 중 탈퇴/추방/방 종료와 관리자 이양 없는 탈퇴는 보수적으로 차단한다.
- #116/#140: 전체 DB/WAL/백업/메모리 예산·보관기간·복구 목표. 이미지의 개별/논리적 BLOB quota는 전체 자원 상한이 아니다. 자동 기록 삭제를 사용하지 않는다.
- #36: 원격 CI workflow 권한 차단. 로컬 하네스 결과를 원격 CI로 보고하지 않는다. 인증·보호 설정을 우회하지 않는다.
- #142: 물리 iPhone/Android, 실제 카카오 복귀·접근성 인수. Chromium 모바일 viewport는 실기기가 아니다.
- #143/#144: 정확한 RC의 독립 리뷰·전체 회귀 및 실제 외부 두 사용자 흐름, 운영 관측과 복구 준비. 모두 충족하기 전 전체 완료나 안전한 운영 출시를 선언하지 않는다.

## 실제로 검증하는 범위

임시 합성 DB에서 unit/API/native SQLite와 production static route를 검사한다. 실 브라우저 E2E는 실제 Nest/SQLite/Sharp 및 여러 browser context를 사용하고 로그인 제공자만 합성으로 대체한다. 모의 API UI 시험과 구분한다. 정확한 commit 및 결과는 작업 기록과 하네스 report에 남긴다. 결과 스크린샷은 합성 사용자 데이터만 사용한다.
