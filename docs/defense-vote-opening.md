# 변론과 첫 투표 개시 (#14)

현재 피고는 선택적으로 변론을 제출하거나 건너뛴다. 변론 별도 타이머는 없다. 방장은 피고가 아무 응답을 하지 않아도 첫 투표를 시작할 수 있다. 투표 접수/집계는 #15/#16 전에는 구현하지 않았으며 마감 시 결과를 가장하지 않는다.

## 명령과 상태

별도 `TrialProgress` 유스케이스가 게임 ID·현재 멤버십·게임 참여 역할과 낙관적 expectedVersion을 확인한다. 경로는 `/api/rooms/:code/games/:gameId/…`다. 옛 게임 요청이 다음 게임에 적용되지 않는다.

- `defense`: `{roundNumber: 1 | 2, expectedVersion, action: 'submit'|'skip', text}`. 피고 본인만 가능하다. 제출은 1~5,000 코드포인트의 비어 있지 않은 내용, skip은 빈 문자열이다. 줄바꿈/탭 외 제어문자는 거부한다.
- `duration`: `{expectedVersion, durationMinutes}`. 방장만 첫 투표 전 1~10분 정수로 변경한다. 사건·벌칙·명단은 바꾸지 않는다. 같은 시간 저장은 no-op이다.
- `open-vote`: `{roundNumber: 1 | 2, expectedVersion, requestId}`. 방장만 변론 단계에서 시작한다. 변론 제출/skip은 시작 전제조건이 아니다.

권한, 게임 상태, 버전, 첫 라운드 존재 여부를 한 transaction에서 재검사한다. 변론 제출과 개시, 시간 변경과 개시가 경합하면 하나만 이전 버전을 사용할 수 있다. 개시가 먼저면 늦은 변론은 충돌로 거절한다. 수정이 먼저면 방장은 최신 내용을 확인해 다시 개시한다. UI의 비활성 버튼은 권한 검사의 대체물이 아니다.

## 단일 마감과 재시도

migration 6은 defenses와 vote_open_receipts를 추가한다. 개시 transaction은 첫 round의 startedAt/deadline, 게임 voting 상태와 버전, 요청 영수증을 함께 저장한다. 실패는 전부 롤백한다. deadline은 서버 now + 현재 게임 duration이며 저장 후 재시도·서버 재시작으로 연장하지 않는다. 동일 게임·요청 ID의 같은 요청자/의도만 재확인할 수 있고 새 ID의 중복 개시는 충돌이다.

첫 라운드가 생기면 시간 변경 endpoint는 닫힌다. 후속 두 번째 투표도 이 게임의 고정 duration을 사용해야 한다. 조기 수동 종료 endpoint는 없다. 현재 시간이 deadline에 도달해도 #16 정산 구현 전에는 게임 상태를 결과로 바꾸지 않는다.

## 화면 시간과 공개 범위

snapshot은 서버 시각 serverNow와 저장된 deadline을 준다. 브라우저는 수신 시 performance.now를 기준으로 단조 증가 경과 시간을 계산하므로 기기 Date.now/시간대 변경이 마감 기준을 바꾸지 않는다. 표시 시각은 네트워크 응답 지연과 폴링 전파 지연을 포함하므로 모든 화면 픽셀이 동시에 바뀐다는 보장은 아니다. 복귀 시 최신 snapshot으로 보정하며 통신 실패는 기존 재연결 안내를 유지한다. 0초에는 서버 마감 처리 대기라고 표시하고 허위 결과/투표 접수 버튼을 제공하지 않는다.

변론은 현재 게임 참여자에게 공개된다. 아직 진행 중인 표수·투표 이유는 반환하지 않는다. 종료 후 새 방 참가자와 미정 중단 상태의 비공개 경계는 #13 그대로 유지한다.

## 검증

API 시험은 피고/방장 권한, 선택적 submit/skip, 무응답 개시, 시간 범위, 같은 개시 요청 경합, 시간/변론 개시 경합, 마감 불변과 늦은 요청 차단을 확인한다. 임시 DB는 개시 중 실패 rollback·재시작 동일 deadline·옛 게임 요청의 다음 게임 격리를 검사한다. 브라우저는 다중 컨텍스트 같은 deadline·기기 시계 변경·오프라인 복귀·동일 요청 재시도·0초 대기 표현을 검사한다. 전체 한 판·실기기/백그라운드 OS·외부 배포는 아직 별도다.

## 화면 확인

390px Chromium 화면의 `artifacts/trial/voting-mobile.png` 영역을 직접 확인했다. 무변론 개시 안내, 1차 서버 기준 마감, 남은 시간, 아직 투표 접수 화면이 없다는 설명이 가로 잘림 없이 읽힌다. 실제 기기 검증은 아니며 0초 대기 UI는 별도 응답 fixture로도 확인했다.

방장 시간 입력은 저장된 값과 미저장 값을 구분한다. 다른 탭에서 시간을 저장하면 편집하지 않은 입력은 최신 값으로 갱신된다. 편집 중인 값은 유지하고, 저장 또는 명시적 취소 전에는 투표 개시를 막는다. 시간 입력에 숫자를 적기만 해도 서버 마감이 바뀐 것처럼 표시하지 않는다. 이 회귀 시험은 다른 탭 저장 후 5분이어야 할 입력이 3분에 남는 실패를 재현한 뒤 통과했다.

#17부터 명시적 roundNumber가 필수이며 2차 흐름은 [최후 변론과 재투표](final-defense-revote.md)를 따른다. 위 #14 당시 화면 검증은 역사적 기록이다.
