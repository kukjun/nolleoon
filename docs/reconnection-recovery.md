# 재접속·화면 복귀·신원 소실 (#19)

## 복구할 수 있는 상태

유효한 같은 브라우저 쿠키와 기존 멤버십이면 서버의 역할·동결 투표 자격·이미 접수한 표·원래 deadline을 다시 읽는다. 재방문이나 온라인 복귀가 새 투표 시간을 만들지 않는다. 같은 닉네임은 신원 복구 수단이 아니며 새 브라우저는 기존 역할/표를 가져오지 못한다.

API 시험은 서버가 단절을 감지한 뒤 유예 안의 재접속과 결과 단계 재접속을 검사한다. 감지 시각부터 599,999ms 시점에도 동일 멤버십·접수·deadline을 확인한다. 10분 이상 단절 시 퇴장 처리는 #20의 범위이며 이 단계에서 경계 이후의 자격을 보장하지 않는다.

## 안전한 세션 갱신

초기 GET 세션 확인과 기존 POST 발급 사이에 쿠키가 사라지면 과거 흐름은 새 신원을 자동 발급할 수 있었다. 신규 `POST /api/session/renew`는 유효한 기존 토큰만 한 트랜잭션에서 검증하고 90일 유효기간을 연장한다. 누락·위조·만료는 SESSION_REQUIRED이며 새 세션 행과 Set-Cookie를 만들지 않는다. CSRF·빈 본문·HttpOnly/Secure/SameSite 및 no-store 규칙은 그대로다. 신규 신원은 명시적인 시작 버튼의 `POST /api/session`으로만 발급한다. 기존 90일 갱신 정책을 조용히 폐지하지 않는다.

새 endpoint 부재의 실제 RED(404, 기대401)를 확인한 뒤 유효 갱신/누락/만료/CSRF/추가 필드 거부와 행 수 불변 시험을 통과했다. 토큰은 JSON·URL·로그에 싣지 않는다.

## 화면 및 검증 경계

pageshow·가시성 복귀·focus·online에서 서버 상태를 다시 확인한다. 네트워크 오류와 신원 소실을 구분한다. 신원 소실은 이전 민감 게임 화면을 제거하고 자동 폴링을 중단하며 쿠키 소실/만료와 닉네임 복구 불가를 안내한다. 새 신원 발급은 자동으로 실행하지 않는다. 이전 인증 세대에서 늦게 온 응답이 새 신원을 지우지 않도록 세대를 확인한다.

실제 Back/Forward·reload와 브라우저 이벤트 기반 재동기화는 자동 시험 증거로 구분해 기록한다. synthetic pageshow/visibility 이벤트가 실제 모바일 OS 잠금·BFCache 진입을 증명하지는 않는다. 실제 네트워크·실기기 잠금 시험은 후속 검증이며, 이 티켓의 자동 회귀 통과로 운영 MVP 전체 완료를 주장하지 않는다.

취소된 이전 요청의 늦은 401이 transport에서 신원 소실을 통지하던 RED(1회, 기대0)를 재현하고 signal 검사로 차단했다. Auth 세대와 별도로 probe 순서를 확인하며, probe 교체·신원 소실·명시적 발급·화면 정리 때 이전 갱신 요청을 실제 abort한다. 처음 신원이 발급되기 전 네트워크 실패는 이전 게임 손실로 안내하지 않도록 유효 신원 확인 여부를 따로 기록한다.
