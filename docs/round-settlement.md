# 라운드 자동 마감과 집계 (#16)

## 규칙

시작 때 고정한 투표 대상 전체가 직접 제출하면 즉시 마감한다. 직접 기권도 제출이다. 일부 미제출이면 서버 deadline에 마감하고 미제출 수를 기권으로 계산한다. 퇴장·단절로 투표 대상 총수를 줄이지 않는다. 미제출을 `votes`에 가짜 투표로 삽입하지 않으므로 자기 접수 영수증도 생기지 않는다.

유죄 G와 무죄 N만 비교한다. G>N 유죄, N>G 무죄, G+N=0 무판결이다. G=N>0인 첫 라운드는 최후 변론 대기로 넘어간다. 같은 조건의 2차 동률은 무죄라는 순수 규칙을 시험하지만 실제 2차 개시 흐름은 #17에서 연결한다.

## 원자성과 복구

`settleRound`는 외부 I/O 없는 트랜잭션 함수다. SubmitVote의 마지막 삽입과 같은 SQLite immediate 트랜잭션·같은 서버 시각으로 집계한다. 마지막 표 저장 후 정산이 실패하면 표·결과·마감시각·게임상태 모두 rollback한다.

별도 `SettleRounds` 유즈케이스와 1초 `SettlementMonitor`는 클라이언트 polling 없이도 열린 투표 라운드를 검사한다. 서버 시작 시 즉시 검사하고 종료 시 timer를 해제한다. 실패는 원문 정보 없는 고정 사건명만 기록하고 다음 tick에 재시도한다. 재시작 뒤에도 DB의 열린 라운드를 다시 검사한다. 실제 탐지/처리 지연만큼 `closedAt`은 deadline보다 늦을 수 있으며, 새 표 접수 허용 경계는 항상 원래 deadline이다.

추가 migration 7은 `round_settlements`를 만든다. 게임/라운드 unique, 집계 합계 CHECK, update/delete 금지 trigger로 결과를 불변으로 보존한다. 과거 migration은 변경하지 않는다. `rounds.closed_at`·게임상태·공용 version 변경은 정산과 함께 커밋된다. 중복 worker와 재접수는 같은 결과를 다시 생성하지 않는다.

## 공개와 화면

완료된 현재 라운드만 `settlement`의 판정·G/N/A·고정 총수·마감시각/사유를 반환한다. 진행 중은 null이며 개인 제출 수를 공개하지 않는다. 이유 목록은 아직 제공하지 않는다. 첫 동률에서는 1차 변론/투표 버튼을 재사용하지 않고 최후 변론 대기를 명시한다. 미정 중단 이력 #33의 기존 기본 비공개는 유지한다.

정산 worker가 먼저 마감한 뒤 온 미제출 요청도 실제 deadline이 지났다면 `DEADLINE_PASSED`다. 기존 본인 동일 의도 접수 재확인은 먼저 처리하여 계속 성공한다. 이 순서의 회귀에서 STATE_CONFLICT가 반환되는 RED를 확인한 뒤 수정했다.

## 실행 증거

- 최초 순수 집계 RED: tally 모듈 미구현으로 실패.
- 단위: 유효표 비교·무판결·1/2차 동률, monitor timer/오류 비공개/종료.
- 실제 API: 마지막 두 표 동시 요청, 전원 직접 기권, 첫 동률, 요청 없는 독립 monitor 마감, 마감 후 지연 POST.
- 실제 임시 SQLite: G1/N0/A3, 퇴장 후 총수 유지, 두 연결의 정산 중복·선착순 경계, 중간 실패 전체 rollback, 불변 trigger, 재연결 결과 보존.
- 실제 Chromium: 전원 제출 자동 유죄, 첫 동률에서 미구현 조작 없음, 전원 기권 무판결. 마감 테스트를 빠르게 만들려고 실제 시간을 줄인 browser fixture는 사용하지 않았다. deadline은 API의 주입 시계+실제 timer로 검증한다.

`artifacts/settlement/result-mobile.png`를 직접 확인했다. 390px viewport의 300px 본문에서 유죄/무죄/기권 3열 수치와 총수·집계 완료 안내가 잘리지 않고 읽힌다. 실기기 검증은 아니다. 전체 한 판·2차 실제 흐름·이유 공개·외부 배포는 아직 완료가 아니다.
