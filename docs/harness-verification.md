# 검증 하네스 실행 근거

## v0에서 유지한 발견

- Node 시험 안의 자식 러너는 NODE_TEST_CONTEXT를 제거해야 독립 TAP을 출력한다.
- 빈 파일도 Node가 암묵적 파일 시험으로 집계하므로 단순 testCount > 0으로 합격시키지 않는다.
- 하네스/출력 검사는 샌드박스나 제품 전체 인수의 대체물이 아니다.

## MVP-03 RED와 변경

기존 runner에 실행불가 blocked, TODO/skip 개수, Playwright JSON 정규화 시험을 추가했을 때 12개 중 3개가 실패했다(종료 코드 1). fake 대역 파일 없는 상태의 단위 시험도 ERR_MODULE_NOT_FOUND로 실패했다. 이후 상태·개수 어댑터와 대역을 구현했다.

기존 v0의 skip·누락 파일 모두 failed 판정을 각각 incomplete·blocked로 구분하도록 시험 기대값을 변경했다. 두 상태 모두 필수 검사의 합격이 아니므로 전체 check는 실패한다. 검증을 성공으로 완화한 것이 아니다.

범위: GetHealth 단위, 실제 Nest HTTP 헬스/404 통합, Chromium에서 React 초기 화면 렌더. SQLite/게임 기능/다인 E2E/실기기/외부 접속은 아직 미구성이다.

정확한 실행별 최종 개수·명령·환경·소스 상태·원격 CI 여부는 작업 이슈/PR과 ignored artifacts/harness 보고서에 기록한다. 문서는 고정된 예전 시험 수를 최신 성공처럼 재사용하지 않는다. 원격 CI는 로컬 결과로 추정하지 않는다.

## #49: 별도 프로세스 그룹의 브라우저 시험 서버 정리

#15 전체 시험이 기존 90초 예산을 초과했을 때 Playwright는 종료됐지만 별도 프로세스 그룹의 합성 시험 서버가 4179에 남았다. 기존 회귀는 같은 그룹의 손자만 검사해 이 경계를 놓쳤다. 해당 실행의 명령과 PID를 확인한 뒤 그 시험 서버만 종료했다.

Playwright 실행마다 임시 lease를 발급하고 하네스 종료 시 제거한다. 시험 서버는 lease 소멸 또는 소유 하네스 PID 소멸을 감지하면 자기 listener와 임시 DB fixture만 닫는다. 다른 서비스의 프로세스를 찾아 종료하지 않는다. 강제 종료에서는 하네스가 lease 디렉터리를 지울 기회를 얻지 못할 수 있지만 서버 자체는 종료된다. lease 파일은 비밀/사용자 데이터가 없는 임시 표식이다.

`tests/harness/browser-lease.test.mjs`는 별도 그룹 child가 timeout 뒤 더 이상 쓰지 않는지와 lease가 남아도 소유 프로세스 강제 종료를 감지하는지 실제 프로세스로 검사한다. 초기 helper 부재 RED를 확인하고 두 회귀 GREEN을 확인했다. 기존 동일 그룹 정리 시험도 유지한다.

같은 최종 소스를 list reporter로 실행한 38개 browser 시험은 모두 통과했으며 합계 1.8분이었다. 실제 15초 연결 감지와 복귀 대기를 여러 회귀가 포함한다. 전체 suite 예산만 90초에서 150초로 늘렸고, 개별 시험 15초 및 assertion timeout은 그대로다. 이를 개별 실패를 숨기는 완화로 사용하지 않는다.
