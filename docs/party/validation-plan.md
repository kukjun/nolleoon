# 확장 검증과 릴리스 경계

## 현재 검증 층
- 단위/HTTP/SQLite: 팀 균형·정확한 N·자기 제비만 공개·영속 재시도·rollback·현재/이력 참여 권한·닫힌 방 아바타 차단.
- 합성 이전 리허설: schema9의 17개 테이블 61행을 온라인 백업/새 경로 복원/새 스키마 이전/재백업으로 비교한다. 실제 운영 데이터나 SQLite 파일 전체 바이트 동일성의 증거는 아니다.
- 사진 방어: 서명/MIME·픽셀·바이트·EXIF 제거, 스트리밍 초과·Origin·권한, 실제 Sharp 동시 처리 한도와 slot 회복. quota/CAS 일부는 application 대역 시험이고 다중 프로세스 부하 성능 증거가 아니다.
- 의존성: 2026-11-17 `npm audit --omit=dev --json`에서 알려진 production 취약점 0건을 확인했다. 감사 데이터 시점과 의존 범위에 한정되며 취약점 부재 보장은 아니다.
- 실제 UI: 독립 브라우저 컨텍스트의 방/팀/제비/재판/결과, 별도 아바타 실제 API 통합. mock 기반 선택 UI 검사는 실제 업로드 검증과 구분한다.
- 기존 재판 회귀: 탐색 흐름 변화에 맞춘 명시적 단계 이동만 보강하며 원래 보안·판정·레이스 assertion을 삭제하거나 느슨하게 만들지 않는다.

## RC 완료 조건
1. 정확한 commit SHA와 깨끗한 checkout에서 전체 하네스, 별도 신규 파티 기능/E2E gate 실행.
2. 이전 단계 검사 후 변경된 파일이 있으면 영향 검사 및 최종 전체 검사를 다시 실행한다.
3. 독립 리뷰에서 결함을 재현 시험으로 고친 뒤 재리뷰한다. 빈 원격 체크는 CI 성공이 아니다.
4. 실기기 미확보는 #28/#63 차단으로 표기한다. 모바일 에뮬레이션을 물리 기기 테스트로 바꾸어 쓰지 않는다.
5. #101 미공개자 최종 이탈 정책은 자동 공개/재배정 없이 보수적으로 미완료를 유지한다. 해당 정책의 제품 인수는 별도 차단이다.
6. 운영은 직전 상태를 읽고 진행 게임을 보호한다. 별도 검증된 백업, 새 경로 복원 시험, 기존 세션/기록 보존, 원본과 정적 파일의 분리, 안전한 전환 시점과 복구 조건을 확인한다.
7. 배포 후 실제 외부 HTTPS·쿠키·초대·참가·게임 흐름을 관찰한다. 로컬 검사만으로 외부 다인 인수를 주장하지 않는다.

## 운영 변경 제한
이 문서와 로컬 테스트는 운영 DB migration·서비스 재시작·DNS/보안 변경을 수행했다는 뜻이 아니다. 새 네트워크/권한 변경은 해당 승인 경계를 따른다. 기존 데이터와 원본 미완성 작업은 그대로 보존한다. 마지막 합격/실패/미실행 기록은 PR/이슈와 정확한 RC report로 남긴다.
