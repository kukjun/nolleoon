# 모바일 접근성 인수: 자동화와 실제 기기 구분

## 현재 상태: 실제 기기 인수 blocked

MVP-28은 물리 iPhone Safari·Android Chrome을 요구한다. 실기기 접근 차단은 GitHub #63에서 추적한다. 아래 자동화가 통과해도 이 이슈 전체를 완료하거나 `mobile-device`를 PASS로 바꾸지 않는다.

읽기 전용 장치 목록 확인 결과 현재 연결 가능한 물리 기기는 없었다. Xcode의 등록 기기는 offline/unavailable이었다. 이번 실행 중 실제 기기 OS·브라우저 버전을 확인하지 못했으며 등록된 과거 정보는 현재 검증값으로 사용하지 않는다. `devicectl`은 Xcode 라이선스 미동의 오류도 보고했다. 라이선스 동의, 페어링, 프로파일 설치, 권한 승인, OS 설정 변경은 하지 않았다. Android `adb`는 사용 가능한 PATH에 없고 실제 Android 기기 접근도 확보되지 않았다. 개인 기기 이름·UDID·serial은 문서와 공개 로그에 기록하지 않는다.

Playwright WebKit 실행 파일도 설치되어 있지 않았다. 이번 범위에서는 Chromium만 실행한다. WebKit 엔진이나 iOS simulator를 추후 사용하더라도 물리 iPhone Safari 인증으로 바꾸어 부르지 않는다.

## 재현 가능한 자동화 환경

- 호스트: macOS 27.2.1 / arm64
- 실제 실행 브라우저: Playwright Chromium 159.0.8154.6
- 시험: `tests/browser/mobile-acceptance.spec.mjs`, `@mobile` 태그
- 명령: `npm run build && npm run test:mobile`
- 별도 `mobile-emulation` gate이며 기존 기능·gameplay E2E와 중복 집계하지 않는다.
- viewport/touch/rotation/축소 높이 등은 에뮬레이션이다. 실제 소프트 키보드, 브라우저 주소창, safe area, OS 잠금, Wi-Fi↔셀룰러 전환을 실행한 것이 아니다.

실제 앱의 저장/접근/오류 상태와 디자인 시스템 gallery의 컴포넌트 시험을 구분한다. gallery는 실제 한 판이 아니며 UI 시연의 성공을 다인 동기화 증거로 사용하지 않는다. 기존 실제 다인 경로는 [종합 E2E](e2e-acceptance.md)에서 별도로 검증한다.

## 물리 기기 인수 체크리스트

아래 항목은 모두 **미실행/기기 확보 대기**다. 각 플랫폼에서 실행 날짜·기기 모델·실제 OS/브라우저 버전·결과·화면/영상 근거를 채우기 전 승인하지 않는다. 현재 빈칸을 에뮬레이션 결과로 채우지 않는다.

| 항목 | iPhone Safari | Android Chrome | 필요한 실제 근거 |
|---|---|---|---|
| 방 생성/초대 참여/역할/수락/한 판 | blocked | blocked | 독립 신원, 실제 화면과 결과 |
| 한글/영문 소프트 키보드·입력/오류·제출 | blocked | blocked | 키보드가 켜진 상태로 입력과 제출 접근 |
| 세로↔가로 회전/주소창/스크롤/safe area | blocked | blocked | 회전 전후 잘림과 스크롤 위치 |
| 확대·색 대비·포커스·스크린리더 | blocked | blocked | 실제 시스템/브라우저 설정과 접근성 읽기 |

| 모달 중복 탭·취소/닫기 | blocked | blocked | 실기기 터치와 포커스 복원 |

## 증거·한계

실패 trace/screenshot은 합성 데이터만 사용하고 ignored 산출물에 둔다. 기존 사용자 기기나 브라우저 설정을 자동 변경하지 않는다. 체크리스트 완료를 위해 새 기기 연결·권한·라이선스가 필요하면 별도 허용 절차를 따른다. 자동화에서 발견한 실제 결함은 RED→수정→동일 회귀 GREEN으로 기록하고, fixture 오류는 제품 결함과 구분한다. 최종 실행 개수와 파일 상태는 clean source 보고서를 따른다.

## 발견·수정한 실제 결함

중복 닉네임의 서버 오류가 전역 안내로만 표시되어 닉네임 입력의 `aria-invalid`가 false이고 `aria-describedby`는 힌트만 가리키는 RED를 실제 참여 UI에서 확인했다. 닉네임 오류를 해당 Input의 error에 연결하고 그 입력으로 포커스를 옮기며, 사용자가 이름을 수정하면 오류를 지운다. 네트워크·방 종료 등 입력과 무관한 오류는 기존 전역 경로에 남긴다. 게임 규칙이나 서버 권한은 변경하지 않는다.

모바일 overflow 측정은 `innerWidth` 대신 명시적으로 설정한 viewport 폭과 document.scrollWidth를 비교한다. 모바일 layout viewport의 자동 확장 때문에 잘못 통과하지 않게 하기 위함이다. 실제 허용 최대 2,000자 무공백 영문 사건과 500자 벌칙을 저장한 뒤 320px 중단/개인 기록을 검사했다. 공통 텍스트 줄바꿈 규칙이 이미 적용되어 이 부분의 CSS 결함은 재현되지 않았으며 임의 CSS 수정을 하지 않았다.

320px 실제 대기실·장문 기록, 390px gallery 확대 근사 캡처를 직접 확인했다. 텍스트와 주요 버튼이 폭 안에 유지되고 입력 오류 색뿐 아니라 문구도 나타난다. 장문 기록은 가로 잘림 없이 길게 스크롤된다. gallery 대비 계산은 특정 기본 버튼과 오류 문구의 계산된 색에 대한 4.5:1 이상 검사이며 모든 상태/브라우저의 WCAG 인증이 아니다. gallery 버튼의 44px 검사도 앱 전체 모든 터치 대상을 감사한 것과 구분한다.

확대 시험의 첫 구현은 root font-size만 200%로 바꿨지만 px 지정 본문이 14px 그대로여서 실제 확대 근거가 되지 않았다. 이를 제품 결함으로 기록하지 않는다. 테스트에서 각 요소의 원래 computed font-size를 먼저 수집한 뒤 2배로 적용하고 대표 본문 14→28px 및 줄바꿈을 확인하는 근사로 수정한다. 이 방식도 브라우저 메뉴 확대나 운영체제 큰 글자 설정을 직접 조작한 것은 아니다.

최종 `@mobile` 3개는 3.6초에 통과했고, 기존 중복 닉네임·동일 프레임 중복 제출 회귀 2개도 통과했다. 새로운 CSS나 서버 변경은 없다. 최종 확대 근사 캡처에서는 장식 `tc` 로고가 고정 상자 밖으로 일부 나오고 타이머 숫자가 두 줄로 감기는 경미한 시각적 한계를 관찰했다. 본문·버튼을 가리지는 않지만 확대의 모든 시각 품질을 통과했다고 주장하지 않으며 실제 확대/기기 인수에서 다시 확인할 항목으로 남긴다. 기기 차단과 함께 #28은 OPEN 상태로 유지한다.

## PARTY-23 (#98) · 세 게임 모바일 확장 인수

기준 소스 `e7086d2`에서 독립 브랜치를 만들어 실제 Nest/SQLite/Sharp와 Chromium의 320/360/390×844 viewport를 사용했다. 신규 `party-mobile-accessibility.spec.mjs` 3개는 `party-features` 자동 발견 대상이다. 기존 mobile 3개와 구분해 집계하며 전체 하네스 실행은 통합 담당자가 다시 수행한다.

검사 범위: 실제 프로필 편집·Escape 복원, 아바타 10종 44px 선택 영역, 로비와 게임 선택, 팀 설정/결과, 장문 벌칙의 제비 설정/본인 제비/접수 상태. 각 화면의 문서 폭과 노출 버튼 44px, reduced-motion의 실제 계산 animation/transition, 로비 버튼 키보드 포커스 및 polling 후 유지, 가로 viewport 변경 전후 CTA 접근, 제비 화면 reload, 200% computed font-size 근사 결과의 줄바꿈을 검사한다. 로비 주요 버튼의 계산된 전경/배경 대비를 4.5:1 이상으로 검사하며 모든 텍스트·상태의 대비 인증은 아니다.

실제 픽셀에서 확대 시 미공개 참가자명이 상태 문구에 밀려 한 글자씩 세로로 길어지는 결함을 발견했다. 320px에서 이름 폭 22.5px < 네 글자 폭104px RED를 재현했고, 결과 명단을 아바타/이름과 다음 줄 상태로 분리했다. 이름/결과 내용이나 공개 권한은 변경하지 않는다. 장식 로고의 큰 글자 근사 잘림은 이전에 알려진 경미한 시각 한계로 남으며 전체 확대 품질 합격을 주장하지 않는다.

추가 물리 기기 항목은 **모두 미실행**이다. #28/#63의 기기 확보 대기를 해소한 것으로 처리하지 않는다.

| 추가 항목 | iPhone Safari | Android Chrome | 실제 확인할 근거 |
|---|---|---|---|
| 캐릭터 10종·사진 crop/upload·동료 표시 | blocked | blocked | 사진 권한/파일 선택, 확대와 동일 아바타 |
| 팀 설정·균형 결과·같은 방 다음 게임 | blocked | blocked | 실제 터치/회전/화면 전환 |
| 본인 제비·장문 벌칙·접수·다른 사람 대기 | blocked | blocked | 중복 탭, 복귀 후 자신의 접수 상태 |
| 세 게임 연속 전환·기록 | blocked | blocked | 동일 방/신원 유지 |
| 큰 글자·VoiceOver/TalkBack·화면 잠금 복귀 | blocked | blocked | OS 설정·읽기 순서·실제 잠금 |

safe-area는 CSS env 패딩이 존재함을 확인했을 뿐 Chromium viewport에서 실제 iPhone notch/주소창/safe-area 동작을 입증하지 않는다. 가로 viewport 변경도 물리 회전과 같지 않다. 소프트 키보드, OS 잠금, 실제 기기 및 네트워크 전환은 실행하지 않았다. 모든 데이터는 합성, 운영 변경은 없다.
