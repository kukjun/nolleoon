# GitHub 실행 이슈 32개 본문 초안

상태: **승인 / GitHub #1–32 생성 완료**. 아래 완료 기준은 미래 구현의 합격 조건이지 현재 통과 증거가 아니다.

공통 범위·순서·TDD 루프는 [README](README.md), 전체 인수는 [scope-and-done](scope-and-done.md) 참조. `REQ`는 기존 [요구사항](../design/04-requirements.md), `T`는 [시험 계획](../design/09-verification.md)의 ID. 과거 문구가 충돌하면 [최신 규칙](../design/00-current-rules.md)과 MVP-01 기준선 정리를 우선한다.

모든 기능 이슈는 필요한 domain/usecase→repository/API→BFF→React를 수직으로 연결한다. 테스트만 마지막 이슈로 넘기지 않는다. 공통 DoD: RED 실행→최소 구현→리팩터링→관련/기존 회귀·lint/type/build→diff 리뷰→증거/한계 기록. 새 라이브러리 설치·외부 변경은 승인·공식 출처 규칙을 따르며, 현재 초안은 실행 권한을 추가하지 않는다.

## MVP-01 · 최신 명세·기술 ADR와 MVP 기준선 정리

- **단계 / 선행:** M1 / 없음
- **추적:** 전체 활성 요구사항 (REQ-032 제외, REQ-054는 복구 부분만)
- **범위:** 최신 정책과 React/TS·Nest 내부 BFF·SQLite·Mac mini/Tunnel 합의를 하나의 활성 명세로 정리. 과거 FastAPI/PG/이양 없음/이유 숨김/중국 게이트 제거·이력 보존. 드라이버·마이그레이션·상태 동기화·세션 및 관측 기준을 최소 ADR로 결정.
- **먼저 실패시킬 시험(RED):** 폐기 REQ-032/T-22·이유 비공개·방장 피고 금지 등 잔존 활성 규칙을 검출하는 검사부터 실패시킨다.
- **완료 기준:** 요구/시험 매핑의 충돌이 제거되고 최신 정책 링크가 단일 기준. 피고 퇴장 중단 공개는 보수적 제안/확인으로 명시. 선정 버전·세부값·미검증 사항을 기록; 구현 완료 주장 없음.
- **검증 방법:** 문서 계약 검사. 실행 명령·환경·소스 상태·실패/미실행을 이슈 증거란에 기록.
