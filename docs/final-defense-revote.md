# 최후 변론과 한 번의 재투표 (#17)

## 흐름

1차 유죄·무죄가 같은 양수이면 완료된 1차 집계와 익명 이유를 공개하고 최후 변론 단계로 전환한다. 유효표가 모두 0이면 무판결이며 재투표로 보내지 않는다. 피고는 새 최후 변론을 제출하거나 건너뛸 수 있고, 방장은 피고가 응답하지 않아도 2차 투표를 개시한다. 두 번째 실질 동률은 무죄, 두 번째 유효표 0은 무판결이다. 3차는 없다.

## 라운드와 명령 식별

`defense`와 `open-vote` 본문은 이제 `roundNumber: 1 | 2`를 필수로 받는다. 게임 ID, 현재 actor, 게임 version, 요청 라운드에 맞는 단계, 해당 라운드 미개시를 같은 트랜잭션에서 검사한다. 첫 라운드 개시는 defense 단계, 2차는 1차 tie가 기록된 final-defense 단계에서만 가능하다. 개시 receipt는 저장된 actor·intent version·roundNumber 모두 일치해야 멱등 재확인이 된다. 옛 1차 명령은 2차를 변경하지 않는다.

`game.defense.roundNumber`는 현재 변론 대상이다. final-defense에서는 이미 닫힌 `game.round.number=1`과 달리 2다. 화면 key에 변론 대상과 phase를 포함해 첫 변론 입력/skip/개시 intent를 최후 변론 폼에 재사용하지 않는다. 2차 개시 뒤 `ownVote`는 2차의 본인 접수만 조회한다. 1차 receipt가 2차 성공 표시로 넘어가지 않는다.

2차도 시작 때 동결한 명단과 최초 투표 시작 전 확정한 기간을 사용한다. 후발 관전자에게 투표 자격을 추가하지 않는다. 새 서버 startedAt/deadline과 새 vote 레코드를 쓰며 첫 표를 합산하지 않는다. duration 명령은 첫 투표 전만 허용한다. 기존 rounds/defenses/open receipts/settlements 스키마가 두 라운드를 지원하므로 새 migration은 없다.

## 익명 공개 경계

`publishedRounds`에는 settlement가 있는 라운드만 넣는다. 집계와 같은 acceptedVotes helper의 동결 자격·deadline 이전 접수 검사를 적용한다. counts와 비어 있지 않은 실제 이유만 `choice`, `reason` 두 필드로 제공한다. member/session/request ID, 접수 시각, 명단 순번, 제출 순번은 반환하지 않는다. 이유 표시 순서는 공개된 choice+reason 문자열의 UTF-16 코드 단위 순서로 정해 원본 조회 순서를 노출하지 않는다. 같은 이유 문자열은 그대로 별도 항목이며 빈 기권 이유나 미제출 이유를 만들어내지 않는다.

1차 공개 내용은 2차 투표 중에도 유지한다. 미완료 2차 이유·표수는 공개하지 않는다. 완료 뒤에는 두 라운드를 별도로 공개한다. 이유 문체나 소수 인원 자체로 작성자를 추론할 수 있어 추론 불가능한 익명성을 보장하지 않는다. 미정 중단 이력 #33의 기존 기본 비공개는 유지한다.

## 검증과 범위

처음 명시적 roundNumber가 포함된 실제 API 요청은 기존 계약의 400으로 RED를 확인했다. API 회귀는 최후 변론/개시 경합, skip·무응답, 2차 동률/전원 기권, 늦은 1차 명령, 3차 차단, 1차 공개 유지·2차 비공개를 검사한다. 임시 DB에서는 2차 개시 중 실패 rollback, DB 재개방 후 같은 deadline, 후발 관전자 거부, G1/N0/A3의 독립 집계를 확인한다. 공개 helper 시험은 원본 레코드 순서를 뒤집어도 같은 공개 문자열 순서·allowlist가 유지되는지 확인한다.

브라우저 검증 결과와 실제 캡처는 작업 기록에 남긴다. 최종 결과 표현/유죄 벌칙 강조와 내부 알파 게이트는 #18에서 마무리하며 운영 배포 완료를 뜻하지 않는다.

공개 필터 리뷰에서 저장소에 비대상/기한 후 표가 있으면 집계에서 제외돼도 이유가 노출될 수 있는 RED를 재현했다. acceptedVotes를 집계/공개에 공유하고 해당 합성 행의 이유 미공개 회귀를 추가했다.
