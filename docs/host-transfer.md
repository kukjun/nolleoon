# 무작위 방장 승계 (#21)

## 언제 바뀌나

현재 방장이 명시적으로 나가거나 단절 감지 후 10분 유예가 끝나면 방장 자리를 비운다. 단순 단절 유예 중에는 방장을 바꾸지 않는다. 실제 퇴장 뒤에는 현재 연결된 active 멤버 중 한 명을 균등 난수 인덱스로 지정한다. 피고와 관전자도 후보지만 방장 지위가 역할이나 투표 자격을 바꾸지 않는다.

후보가 없으면 공석이다. 유예 참가자의 heartbeat 복귀 또는 새 참여 뒤 연결 후보가 생기면 지정한다. 이전 방장이 돌아와도 이미 지정된 새 방장을 밀어내지 않는다. 전원 퇴장한 방의 자동 폐쇄는 다음 #22 범위다.

## 서버 경계

`RandomSource.nextInt(upperExclusive)`는 application 포트이며 production adapter는 `node:crypto.randomInt`다. composition root가 하나의 provider를 명시적으로 주입한다. 테스트에는 고정 후보 대역 또는 호출 횟수를 기록하는 대역을 주입하며 제품 코드에 테스트 fallback을 두지 않는다.

승계는 SQLite 쓰기 transaction에서 최신 host=null을 다시 확인하고 fresh 연결 후보를 구한 뒤 한 번 선택한다. 여러 만료가 밀렸다면 모두 처리한 다음 선정하여 곧 만료되는 멤버를 중간 방장으로 뽑지 않는다. disconnectedAt=null이어도 lastSeen이 15초 이상 오래되면 후보에서 제외한다. 같은 captured server now를 사용한다. 후보가 없거나 이미 방장이 있으면 난수 provider를 부르지 않는다.

선택과 버전 변경은 같은 transaction이며 실패하면 퇴장과 승계 모두 rollback한다. 저장소 재개방이나 반복 monitor는 기존 방장을 재추첨하지 않는다. 저장 초안·벌칙 동의·게임 역할·동결 명단·표는 변경하지 않는다. 이후 설정 저장/투표 개시 명령은 현재 방장인지 서버에서 다시 확인한다. 오래된 방장의 요청은 승인하지 않으며 새 방장도 초안 CAS를 지켜야 한다.

## 검증 근거

실제 RED는 방장 퇴장 후 host가 null인 상태(선택된 피고 기대)였다. 후보 수·선택 인덱스·호출 횟수, 피고/관전자 후보, 단절 유예, 후보0 뒤 동시복귀, 만료와 개시 경합, stale 후보 제외, 저장 실패 rollback/재개방, 옛 방장 저장 거부와 새 방장 CAS를 검사한다. 기존 테스트의 constructor 변경은 새 필수 RandomSource를 명시적으로 제공하기 위한 것이다.

브라우저는 독립 3개 context에서 실제 무작위 결과를 snapshot으로 읽어 새 방장을 찾고, 단일 방장·공유 초안 보존/수정·피고 역할 유지·옛 방장 재참여 시 권한 미복구를 검증한다. 어떤 후보가 뽑힐지 미리 가정하지 않는다. 390px 캡처는 화면 검증이며 실제 모바일 기기 실행이나 외부 배포를 뜻하지 않는다.

리뷰에서 유예 중 단절 방장이 다른 연결자 3명만으로 자신을 뺀 재판을 시작할 수 있는 실제 HTTP 결함(201, 기대409)을 재현했다. 시작 조건에 현재 방장의 fresh 연결 포함을 추가했다. heartbeat 복귀 후에는 방장을 포함한 4명으로 시작하며, 이미 성공한 시작 receipt 재확인은 새로운 시작이 아니므로 원래 게임을 유지한다. 범위 밖 난수(-1/후보수/NaN)도 퇴장·방장 포인터·버전 전체 rollback 회귀로 확인한다.
