# 현재 벌칙 수락·거절 (#12)

현재 피고가 서버에 저장된 벌칙을 읽고 명시적으로 수락하거나 거절한다. 방장도 피고라면 결정할 수 있지만, 방장이라는 이유로 다른 피고를 대신할 수는 없다. 비어 있거나 아직 저장하지 않은 벌칙은 수락 대상이 아니다. 실제 게임 시작은 #13 전에는 제공하지 않는다.

## 세 가지 버전

1. `penaltyRevision`: 저장된 벌칙 문자열이 달라질 때 증가한다. A→B→A도 증가하므로 옛 수락이 살아나지 않는다. 바깥 공백 정리 후 같은 벌칙을 다시 저장하거나 사건/시간만 바꾸면 증가하지 않는다.
2. `roleRevision`: 피고 변경을 추적하는 #11의 버전이다. A→참가자→A 왕복도 이전 수락을 무효화한다.
3. `decisionVersion`: 수락/거절 저장마다 증가하는 CAS 버전이다. 먼저 거절한 후 다른 탭에서 늦게 도착한 옛 수락이 덮어쓰지 못한다. 벌칙이나 피고 변경으로도 이 버전을 0으로 되돌리지 않는다.

`POST /api/rooms/:code/consent`는 `{penaltyRevision, roleRevision, expectedDecisionVersion, decision}`만 받는다. decision은 accepted/rejected다. 쿠키 신원, 동일 origin/CSRF를 확인한 뒤 트랜잭션에서 열린 방·활성 현재 피고·저장된 비어 있지 않은 벌칙·진행 게임 부재·세 버전을 검사한다. 숨겨진 버튼이나 canDecide 표시는 권한 근거가 아니다.

## 상태와 저장

snapshot은 pending/accepted/rejected, 현재 버전, 현재 피고 멤버 ID와 canDecide를 명시한다. 저장된 결정의 피고/역할/벌칙 버전이 현재와 다르면 pending이다. 수락을 해시나 텍스트 일치만으로 복구하지 않는다. 이미 공개된 방 명단의 멤버 ID만 사용하며 세션 ID·토큰은 반환하지 않는다.

append-only migration 4가 penalty_revision과 penalty_consents를 추가한다. 한 방의 최신 결정 한 행과 단조 증가 결정 버전을 유지한다. 결정+방 snapshot 버전 저장은 원자적이고 실패하면 둘 다 롤백한다. 현재 벌칙 수락 여부를 판정하는 `hasCurrentAcceptance`는 #13 시작 유스케이스에서 동일 트랜잭션으로 읽은 현재 피고/벌칙/버전과 함께 사용해야 한다. helper 자체가 모든 게임 시작 조건을 검사하지는 않는다.

## UI와 검증

저장된 벌칙 확인 영역은 방장의 미저장 편집 내용과 구분한다. 서버 성공 응답을 받기 전에 수락/거절 완료로 표시하지 않는다. 거절 후 방장이 벌칙을 바꿔 저장하면 pending으로 돌아가며 현재 피고가 다시 결정한다. 충돌/통신 실패는 성공으로 표시하지 않고 최신 상태 확인을 안내한다.

실제 API로 피고/방장 권한, 빈 벌칙 거부, 벌칙/역할 왕복 무효화, 동일 벌칙 유지, 두 결정 경합, 늦은 수락 거부, 추가 키 거부와 진행 게임 잠금을 검사한다. 임시 DB 시험은 방장=피고 결정과 저장 실패 rollback 및 재개방 후 보존을 확인한다. 브라우저 시험은 명시적 버튼·미저장 값 구분·다른 탭 늦은 결정 충돌을 다룬다. 실제 시작·실기기·외부 배포 완료를 뜻하지 않는다.
