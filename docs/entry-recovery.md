# 방 진입 요청의 지연 복구 (#67)

초대 링크의 최초 조회와 방 생성·참여 요청은 각각 6초 동안만 기다린다. 응답이 없으면 요청을 취소하고 로딩을 해제한다. 닉네임은 지우지 않는다.

- 조회 실패: `방 연결 다시 확인`을 누를 때만 다시 조회한다. 확인되지 않은 상태에서 참여 POST를 자동 실행하지 않는다.
- 생성·참여 지연 또는 연결 오류: 서버가 이미 처리했을 가능성을 안내한다. 자동 POST 재전송은 없다. 참여는 같은 브라우저/링크로 명시적으로 다시 시도하면 기존 멤버십을 반환한다. 생성 재시도는 새 방을 만들 수 있다고 안내한다.
- 취소는 서버 작업의 롤백을 의미하지 않는다. 생성된 방의 응답을 잃으면 해당 초대 링크를 이 화면에서 알아낼 수 없으며, 생성 요청의 영속 멱등성은 이 수정 범위가 아니다.
- 화면 이동·신원 소실 시 기존 요청을 abort하고 generation을 무효화한다. timeout 이후 늦게 도착한 응답은 현재 화면을 바꾸지 않는다. 기존 transport의 abort 후 신원 소실 알림 차단도 유지한다.

## 검증

실제 브라우저에서 응답을 보류한 최초 조회와 생성 요청이 무한 로딩을 만드는 RED 2건을 먼저 확인했다. 생성/참여의 응답 보류는 실제 서버 처리를 완료한 뒤 응답만 지연해 불확실성을 재현한다. 조회 명시적 재확인, 닉네임 유지, 자동 재전송 없음, 늦은 생성 응답 무시, 참여 재시도 후 멤버 중복 없음과 reload 복구를 확인한다. 이 시험은 localhost 합성 데이터만 사용하며 외부 운영 배포나 실제 단말 검증이 아니다.

추가 회귀: 실제 서버 생성 완료 뒤 네트워크 오류에도 불확실 안내를 표시한다. 보류된 생성 성공 응답이 미리보기 화면 이동, 쿠키 삭제, 새 신원 명시적 생성 뒤 도착해도 URL/방을 되돌리지 않으며 새 신원은 옛 방에 접근할 수 없다.
