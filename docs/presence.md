# 방 snapshot·접속 감지 (#9)

## 시간과 경계

- 보이는 화면은 이전 응답 뒤 3초 후 동일 origin POST heartbeat로 최신 snapshot을 받는다. 응답 대기는 6초로 제한하고 실패 시 마지막 화면을 유지한 채 재시도한다.
- 마지막 유효 heartbeat(생성/참가 때는 가입시각) 이후 15초 이상 무응답이면 서버가 단절 후보로 본다.
- 독립 서버 작업이 1초마다 검사한다. 아무도 폴링하지 않는 방도 검사하며 서버 시작 때 즉시 한 번 검사한다. 종료하면 timer를 해제한다.
- `disconnectedAt`은 lastSeen+15초를 역산하지 않고 **실제 서버 검사 시각**이다. 이벤트 루프·DB 지연 때문에 검사는 늦어질 수 있다.
- 10분 유예와 퇴장 실행은 #20이다. 이 단계는 오래 끊겨도 퇴장시키거나 방장을 바꾸지 않는다. 이후 경계는 `now >= disconnectedAt + 600000`이다.

클라이언트가 보내는 시각은 받지 않는다. GET은 읽기 전용이므로 참가자 상태를 살려내지 않는다. heartbeat는 기존 활성 참가자만 갱신하고, 이미 left_at이 있는 참가자는 FORBIDDEN이다. 링크·닉네임만으로 과거 멤버십을 복원하지 않는다.

## 버전과 오류

방 생성은 version 0이다. 새 참가, 서버 단절 감지, heartbeat에 의한 복귀처럼 공개 snapshot이 바뀔 때만 증가한다. 하나의 sweep에서 여러 명이 끊기면 해당 방 버전은 한 번 증가한다. 정상 heartbeat와 GET은 버전을 올리지 않는다. 모든 저장 변경은 SQLite immediate transaction 안에서 이뤄진다.

클라이언트는 요청 세대와 서버 version을 함께 확인한다. 이미 새로운 요청을 시작했거나 받은 버전보다 낮은 응답은 반영하지 않는다. 이동/언마운트 때 이전 요청을 취소한다. 네트워크 실패는 마지막 방 명단을 삭제하거나 변경 명령 성공으로 바꾸지 않고 재연결 상태를 표시한다. 본인 통신 오류와 다른 참가자의 서버 판정 단절은 별개다.

숨겨진 탭에서는 주기 폴링을 멈추고 visible/focus/online 이벤트 때 즉시 확인한다. 실제 모바일 브라우저는 백그라운드 타이머·네트워크를 중단할 수 있어, 단절 표시는 사람이 실제 나갔다는 뜻이 아니다. 즉시 감지·배터리 최적화 실측·실기기 지원을 보장하지 않는다.

## 저장소와 검증

append-only migration 2가 last_seen_at을 추가하고 기존 가입시각으로 backfill한다. 기존 migration 1은 변경하지 않는다. 서버가 재시작하면 이미 오래된 lastSeen을 즉시 검사하지만 disconnectedAt을 시작 시각으로 기록한다. 저장된 단절을 재검사해 시각/버전을 계속 덮어쓰지 않는다.

임시 DB+가짜 서버 시계로 임계값 직전/이후, 실제 감지시각, 반복 sweep, 복귀, left 상태 보호를 검사한다. 실제 Nest lifecycle 시험은 클라이언트 요청 없이 timer가 단절을 기록하는지와 app.close 이후 timer 정지를 확인한다. 스키마 v1→v2 업그레이드에서 기존 참가자 보존을 별도로 검사한다. 전체 한 판, 10분 퇴장, 외부 배포는 아직 검증 범위가 아니다. 실제 15초 단절·6초 응답 제한을 기다리는 브라우저 회귀 시험 추가로 하네스의 전체 브라우저 실행 예산은 60초에서 90초로 늘렸다. 개별 검사·실패 판정은 완화하지 않는다.

## 화면 확인

390px Chromium 캡처 `artifacts/presence/reconnecting-mobile.png`를 직접 확인했다. 마지막 참가자 명단을 유지하면서 자기 행의 ‘연결 확인 중’과 아래 재연결 설명이 함께 표시된다. 긴 안내문은 줄바꿈되며 가로 잘림은 없었다. 실기기 백그라운드 동작·키보드·배터리 측정은 수행하지 않았다.

현재 #20 전에는 10분을 넘긴 부재도 활성 멤버십이 남아 있어 heartbeat로 복귀할 수 있다. 이를 최종 퇴장 정책 완료로 간주하지 않는다. 정상 무부하 서버의 감지 예정은 무응답 15초 이후 다음 1초 sweep이고, 다른 화면 표시는 추가 폴링/응답 지연이 든다. 감지 실패 로그는 `presence_sweep_failed` 고정 사건명만 남기며 원본 오류·닉네임·토큰을 기록하지 않는다.

### 로컬 브라우저 측정

독립 Chromium 컨텍스트 2개로 실제 서버를 사용한 한 회차에서 참가 요청부터 다른 화면 명단 반영까지 2,837ms, 네트워크 오프라인 설정부터 다른 화면의 단절 표시까지 15,446ms였다. 로컬 단일 표본이며 평균·백분위·외부 네트워크 SLA가 아니다. 별도 시험은 응답을 멈춰 6초 취소 후 재시도 복구와 클라이언트 Date.now=0 변경에도 빈 heartbeat 요청 `{}`만 전송됨을 확인했다. visibility 이벤트 시험은 합성 이벤트이며 실제 OS 백그라운드 검증이 아니다.
